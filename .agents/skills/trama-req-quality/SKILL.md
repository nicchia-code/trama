# Requirements: Qualità

Generated by Trama from `.trama/requirements/quality/`. Do not edit these files: change the Requirements through a Trama Proposal (or ask the developer).

These are the developer's Requirements for how the System is built. Follow them when you write code. The Model (`.trama/model/`) says what the System does; when a Requirement and the Model disagree, stop and tell the developer.
A section titled with a Model reference (such as `order/Paid`) applies to that element and to everything inside it.
This is the index of the Area's Requirements. The General Requirements are below in full; every other section is in the file of its fragment, next to this one: read the fragments whose sections name the elements you work on.

## General

- Reliability: the test suite does not depend on the environment variables of the shell that runs it: it passes the same with or without Trama's variables (`TRAMA_*`, which every agent launched by Trama inherits) and `BUN_INSTALL` set. The suite's `bun test` preload (`bunfig.toml`) removes them at start; a test that needs one of them sets it itself and restores the previous value when it ends.
- Performance: the editor host never blocks its thread waiting for something outside it. Every process it starts (git, omp, gh, ps, PowerShell, the system's certificate tools) runs asynchronously, and a retried write (`src/core/atomic-write.ts`) or a wait for a lock (`src/core/file-lock.ts`) yields between attempts instead of waiting actively. The same core code may stay synchronous in the command line, a short process that serves no editor.
- Performance: what the window learns from git and rarely changes (the `origin` remote, hence the GitHub repository and whether Team is available, and the git folders) is read once per window and again only when git's configuration changes; never at each picture, view or save. Typing, saving or switching the editor's tabs starts no process and reads no file of `.trama/`.
- Diagnostics: an Output channel `Trama Performance`, always on, gets one line for each operation of the editor host that takes more than 200 ms: when it ended, what started it (a change of files, an action of the panel or of a view, a launch, a timer, an event of the editor), what it did, how long it took and each process it started with its own duration. Faster operations write nothing. The channel never comes forward by itself and holds no content of files, prompts, answers or settings, only names of operations, paths under `.trama/`, program names and durations. Writing it starts no process and reads no file.
- Acceptance on a machine where antivirus inspects every process start and file access: typing and saving in any file of the project, switching the editor's tabs, switching the panel's views and showing the side menu start no process and leave `Trama Performance` empty; a job's conversation tab shows at once; an action of the Board shows its result with one picture.
