# Requirements: Tecnologia e vincoli, Markdown renderer

Use when building or changing the Markdown renderer of the panel and of omp Chat: parser, tables, mermaid diagrams, GitHub Markdown.

## editor-panel

- Markdown in the panel is rendered by a small renderer of our own in the webview code, with no Markdown library. One renderer serves the Diagram, the Board and the Requirements tabs, e anche l'overlay delle domande e omp Chat, and it is a plain function from text to React elements that can be tested without a browser page. The only library it calls is `mermaid` (`specs#frameworks`), and only to draw a `mermaid` block.
- `mermaid` blocks (`ui#panel`): the block parser keeps the fence language, as today, and a block with language `mermaid` renders as a diagram component instead of `<pre><code>`. `mermaid` is built by `scripts/build-extension.ts` into its own `iife` bundle, `mermaid.js`, next to `webview.js` and `omp-chat.js`, and is never inlined in them; the bundle ships in the `.vsix` and `extension/THIRD-PARTY-NOTICES.md` carries the licence of `mermaid`. The first diagram of a page loads it by adding a `<script>` with the page's nonce and `src` from `cspSource`, once per page; later diagrams wait for the same load. `mermaid` is initialised with `startOnLoad: false`, `securityLevel: "strict"`, the font of the panel and the theme `default` or `dark` from the panel's theme; a change of theme draws the diagrams of the page again. A load that fails, a parse error or a drawing error falls back to the plain code block. The diagram's box is a `div` with `overflow-x: auto` and `max-width: 100%`, like tables, and the SVG keeps its natural width. In the component tests `mermaid` is replaced by a stub: the parser and the fallback are tested without it.
- GitHub Markdown (`ui#panel`): strikethrough, task list items, bare http and https addresses and GitHub references are recognised by the same parser and inline renderer, as new block and inline kinds; they are never inside inline code or code blocks. The host sends the GitHub repository of the project (`owner/repo`, read from the `origin` remote with git when its address is on github.com, otherwise nothing) with the other data of the picture; with it `#123` links to `https://github.com/<owner>/<repo>/issues/123` and `@handle` to `https://github.com/<handle>`, opened by the host like every other link. A user name has 1 to 39 letters, digits or single hyphens, not starting or ending with a hyphen.
- Tables (`ui#panel`): the renderer's block parser recognises a pipe table (header row, separator row matching the existing `TABLE_SEPARATOR`, body rows) as a `table` block with its column alignments, instead of turning it into a plain code block; cells go through the same inline renderer as paragraphs. The block renders as a `div` with `overflow-x: auto` and `max-width: 100%` around a `table` with `border-collapse: collapse` and no fixed width, whose cells have `max-width: 20rem` and `overflow-wrap: break-word` (not `anywhere`, so a column never narrows below its longest word and the box scrolls instead) and whose alignment comes from `text-align`. The `.md` rule `overflow-wrap: anywhere` does not reach table cells. The layout is only CSS (`.md table` rules in `extension/src/webview/styles.css`): no `ResizeObserver`, no width measured or stored in JavaScript, so the table follows every resize of its container, also after it has been rendered.
- The renderer builds React elements and puts text in them as text children; it never uses `dangerouslySetInnerHTML`, `innerHTML` or similar, so no text from a file can inject markup or script. The only markup that enters the page is the SVG that `mermaid` returns with `securityLevel: "strict"`: it is parsed with `DOMParser` as `image/svg+xml`, any `script` element, `foreignObject` element, `on*` attribute and `href` that is not a fragment (`#…`) is removed, and the result is imported into the diagram's box. Links are only given an `href` when they are http or https, and are opened by the editor host in the system browser, not by navigating the webview.
