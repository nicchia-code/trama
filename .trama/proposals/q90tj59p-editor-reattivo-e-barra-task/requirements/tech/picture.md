# Picture of the project

## panel/Open
- One picture per change, shared by the panel and the side menu: a host module, one per window, owns the picture of the project (`buildSnapshot` of `src/core/snapshot.ts`, called with `driftsFinishing`, `proposalsFinishing` and `tasksFinishing` of the project). After the 150 ms pause of the global watcher of `.trama/**`, and at a change of the workspace folders, it builds one picture and gives the same object to the panel (`Controller.refresh`), to the side menu (the numbers and the name of `tech#menu-laterale`), to the ghost item of the status bar (`tech#announcement`), to the execution check (`tech#time`) and to the Run all estimate. A refresh that an action of the panel or a host event asks for (the decisions, Clear, Delete, the question rounds, the Drift resolution, the settings) builds a new picture at once, so it always sees the files the action just wrote, and gives it to all of them; the watcher events that arrive afterwards for files that picture already read with the same `mtimeMs`, `size` and `ino` build no second picture. A failed read gives the error to the panel, which shows it as today and keeps its last picture; the menu keeps its last numbers.
- `Controller.refresh` reads nothing the picture already read: the open Drifts and every other card it needs for `resolve`, `unify`, `refinement` and `runEstimate` come from the picture or from the parsed files of the same build, not from a new `listDrifts`, `listTasks` or `listProposals`.
- A picture reads each file once: `buildSnapshot` lists each folder of `.trama/` once and reads and parses each file at most once per picture. The functions it calls receive the cards already read instead of listing and reading them again: `unifiedInto` and `unifiedDrifts`, `closedUnchanged`, the synchronization of the short numbers (`syncShortNumbers`), the views of Team's handoffs (`teamViews`), and the Tasks of the Proposals. The time of a picture grows linearly with the number of files.
- The parsed-file cache: `src/core` has a cache of parsed documents keyed by absolute path, Model and Requirement files included. Each entry holds what `readDocument` returns (front matter and body) with the `mtimeMs`, `size` and `ino` of the stat made before the read. The picture module collects the paths the watcher reports (created, changed, deleted) between two pictures; a picture stats, reads and parses again only those, drops the entries of the deleted ones and takes every other file from the cache, with the folder listings kept by the module and updated by the same created and deleted events. A full check (listing every folder of `.trama/` and stat of every file, reading again those whose three values changed) runs when the window opens the project and when `window.onDidChangeWindowState` says the window came back to the foreground, asynchronously (`fs.promises`), and its result becomes the next picture only when something changed. Derived values (blocked Tasks, card views, numbers, decisions) are never cached: they are computed again at every picture from the parsed files. What the cache returns is never changed by its callers. The functions that change a card read it without the cache, as the commands do today. The host keeps one cache per window, in the picture module, for the life of the window; the command line builds its pictures without a cache.
- What the picture's message carries from git (the GitHub repository of `tech#editor-panel`, Manager mode's status, Team's target) comes from the values the window keeps (`quality#General`): `Controller.refresh`, `postManager`, `teamRepository` and the Team view start no git process.
- Changing the panel's view (`viewChanged`, `navigate`) builds no picture and reads no file: the webview already holds the picture of every view.
- Tests (`bun:test`): one picture of a project with a few hundred Drifts (some unified), Proposals and History entries reads each file at most once, counted by the cache. A second picture with nothing changed reads, parses and stats no file. A picture after a watcher event for one file stats and reads only that file. A file rewritten with the same size is read again. A deleted card leaves the picture. A file changed without a watcher event shows after the full check of the window's return to the foreground. An action that writes files gives one picture, not two. The panel and the menu receive the same picture for one watcher event. The picture built with the cache equals the one built without it.
