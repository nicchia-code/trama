# Requirements: Tecnologia e vincoli, Handoffs and issues

Use when building handoffs and issues: the core modules, the gh reader, the host messages, the Decisions and Issues tabs, the handoff skill and its launches.

## issue

- Core: `src/core/issues.ts`, with `bun:test` tests, holds the issues of a handoff and the issue cards (`data#issue`): parsing and writing, identities unique with the Tasks, the hand-over checks and warnings of a handoff (`rules#proposal/Draft`) in the same function that `trama proposal show` and the hand-over call, the Manager's changes (`rules#developer.CHANGE_ISSUE_FIELD`), the order of publication, and the composition of the GitHub body (`rules#issue`), a pure function of the issue, the numbers of its dependencies and Solo mode, used by the preview and by `trama issue show`. `ProposalKind` gains `handoff`; `coversScope` stays false for it and the coverage of issues is a separate function that only produces warnings. Approving a handoff writes its issue cards in the same step that applies its files, before any launch.
- Core: `src/core/github.ts` runs `gh` only to read (`rules#github-project`), with `execFile` semantics, fixed arguments, no shell, a 20-second timeout, and maps each failure to a fixed reason: not found, not logged in, cannot read Projects, or `gh exited with code <n>: <first line of stderr>`. The GraphQL queries are constants in the module. It is shared by `trama issue fields` and by the host, which never builds a `gh` command elsewhere.
- The text fingerprint recorded at publication is the one of `tech#scans`, computed by the same function.
- Host: the snapshot of the panel carries, apart from the Board's data, the open handoffs with their issues and warnings and the issue cards; the Board's columns and its number never include `kind: handoff` (`data#task`), and the side menu's `Team` entry gets the number of open handoffs in `menuState`.
- Host: on showing the Team view and on `refreshTeam`, the host reads GitHub through `src/core/github.ts` once at a time (a second request while one runs waits for it), stores the result in `workspaceState` (`data#github-project`) and sends `teamGitHub { state, readAt, project, error }` to the webview.
- Messages, webview → host, validated by `parseToHost`: `writeHandoffRequest`; `setIssueField { handoff, issue, key, value }`, checked again by `src/core/issues.ts`; `splitIssue { handoff, issue }`; `publishAgain { handoff }`; `linkGitHubProject { owner, number }`; `unlinkGitHubProject`; `refreshTeam`; `logInGitHub`. Approving, rejecting and reworking a handoff use the existing decision messages of the Board, which the host accepts for a handoff only from the Team view.
- Launches: the handoff request uses the same `DesignRequests` of `extension/src/host/design-requests.ts`, with a request kind instead of the setup flag and a new `workspaceState` key `trama.handoffDesignRequests`; its instruction (`rules#agent-terminal`) names `trama-handoff` and its terminal `Handoff`. Split and publication are new `ResolvedAction` kinds of `extension/src/host/prompts.ts`, with their terminal names; `roleOf` in `extension/src/host/terminal-agent.ts` gives `Handoff` and `Split <n>` the analysis role and `Publish <n>` the execution role. None of them may file Drifts. Their ghosts have no column.
- Webview: the Decisions and Issues tabs live in `extension/src/webview/team/` next to People, with their pure logic (ordering, grouping by epic, time ago, field editors) in `logic.ts`, tested without DOM; the preview renders the composed body with the shared `Markdown` component of `extension/src/webview/markdown.tsx`.
- Skill: `skills/trama-handoff/SKILL.md`, embedded in the binary in `src/cli/skills.ts` and installed with the other skills, with the `## Language` section of `rules#agent-terminal`, the interview rules of `trama-design` and the publication steps of `rules#issue`.
- `README.md`, `extension/README.md`, `docs/` and `CHANGELOG.md` describe handoffs, the Decisions and Issues tabs and the GitHub command line Team needs; `docs/cli.md` the `trama issue` commands and `kind: handoff`; `docs/uat.md` the manual steps: a handoff with and without Model changes, changing fields and undoing, Split, approving and publishing, a refused issue and Publish again, `gh` missing or logged out, linking a Project without iteration field.
