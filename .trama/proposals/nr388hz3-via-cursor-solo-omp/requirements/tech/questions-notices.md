# Tecnologia dei round di domande

## question-round
- Expose `trama question new`, reading the round as JSON from standard input (`--input -`) and waiting until it can print the result as JSON to standard output. When no editor is connected for the project it prints explicit editor unavailability instead of an answer. Keep diagnostics off standard output so agents can consume the result. This command displays no terminal question interface.
- L'overlay fa parte del webview del pannello, nello stesso bundle delle schede, senza nuove librerie runtime e senza un secondo webview. La Quick Pick e l'input box nativi non si usano più per le domande; il loro codice sparisce.
- Lo stato del round (domande, posizione, risposte confermate, scelte e testo non confermati, riepilogo, riduzione a barra) vive nell'host dell'estensione, non nel webview. Il webview riceve lo stato e manda solo le azioni del developer; l'host le controlla e risponde con lo stato nuovo. Così un pannello chiuso e riaperto, o un webview ricreato, mostra il round esattamente come era. Il testo scritto arriva all'host mentre si scrive, con un breve ritardo, per non perderlo se il pannello si chiude.
- Quando un round entra in Asking, l'host crea il pannello se non c'è o lo porta in primo piano (`reveal` con focus), poi gli manda il round. Il comportamento è lo stesso in ogni editor.
- La notifica dopo la chiusura del pannello è `vscode.window.showInformationMessage` con il pulsante `Reopen`; non si può ritirare, quindi `Reopen` controlla se il round esiste ancora.
- The extension accepts `trama question new` question requests over a user-local Unix-domain socket, or a named pipe on Windows, accessible only to the current OS user. Do not expose an HTTP port or remote service and do not add runtime libraries for this transport.
- Su Windows la named pipe è quella di Node (`net`, `\\.\pipe\trama-question-<uuid>`), senza ponte PowerShell, senza `Add-Type` e senza nessun altro processo: il codice che avvia PowerShell per la pipe o per verificare le ACL sparisce. Poiché una pipe di Node lascia connettere in lettura anche altri utenti locali, ogni richiesta all'editor, su ogni piattaforma, porta il segreto della finestra letto dal suo record di discovery (vedi `data#question-round`): una richiesta senza il segreto giusto non riceve nessuna risposta e la connessione si chiude. Su Windows Trama si affida ai permessi predefiniti di `%LOCALAPPDATA%`, senza controllarli; su Linux e macOS il socket e la cartella dei record mantengono i permessi e i controlli di oggi.
- Supply the launching window's endpoint in the environment of Trama agent terminals. `trama question new` without that address discovers a live endpoint for the same project through user-local runtime records outside the repository, using focus recency to select a window. Stale records are not a reachable editor.
- Preserve workspace/project routing independently of the process working directory, through `trama question new --root <project>`.
- Propagate the interruption of `trama question new` (SIGINT or SIGTERM) and its disconnection to the round's lifecycle. Close controls only for the affected round and release its queue position. Client-side timeouts that are not signalled to Trama cannot be detected; observable cancellation or disconnection is required to remove those rounds.
- Su Windows `SIGTERM` non arriva al processo: `trama question new` si annulla con Ctrl+C (`SIGINT`) o con la chiusura del suo output o della sua connessione, e `docs/cli.md` lo dice. Un processo ucciso senza preavviso conta come disconnessione appena l'editor vede chiudersi la pipe.
- Distinguish initial editor connection failure from loss of an established editor connection after sending a validated round. Connection failure before submission returns initial editor unavailability. Closure or failure of the editor connection after submission and before a complete result returns the shared `editor-interrupted` error without answers; do not wait for a response timeout or translate it into the fallback result.
- For `editor-interrupted`, `trama question new` prints the error with its code and message as JSON on stdout and exits with failure, keeping diagnostics on stderr. This ends the waiting operation, not external agent processes. The agent skills enforce stopping the workflow awaiting those decisions.
- Il risultato `unavailable` ha come `reason` «Editor not available for this project. Do not ask in any other way: stop, tell the developer to open the project in the editor with Trama, and run the same trama question new again when they say to continue.». Il testo non nomina lo strumento di domande dell'agente. `status: "unavailable"` resta un risultato distinto, con uscita 0. `docs/cli.md` riporta il testo e non dice che questo risultato permette lo strumento di domande dell'agente. La riga di comando calcola la cartella dei record di discovery sempre con `process.getuid()`: `CURSOR_SANDBOX` e `CURSOR_ORIG_UID` non si leggono più, e non c'è un secondo testo per la sandbox di Cursor.
- `docs/cli.md` e le skill `trama-design`, `trama-import` e `trama-resolve-drifts` descrivono i campi facoltativi `context` e `details` della richiesta di `trama question new`.
- L'aiuto di `trama question new` (`--help`) dice, nella descrizione del comando e in quella dei campi `question` e `context`, che il developer vede solo il round e non la conversazione dell'agente, quindi ogni domanda con il suo contesto e le sue opzioni deve capirsi da sola, e che i testi non usano la prima persona. La sezione «Asking» di `trama-design`, `trama-import` e `trama-resolve-drifts` lo dice con le stesse parole; `trama-setup`, `trama-scan` e `trama-implement` la seguono con il loro rimando.
- Lo strumento bash di omp uccide un comando allo scadere del suo `timeout`, 300 secondi se non è indicato (lo spostamento in background dopo 60 secondi non cambia la scadenza): il round finiva Abandoned e il developer perdeva tutte le risposte. Le skill `trama-design`, `trama-import` e `trama-resolve-drifts` dicono all'agente di lanciare `trama question new` senza limite di tempo, con `timeout: 0` nello strumento bash di omp, mai un valore fisso, e di aspettarne la fine: niente timer o attese di durata fissa, `sleep`, letture periodiche dell'output del terminale o controlli a intervalli; non chiudono il turno per farsi risvegliare; non considerano fallito `trama question new` né lo ripetono. Non nominano strumenti di attesa di altri agenti (`AwaitShell` di Cursor). La frase dell'istruzione (`rules#agent-terminal`) è la costante `ASK_DEVELOPER_SENTENCE` in `extension/src/host/prompts.ts`.
- `trama-scan` e `trama-implement` non ripetono il formato e le regole di `trama question new`: quando hanno una domanda rimandano alla sezione «Asking» di `trama-design`, come fa `trama-setup`, e valgono anche per loro le regole sull'attesa qui sopra.
- Il messaggio di rifiuto del tool di domande dell'agente è in inglese: «In Trama's work, ask the developer only with `trama question new --root <project>`, as the Trama skill says. This question tool is disabled here.». `<project>` resta scritto così: l'agente conosce il suo progetto. Lo usa l'hook di omp (vedi `tech#agent-hook`).
