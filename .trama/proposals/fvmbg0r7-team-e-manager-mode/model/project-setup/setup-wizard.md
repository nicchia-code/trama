# Setup wizard

Il wizard che guida il developer, a passi, a mettere Trama in una cartella e a scegliere le impostazioni principali di Trama, per poi confermare tutto insieme da un riepilogo. Nulla si salva e nulla si crea prima di quella conferma: chiudere il pannello o annullare a metà non lascia tracce. Ogni passo parte dai valori attuali delle impostazioni utente del developer, così chi ha già configurato Trama deve solo andare avanti.

Il wizard ha tre modi, che differiscono per i passi che mostra e per ciò che fa alla conferma:

- **Primo setup**: in una cartella che non è un progetto Trama, è la scheda Get Started stessa (vedi il Panel). Mostra tutti i passi: percorso, omp, modelli, progetto, cartelle da importare (solo con Import from Code), avanzate e riepilogo. Nel passo del percorso e nel riepilogo, e solo lì, un avviso dice che Trama creerà nella cartella i suoi file, pensati per essere versionati. When Solo mode is chosen in the Project step, the notice says instead that those files stay out of git in this working copy. La conferma salva le impostazioni, inizializza la cartella scelta (vedi il Project) e prosegue con il percorso scelto.
- **Impostazioni**: in un progetto, dal pulsante Guided setup in cima alla scheda Settings, che mostra il wizard al posto del modulo delle impostazioni. Mostra solo omp, modelli, progetto, avanzate e riepilogo. The confirmation saves only the settings and Manager mode.
- **Modello vuoto**: in un progetto con il Modello vuoto, dai pulsanti Import from Code e Start from Scratch del Diagramma o dal comando Import from Code, con il percorso già scelto; il pannello passa alla scheda Settings, che mostra il wizard. Mostra omp, modelli, progetto, le cartelle da importare solo con Import from Code, avanzate e riepilogo. La conferma salva le impostazioni e prosegue con il percorso, senza inizializzare nulla perché il progetto c'è già.

Le impostazioni che il wizard chiede sono un sottoinsieme di quelle della scheda Settings, con gli stessi titoli, gli stessi controlli, le stesse spiegazioni e gli stessi gruppi, nello stesso ordine; come nella scheda Settings, la spiegazione di ogni impostazione si legge subito, sotto il suo titolo, senza aprire nulla che copra il resto del passo. La lingua si sceglie nel passo omp. Auto Exit non è fra i passi e resta nella scheda Settings. Proseguire con Import from Code chiede all'agente di descrivere il codice esistente lasciando fuori le cartelle escluse nel wizard; proseguire con Start from Scratch apre la richiesta di setup del progetto (vedi la Design request). Le cartelle escluse valgono solo per quell'import: non si salvano e non cambiano scan e Run successivi.

In the first setup and empty-Model modes, and only there, the Project step also offers Solo mode with the choice of what it keeps out of git, the same as in the Settings tab (see Solo switch). Solo mode is not a user setting: it starts off in the first setup and from the project's current value in empty-Model mode, it is recorded in the project, never in the user settings, and like everything else nothing is written before the confirmation. Outside a git repository it is shown off and not changeable, saying why. The Guided setup does not show it: there it stays in the Settings tab.

In every mode the Project step also offers Manager mode, the same as in the Settings tab (see Manager mode), with the GitHub repository of origin it would use. Manager mode is not a user setting: it starts off in the first setup and from the project's current value in the other modes, it is recorded in the project, never in the user settings, and like everything else nothing is written before the confirmation. Without origin on GitHub it is shown off and not changeable, saying why.

## States

### Closed (initial)
Nessun wizard è aperto: in un progetto la scheda Settings mostra il modulo delle impostazioni.
- `developer.OPEN_PANEL` → Path: la cartella non è un progetto Trama e il pannello si apre, o era chiuso e torna, su Get Started. Il wizard parte dal primo passo, in modo primo setup.
- `workspace.MODEL_CHANGED` → Path: la cartella non è più un progetto Trama e il pannello torna a Get Started. Il wizard parte dal primo passo, in modo primo setup.
- `developer.OPEN_GUIDED_SETUP` → omp: il developer preme Guided setup nella scheda Settings di un progetto. Il wizard si apre in modo impostazioni.
- `developer.OPEN_GUIDED_SETUP` → omp: il developer preme Import from Code o Start from Scratch nel Diagramma con il Modello vuoto, o lancia il comando Import from Code in un progetto con il Modello vuoto. Il wizard si apre in modo Modello vuoto con quel percorso già scelto. Il comando Import from Code con un Modello non vuoto non apre il wizard e lancia l'import come prima, senza cartelle escluse.

### Open
Il wizard mostra un passo alla volta, sotto un titolo che dice se è il primo setup o il setup guidato, con l'indicazione di quali passi del suo modo ci sono, di quali sono già fatti e di quale si sta guardando. Ogni passo mostra le sue impostazioni una sotto l'altra, e i pulsanti per andare avanti, tornare indietro e confermare restano sempre visibili, anche nei passi lunghi; nulla di ciò che il passo mostra si sovrappone ad altro. In ogni passo il developer cambia liberamente i valori; Back, Next e i passi precedenti scelti nell'indicazione dei passi li conservano, anche tornando indietro di più passi. I passi successivi a quello corrente non si scelgono dall'indicazione: ci si arriva solo con Next, che controlla ogni passo. Un'impostazione cambiata da fuori mentre il wizard è aperto, per esempio dalle impostazioni dell'editor, non sovrascrive i valori del wizard: il riepilogo confronta con il valore che vale in quel momento.
- `developer.CLOSE_PANEL` → Closed: il wizard dimentica tutte le scelte fatte; nulla è salvato. Riaprendo il pannello su Get Started, il wizard riparte dal primo passo con i valori attuali.
- `developer.CANCEL_SETUP` → Closed: solo nei modi impostazioni e Modello vuoto. Nulla è salvato e nulla parte; il wizard dimentica le scelte.
- `workspace.MODEL_CHANGED` → Closed: in modo primo setup, la cartella è diventata un progetto Trama da fuori, per esempio da un'altra finestra o dal controllo di versione. Nulla è salvato e il pannello passa al progetto.
- `workspace.MODEL_CHANGED` → Path: nei modi impostazioni e Modello vuoto, la cartella non è più un progetto Trama. Le scelte sono dimenticate e il wizard riparte dal primo passo in Get Started, in modo primo setup.

#### Path (initial)
Solo nel primo setup. Il developer sceglie come mettere Trama nella cartella: Import from Code, per un progetto che ha già il suo codice, o Start from Scratch, per un applicativo ancora da costruire. All'inizio nessuno dei due è scelto; la scelta fatta si riconosce a colpo d'occhio. Con più cartelle nell'area di lavoro il developer sceglie qui anche quale inizializzare; all'inizio è scelta la prima. Quando è scelto Start from Scratch e la cartella scelta contiene già dei file, un avviso nel passo stesso dice che Start from Scratch li ignora salvo che la richiesta li nomini, mentre Import from Code li descrive; il developer può cambiare percorso subito, senza dialoghi.
- `developer.NEXT_SETUP_STEP` → omp: solo con un percorso scelto; senza, Next non è disponibile e dice perché.

#### omp
omp, l'unico agente con cui Trama lavora, che è obbligatorio: dove trovare omp, dove si apre il suo terminale e se i lavori di Trama ignorano i file di istruzioni degli agenti (vedi l'Agent terminal). Il passo verifica omp ogni volta che si mostra o che il percorso di omp cambia, e mostra il risultato in cima al passo, prima delle impostazioni: se omp risponde, con la sua versione e con quanti modelli, oppure perché non risponde. La verifica guarda anche se c'è una versione nuova di omp, come prima di ogni lancio (vedi Agent launching): se c'è, il passo aggiorna omp da sé, lo stato della verifica mostra l'aggiornamento in corso e poi la versione nuova; un aggiornamento che fallisce lo dice e omp resta quello di prima, che risponde. Quando omp manca, il passo dice che omp è obbligatorio, perché Trama lancia ogni agente con omp, e offre di installarlo, accanto al motivo; finché omp non risponde non si va avanti.

Sotto lo stato della verifica, quando omp risponde, la sezione Providers, la stessa del gruppo omp della scheda Settings (vedi il Panel), offre il login ai fornitori di modelli con abbonamento che Trama conosce, una riga ciascuno con il nome, l'abbonamento, se è collegato e il pulsante del login; a Connected row also has Log out, as in the Settings tab. Un fornitore è collegato quando l'omp del passo ha almeno un suo modello usabile. Il login non è obbligatorio, ma per andare avanti omp deve avere almeno un modello usabile, di qualunque fornitore, anche fuori dall'elenco: senza, il passo Models non avrebbe nessun modello da suggerire.

La riga di Cursor ha anche la chiave API, come nella scheda Settings (vedi il Panel): Set API key o Change API key e, con una chiave salvata, Remove API key. A differenza delle impostazioni del passo, la chiave si salva o si toglie subito, come il login, e resta com'è anche se poi il wizard è annullato; una chiave di Cursor che dà a omp dei modelli basta per andare avanti.

Among the step's settings there is also System Certificates, with the same state of the bundle and the same Refresh as in the Settings tab (see the Panel and Agent launching), so that behind a proxy that inspects HTTPS traffic the developer can turn it on before the check of omp blocks Next. Like the path of omp, the step's value counts at once, even before it is saved, for what the step itself starts: its check of omp, with the update, and the terminals it opens to install omp and to log in. Turning it on in the step exports the bundle and, when the export ends, checks omp again with it; turning it off checks omp again without it. The value is saved with the other choices of the wizard, at the confirmation; cancelling the wizard leaves the saved value as it was, and every other process that Trama starts follows only the saved value.

Ogni volta che il passo si mostra, Trama cerca anche i file di istruzioni che gli agenti caricano da soli: quelli più comuni nella cartella del progetto (nel primo setup quella scelta nel passo Path), quelli generali nelle cartelle che la contengono fino alla cartella home esclusa, e quelli dell'utente. Un file vuoto non conta. Quando ne trova, un avviso dopo le impostazioni dice che l'agente li carica in ogni lavoro di Trama e consiglia di toglierli dal repository o di controllare che non contraddicano Trama, ed elenca i file trovati, uno per riga; scegliere un file lo apre in una scheda dell'editor e il wizard resta dov'è. Con i file di istruzioni ignorati, l'avviso dice anche che i lavori di Trama non li leggono. L'avviso non impedisce di andare avanti e non cambia nulla nei file; senza file trovati non compare.
- `developer.INSTALL_OMP` → omp: solo quando omp manca. Trama apre un terminale visibile con l'installer ufficiale di omp per il sistema del developer (vedi Agent launching); quando il terminale finisce, il passo verifica omp di nuovo. Le scelte del wizard restano.
- `developer.LOG_IN_PROVIDER` → omp: solo quando omp risponde. Trama apre un terminale nuovo e visibile, nell'area dei terminali, in cui l'omp del passo fa il login a quel fornitore, come dalla scheda Settings (vedi il Panel); quando il comando del terminale finisce, riuscito o no, il passo verifica omp di nuovo e aggiorna lo stato dei fornitori e il numero dei modelli. Le scelte del wizard restano.
- `developer.LOG_OUT_PROVIDER` → omp: only when omp answers and the provider's row is Connected, after the developer confirmed. Trama has the step's omp forget every account of that provider, in the background, as from the Settings tab (see the Panel), with the same spinner, error and notice; when omp has finished, the step checks omp again and updates the providers' state and the number of models. If no usable model is left, Next becomes unavailable as for any check. The wizard's choices stay, and the logout stays done even if the wizard is then cancelled.
- `developer.SET_CURSOR_API_KEY` → omp: solo quando omp risponde. Trama salva subito la chiave nel portachiavi dell'editor, come dalla scheda Settings (vedi il Panel), e il passo verifica omp di nuovo con la chiave nuova e aggiorna lo stato dei fornitori, il numero dei modelli e la riga di Cursor. Se il portachiavi non riesce a salvarla, un errore dell'editor lo dice e nulla cambia. Le scelte del wizard restano, e la chiave resta salvata anche se il wizard è poi annullato.
- `developer.REMOVE_CURSOR_API_KEY` → omp: solo quando una chiave è salvata. Trama la toglie subito dal portachiavi dell'editor, come dalla scheda Settings (vedi il Panel), e il passo verifica omp di nuovo senza la chiave e aggiorna lo stato dei fornitori, il numero dei modelli e la riga di Cursor. Se il portachiavi non riesce a toglierla, un errore dell'editor lo dice e nulla cambia. Le scelte del wizard restano.
- `editor.CURSOR_API_KEY_CHANGED` → omp: la riga di Cursor si aggiorna alla chiave di adesso e il passo verifica omp di nuovo, come se il cambio fosse avvenuto in questa finestra. Le scelte del wizard restano.
- `developer.REFRESH_SYSTEM_CERTIFICATES` → omp: only while System Certificates is on in the step and no export is running. Trama exports the bundle again, as from the Settings tab (see the Panel), and the step checks omp again when the export ends, successful or not. The wizard's choices stay.
- `developer.NEXT_SETUP_STEP` → Models: solo quando omp risponde e ha almeno un modello usabile; altrimenti Next non è disponibile e dice perché: che senza omp Trama non lavora, o che omp non ha ancora modelli e serve il login a un fornitore o una chiave API.
- `developer.PREVIOUS_SETUP_STEP` → Path: solo nel primo setup; negli altri modi omp è il primo passo e Back non è disponibile.
- `developer.OPEN_SETUP_STEP` → Path: il developer sceglie Path nell'indicazione dei passi, solo nel primo setup. Le scelte restano.

#### Models
I tre ruoli dei modelli (analisi, scansione, esecuzione), ciascuno con il suo livello di thinking come nella scheda Settings quando omp dichiara dei livelli per il modello scelto, e il numero massimo di sotto-agenti in parallelo. Sotto ogni ruolo una frase consiglia, a parole e senza nominare modelli, il suo peso: il modello più capace per l'analisi, uno intermedio per l'esecuzione, uno veloce e leggero per la scansione. Il wizard non sceglie né ordina i modelli in base al consiglio. I modelli suggeriti, e i loro livelli, sono quelli che dichiara l'omp scelto nel passo precedente, anche se il suo percorso non è ancora salvato. Un numero di sotto-agenti non valido mostra perché e Next non è disponibile finché non torna valido.
- `developer.NEXT_SETUP_STEP` → Project: solo con valori validi.
- `developer.PREVIOUS_SETUP_STEP` → omp
- `developer.OPEN_SETUP_STEP` → Path: il developer sceglie Path nell'indicazione dei passi, solo nel primo setup. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → omp: il developer sceglie omp nell'indicazione dei passi. Le scelte restano.

#### Project
La cartella in cui Trama installa le skill dell'agente. Quando il workspace ha un valore che prevale su quello utente, un avviso dice quale vale davvero. In the first setup and empty-Model modes, below the folder of the skills, Solo mode and, while it is chosen, what it keeps out of git. In every mode, last, Manager mode with the repository of origin.
- `developer.NEXT_SETUP_STEP` → Folders: il percorso è Import from Code.
- `developer.NEXT_SETUP_STEP` → Advanced: il percorso è Start from Scratch, o il wizard è in modo impostazioni.
- `developer.PREVIOUS_SETUP_STEP` → Models
- `developer.OPEN_SETUP_STEP` → Path: il developer sceglie Path nell'indicazione dei passi, solo nel primo setup. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → omp: il developer sceglie omp nell'indicazione dei passi. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → Models: il developer sceglie Models nell'indicazione dei passi. Le scelte restano.

#### Folders
Solo con Import from Code. L'albero delle cartelle della cartella scelta, con tutte le cartelle incluse all'inizio; le cartelle nascoste e quelle che il controllo di versione ignora non compaiono. Cartelle e file si distinguono a colpo d'occhio, e il nome intero di una voce si può sempre leggere. Il developer toglie le cartelle che l'agente non deve importare; togliere una cartella toglie anche tutto ciò che contiene. Le scelte restano tornando indietro e cambiando passi, ma si perdono se il developer cambia la cartella da inizializzare.
- `developer.NEXT_SETUP_STEP` → Advanced: solo con almeno una cartella, o un file al primo livello, ancora incluso; altrimenti Next non è disponibile e dice perché.
- `developer.PREVIOUS_SETUP_STEP` → Project
- `developer.OPEN_SETUP_STEP` → Path: il developer sceglie Path nell'indicazione dei passi, solo nel primo setup. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → omp: il developer sceglie omp nell'indicazione dei passi. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → Models: il developer sceglie Models nell'indicazione dei passi. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → Project: il developer sceglie Project nell'indicazione dei passi. Le scelte restano.

#### Advanced
The panel theme and the optional features, divided by topic into the same sub-groups as the Advanced group of the Settings tab, except Notifications: the away notifications are set only in the Settings tab, never in the wizard nor in its summary. Il passo si può saltare.
- `developer.NEXT_SETUP_STEP` → Summary
- `developer.SKIP_SETUP_STEP` → Summary: i valori del passo tornano a quelli attuali, anche quelli già cambiati nel passo.
- `developer.PREVIOUS_SETUP_STEP` → Folders: il percorso è Import from Code.
- `developer.PREVIOUS_SETUP_STEP` → Project: il percorso è Start from Scratch, o il wizard è in modo impostazioni.
- `developer.OPEN_SETUP_STEP` → Path: il developer sceglie Path nell'indicazione dei passi, solo nel primo setup. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → omp: il developer sceglie omp nell'indicazione dei passi. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → Models: il developer sceglie Models nell'indicazione dei passi. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → Project: il developer sceglie Project nell'indicazione dei passi. Le scelte restano.
- `developer.OPEN_SETUP_STEP` → Folders: il developer sceglie Folders nell'indicazione dei passi, solo con Import from Code. Le scelte restano.

#### Summary
Tutte le scelte del wizard, passo per passo, ogni passo per conto suo: il percorso e la cartella, ogni impostazione dei passi con il suo valore, con evidenziate, insieme al valore attuale che sostituiscono, quelle che cambiano il valore attuale, e le cartelle escluse. Ogni passo del riepilogo ha un pulsante Edit che riporta a quel passo, e l'indicazione dei passi riporta a un passo come negli altri. Mentre la conferma è in corso, comprese le domande e gli avvisi che apre, nessun pulsante del wizard si può premere. In the first setup and empty-Model modes the Project step of the summary also says whether Solo mode is on and, when it is, what it keeps out of git. In every mode it also says whether Manager mode is on, highlighted when it changes the project's current value.
- `developer.OPEN_SETUP_STEP` → Path: il developer preme Edit sul percorso e la cartella, o sceglie Path nell'indicazione dei passi, solo nel primo setup.
- `developer.OPEN_SETUP_STEP` → omp: il developer preme Edit su omp, o sceglie omp nell'indicazione dei passi.
- `developer.OPEN_SETUP_STEP` → Models: il developer preme Edit sui modelli, o sceglie Models nell'indicazione dei passi.
- `developer.OPEN_SETUP_STEP` → Project: il developer preme Edit sulla cartella delle skill, o sceglie Project nell'indicazione dei passi.
- `developer.OPEN_SETUP_STEP` → Folders: il developer preme Edit sulle cartelle escluse, o sceglie Folders nell'indicazione dei passi, solo con Import from Code.
- `developer.OPEN_SETUP_STEP` → Advanced: il developer preme Edit sul tema e le funzioni facoltative, o sceglie Advanced nell'indicazione dei passi.
- `developer.PREVIOUS_SETUP_STEP` → Advanced
- `developer.INITIALIZE_PROJECT` → Closed: in modo primo setup il developer conferma e tutto riesce. Le impostazioni che cambiano sono salvate nelle impostazioni utente, come dalla scheda Settings; poi Trama inizializza la cartella scelta, con la cartella delle skill scelta (vedi il Project); poi prosegue con il percorso: con Import from Code chiede all'agente di descrivere il codice lasciando fuori le cartelle escluse, con Start from Scratch apre la richiesta di setup. Il pannello mostra il progetto. With Solo mode chosen, the initialization turns it on before writing any file of Trama (see Solo switch). With Manager mode chosen, the initialization records it once the project exists; failing to record it does not undo the project (see Manager mode).
- `developer.INITIALIZE_PROJECT` → Summary: in modo primo setup, il salvataggio di un'impostazione fallisce, il developer rifiuta di sovrascrivere skill personalizzate, oppure l'inizializzazione fallisce. Le impostazioni già salvate restano salvate e nulla parte. Il riepilogo mostra il motivo accanto alla conferma, salvo per un rifiuto, e la conferma si può ripetere senza rifare i passi. Failing to turn on the chosen Solo mode is a failed initialization: nothing of the project is created.
- `developer.CONFIRM_SETUP` → Closed: nei modi impostazioni e Modello vuoto il developer conferma e ogni salvataggio riesce. Le impostazioni che cambiano sono salvate nelle impostazioni utente; in modo Modello vuoto Trama prosegue poi con il percorso, come nel primo setup ma senza inizializzare. In empty-Model mode, when the choice of Solo mode changes the project's current value, Trama turns it on, changes what it keeps out of git or turns it off (see Solo switch) after the settings and before going on with the path. In both modes, when the choice of Manager mode changes the project's current value, Trama turns it on or off (see Manager mode) after the settings and before going on with the path.
- `developer.CONFIRM_SETUP` → Summary: il salvataggio di un'impostazione fallisce. Le impostazioni già salvate restano salvate e nulla parte; il riepilogo mostra il motivo accanto alla conferma e la conferma si può ripetere. A failed write of Solo mode counts as a failed save.
