# Trama

Shows the Trama Model of your project (`.trama/model/`) as a read-only Diagram, its Requirements (`.trama/requirements/`) in a read-only Requirements tab, and a Board of Proposals, Drifts and Tasks: Backlog holds the open Proposals and the Drifts, Active every Task in To do or In progress (the blocked ones too), Done the finished work as History, and System Activities the ghosts of what the agent is preparing. The Board is read-only for Tasks: it offers no arrows, dragging or Take back button, and the editor accepts no message to move a Task or take it back; moving a Task and taking it back stay in the command line (`trama task move`, which takes back a Task the agent has when you move it to In progress). Descriptions, Requirements, Proposal bodies, Task bodies and Drift texts are shown as Markdown. You never edit the Diagram: you ask your coding agent, then approve or reject its Proposals. Requirement files you may also edit by hand; the extension regenerates the `trama-req-*` agent skills whenever they change.

**Notes on ghosts.** While the agent works it declares notes on the ghosts of its work (`trama announcement edit` with `{ "note": "…" }`, on one announcement by its ID or, without an ID, on every ghost of its terminal or Cursor chat conversation, comparisons excepted): one line of at most 120 characters about what it is doing and why. A ghost keeps its last 6 notes, each with the instant it arrived, in its `announcements/<id>.md` file (`notes`, local and never versioned), and the Board snapshot carries them with `announced`, the instant the ghost was born. The ghost shows the last note under its phase, and clicking it opens its details: what the ghost is doing, how long it has gone on and the notes. A note changes neither the phase, the title nor the delivery or withdrawal of the ghost, and it does not count as the agent's activity.

Il filtro Done usa giorni locali: `Today`, `Last 7 days` e `Last 30 days` includono oggi e rispettivamente zero, sei o ventinove giorni precedenti, fino alla mezzanotte successiva esclusa, anche al cambio dell'ora. Le schede finite nei giorni futuri non compaiono né entrano nel contatore; `All` le mostra e conserva in fondo il gruppo `No date`.

- **Trama: Open** opens the panel on the Diagram tab, whose tabs are Board, Diagram, Requirements and Settings. In a folder without `.trama/` it opens on Get Started instead, the setup wizard: it asks, step by step, how to start (**Import from Code** or **Start from Scratch**, and the folder when the workspace has several), the agent, the models, where the skills go, which folders the import leaves out and the theme and experimental features, then sets the project up only when you confirm its summary. In a project, **Guided setup** at the top of the Settings tab opens the same wizard to review the main settings.
- **Trama: Scan System** and the Scan and Run buttons send a prompt to your agent. Design requests start only from the Board's **Add Work Item…** button, and, while the Model is empty, from the Diagram's **Import from Code** and **Start from Scratch** buttons under its empty-Model text, which links to the Board; those two buttons open the setup wizard in the Settings tab with that path chosen.
- **Add Quick Task**, in the menu of the arrow next to the Board's **+ Add Work Item**, opens a new, bare chat with your agent for a small job: no instruction, no skill, no scan, no Proposal. With omp it is a terminal named `Quick` that takes the focus and runs `omp` on the model of `trama.execution`; with Cursor's chat it is an empty new conversation that Trama does not follow.
- The **Add Work Item…** button and the Board's **+ Work Item** create an empty file `.trama/requests/<id>.md`, named after the local date and time (for example `2026-10-04T19-05-12.md`, with `-2`, `-3`, … when taken), and open it in a tab where you write a design request at length. The folder has its own `.gitignore`, so requests are never versioned. Trama saves the file by itself shortly after every change, whatever `files.autoSave` says, so closing the tab never asks to save. **Send to agent** in the editor title (or closing the tab) sends the agent `Use the trama-design skill on the design request in .trama/requests/<id>.md. …` and closes the tab; with the terminal launcher the ghost on the Board takes the request's title. An empty text sends nothing: **Send to agent** warns, and closing the tab deletes the file silently. If the instruction does not leave (for example you cancel the agent command prompt), the request stays on disk unsent; reopen it from the Explorer to send it. A request is sent once: Trama remembers the sent ones across restarts, and a sent request reopened can be edited but has no **Send to agent**, and closing it sends nothing. Closing the editor window sends nothing either. The agent binds its first Proposal to the request, and handing that Proposal over deletes the file; its tab closes unless it has unsaved changes.
- An empty request tab shows a grey ghost text saying what to write and how to send it (Send to agent, or closing the tab). It is only on screen, never saved or sent, and it disappears at the first character; a request already sent shows none.
- **Trama: Import from Code** asks your agent to describe the existing code as Proposals (a first one for the System and its Actors, then one per Feature, each requiring the first). They describe the code as it is and list their doubts; approving them starts no Scan. With an empty Model it opens the setup wizard in the Settings tab with Import from Code chosen, where you can leave folders out of this import (the exclusions are not saved); with a Model it imports at once, as before.
- **Trama: Update Agent Skills** installs this version's skills into the project, adds the starting Requirement Areas to projects created before they existed, converts Areas still written as one file `requirements/<area>.md` into a folder with `area.md` and `main.md`, and regenerates the Requirement skills; its notification says which Areas it converted or left, and the mode of the Requirement skills (one per fragment, or one index per Area).

Every ordinary opening of Trama (the status bar button, the Open Trama icon or command, and **Reopen** on the questions notice) also checks, in the background and after the panel is shown, whether what Trama installs for the agent differs from this version: the agent skills in `trama.skillsDir`, the retired `trama-fix` skill and `trama-triage` definition, omp's `trama-analysis` definition and `.omp/WATCHDOG.yml`, the Requirement skills, and the chat's user definition of `trama-analysis` with the current `trama.scan`. If something differs it brings it in line as Update Agent Skills does, replacing hand-edited copies without asking and writing only files whose content changes, and shows «Trama: updated the agent skills to this version.»; if everything matches it shows nothing. It does not convert single-file Areas, create the starting Areas or touch the editor hooks. A failure shows «Trama: could not update the agent skills: <reason>.» and the next opening checks again. It does not run when the panel opens by itself for a question round, in a window with no folder, or on Get Started.

Le modifiche, aggiunte e cancellazioni nei Requisiti rigenerano automaticamente le skill del progetto della cartella modificata, anche con il pannello chiuso. Nei workspace con più cartelle ogni progetto ha una pausa breve indipendente; un errore di rigenerazione viene mostrato al developer.

Cards are named on the Board, in the panel and in the buttons by their **short number**: `P3` for a Proposal, `T3` for a Task, `D3` for a Drift. The number is temporary and belongs to this working copy (it is kept in `.trama/short-numbers/`, which is never versioned), so another copy or worktree may give the same card another number; a card that is closed (a decided Proposal, a resolved Drift, a Task in Done) has no number and shows its permanent eight-character identity instead, never both. The two look alike, in the same place and font, and are told apart by the tooltip and accessible name, **Short number (temporary)** or **Permanent ID**. Everything Trama writes into files, branches and instructions to the agent uses the identity. The command line accepts the number too (`trama task move T3 doing`); see the [CLI conventions](https://github.com/nicchia-code/trama/blob/main/docs/cli.md#conventions).
Choose where prompts go with the application-scoped `trama.agent` setting, for every project and instruction:

- `cursor` (the default): Cursor's chat, in Cursor only. Outside Cursor the instruction goes to the clipboard with a notice that asks you to choose omp.
- `omp`: starts `omp` in a new integrated terminal; supported in Cursor and in every compatible editor, such as VS Code.

`trama.terminalLocation` applies to `omp`: `panel` (the default) creates the terminal in the terminal area without showing it; `editor` opens it as a tab in the active editor group without taking focus. Only the user value `editor` selects a tab; an absent or unrecognised value uses the terminal area. Existing values for removed settings are ignored and never rewritten.

`trama.ignoreInstructionFiles` (`false` by default, application-scoped) applies to `omp`: when on, Trama's jobs ignore agent instruction files (AGENTS.md, CLAUDE.md, Cursor rules, .omp/RULES.md) in the project, the folders above it and your user folders. It is read from your user settings only; a value that is not a boolean counts as off. It shows in the Agent group of the Settings tab whichever agent is chosen.

With `omp` and `trama.ignoreInstructionFiles` on, each launch (read at that moment) searches the instruction files of the project again and passes omp an overlay, `launch.yml` in the extension's storage, with `--config`: its `disabledExtensions` are yours (from `<project>/.omp/config.yml`, else `~/.omp/agent/config.yml`) plus the files found: context files (`context-file:project:AGENTS.md`, `context-file:project:CLAUDE.md` and the same for the user), the fixed rules (`rule:RULES@project`, `rule:RULES`) and each Cursor rule one by one (`rule:<name>`). Sub-agents and advisors inherit them; `.cursorrules` has no exclusion because omp does not read it. With no file found, or the setting off, nothing changes; a failure of the search never stops the launch. Skills, sub-agents and `.omp/WATCHDOG.yml` are never excluded.

Every instruction uses the current setting, including import and project initialization. No first-launch prompt, custom commands or other terminal agents are supported. Terminals are never reused.

Agents run the `trama` CLI, so it must be on their `PATH`. `trama.skillsDir` is where the setup wizard installs the agent skills.

No Drift resolves itself: there is no delegation, no automatic approval and no automatic Run. Resolve on a Drift card takes only that Drift, asks you the decisions and hands over a resolution for you to review; the Tasks that come out of it start by hand. `Resolve all` does not exist any more, and a Drift has no severity (`critical`).

Unify Drifts (the first item of the arrow menu of **+ Add Work Item**) has the agent merge every open Drift that is in no resolution being written or open, at least two, into one **unified Drift** with `trama drift new` and `unifies`. The unified Drift is a new Drift like the others, Open, with its red card; it remembers the origins of all the merged Drifts and follows all their precedents (`unified` and `recurring` badges), and its details list the merged Drifts. The merged Drifts leave the Board as `Unified` and are no Drift decided: they are not counted among the Drifts already resolved. The model chosen for a Proposal applies to Resolve on a unified Drift only when all its origins belong to that Proposal.

`trama.submitWhileRunning` is a checkbox, `false` by default. With `false`, Run all and each Task's Run are unavailable while a run started by Trama is not finished: its end-of-run scan included,. With `true`, a run can start while another one is in progress. Any value that is not a boolean (for example the former text `disabled` or `enabled`) counts as `false` and is never rewritten. It applies in your user and workspace settings.

`trama.language` is the language the agent writes in, typed as free text (`Italian`, `Deutsch`…) and empty by default. When it is set, every instruction Trama sends to the agent ends with `Write everything you generate in <language>, except code, which always stays in English.` That covers the text the agent writes for Trama; code, comments, commit messages, project documentation, names and titles, IDs, Event names and required section titles stay English. The setting is read at each launch, changes nothing already written and is not saved in the project.

On the first start of the extension in an editor, when you have no `trama.language` in your user settings, Trama detects it: the language of your operating system (`LC_ALL`, `LC_MESSAGES`, `LANG`), else the editor's language, else `English`, and saves its English name (`Italian`) in your user settings. It happens once per editor; a value you already have, or one you clear later, is never changed again.

`trama.maxParallelAgents` is an application-scoped number, default 20 and minimum 1. It tells the agent how many sub-agents to run at once in a scan, in the exploration of a design or of a Drift resolution and in a Task run; agents without sub-agents ignore it. Empty, non-integer or less than 1 values use 20. The same value appears in each instruction and in the `max` of `trama task list` for implementation runs. Workspace settings do not override it.

`trama.theme` is the colours of the Trama panel: `auto` (the default) follows the editor, light with a light theme and dark with a dark one, high contrast included; `light` and `dark` keep the panel in that theme. It is application-scoped, read from your user settings only, and a change applies at once in the open panel. It is the only setting of the Appearance group.

The Settings tab of the Trama panel lists every `trama.*` setting in groups (Appearance, Agent, Models, Project, Experimental), with its title and explanation. Choose a value there and it is saved at once in your user settings, never in the workspace's; a text field saves when it loses focus or on Enter, and an empty text or the default value removes the value from your user settings. No setting asks for confirmation. A workspace value that overrides a setting is shown under its control.

The Experimental group also holds `trama.submitWhileRunning`, a checkbox, off by default: with it off, Run all and each Task's Run are unavailable while a run started by Trama is not finished; with it on, a run can start while another one is in progress. It also holds `trama.experimentalDriftBlocker`, a checkbox, off by default and application-scoped. Experimental: on, the agent that files a Drift checks which Tasks it would block are really affected, blocks only those and explains why it leaves the others free; a Drift that blocks no Task is filed inside a resolution Proposal for you to approve. Off, a Drift blocks every Task that concerns the same thing. Only agents started by Trama follow it.

`trama.experimentalAdvisorScanner` is the Experimental Advisor Scanner, a checkbox, off by default and application-scoped; it is shown whatever `trama.agent` is. It is active with every agent: on, during every Run, the advisor (omp's with omp, Trama's `trama-advisor` sub-agent in Cursor's chat) checks the code the agent reads and writes against the Model and the Requirements, tells the agent when its work drifts and files a Drift for a difference in existing code. While it is active every scan is off (the Scan buttons, the pre-flight and the end-of-run scan), and the advisor uses the Scan model. Off, scans work as usual. Trama's advisors live in `.omp/WATCHDOG.yml`, installed in every project: in an omp session you start yourself with the advisor on, they replace omp's default advisor, run only `trama advisor show` and then stay silent.

`trama.experimentalParallelExecution` is the Experimental Parallel Execution, a checkbox, off by default and application-scoped, shown after the Experimental Advisor Scanner. Experimental, only for runs over several Tasks with an agent that has sub-agents: on, the agent reads the Tasks before the run and may start together Tasks that Trama would keep apart because they concern the same thing, or hold a Task until another is done, giving a reason for each choice; a sub-agent that finds its Task touching the same things as another stops, and the agent resumes it later. Off, Trama never gives two Tasks that concern the same thing at once. Only agents started by Trama follow it. The host reads it from the user settings only: a workspace value or a non-boolean counts as off.

With `trama.experimentalAsyncDriftResolver` on (Experimental group, off by default, application-scoped, read from your user settings only), the instruction of a scan, a Run or an import carries the sentence "The Async Drift Resolver is on: …", and the main agent, before it finishes, prepares with its sub-agents (at most `trama.maxParallelAgents` at once) the resolution question of each Drift the work filed; the report says how many were prepared. The `trama-resolve-drifts` skill describes how a prepared question is written and how the agent works when the developer's answer to it is already in the instruction; `trama-scan`, `trama-implement` and `trama-import` have an "Async Drift Resolver" section that applies only with that sentence. With it on, at the click, Resolve on a Drift with a valid prepared question starts no agent and announces no ghost: it opens that question at once as a one-question round labelled `Prepared question`, with the recommendation selected. A Fix option (its free text is the note), or closing the Drift or adopting its attached Proposal with no free text, is written and handed over by Trama as a resolution Proposal marked `prepared`, and its yellow card appears in the Backlog; free text with another option, or a refused hand-over, launches the usual agent with the answer. A skip or a lost editor writes nothing and the question stays prepared. While the question is open Run, Run all, the Resolve of other Drifts and Dismiss Drift are unavailable; a resolution awaiting a decision never stops Resolve on a Drift with a valid prepared question.

The main agent finds those Drifts with `trama drift list` and `{ "currentJob": true, "unprepared": true }`, in a terminal and in Cursor's chat alike: in the chat `TRAMA_JOB` arrives with the `trama` commands the hook completes, so the Drifts filed there (and those the `trama-advisor` sub-agent files) carry their `job` like the ones of a terminal.

`trama.experimentalContextSharing` (Experimental group, after the Async Drift Resolver, off by default, application-scoped, read from your user settings only) is for an agent that has sub-agents. On: when the agent hands work to its sub-agents, it passes each one the part of what it has already read that concerns that work (Trama's texts quoted as they are, and where the code is), so sub-agents do not read it again; they still read the code themselves. Off: each sub-agent reads what it needs on its own. Only agents started by Trama follow it, and the command line does not read it.

## Terminal agents and model roles

There is one terminal agent, omp (`omp`). Each instruction uses the model role that matches its work; empty roles leave the agent's default model:

- `trama.analysis`: design requests (written), Resolve Drifts and import.
- `trama.scan`: scans of the System and Features.
- `trama.execution`: implement and implement all, including the final selective scan of the run.

For instructions that can scan, omp receives the `trama-analysis` sub-agent sentence, and gets `--slow <scan>` when `trama.scan` is set.

Cursor's chat (`cursor`) takes the same roles: the role's model starts the new conversation only, with Max mode off. Chat instructions that can scan carry the sub-agent sentence too. Get Started, Update Agent Skills and the check when Trama opens write the chat's user definitions of `trama-analysis` and `trama-advisor` (`~/.cursor/agents/`) with the current `trama.scan`; opening Trama refreshes them when they differ.

## Cursor

Cursor is supported (tested on 3.22.12 and 3.23.12), in the editor window; Cursor's Agents Window is not supported.

- **Delivery.** The chat launcher tries, in order, and moves on silently when a step is missing or fails: a new chat that sends the prompt by itself (Cursor's internal `composer.createNew`); the prompt deeplink, which opens a chat that waits for your confirmation and Enter (skipped when Cursor would refuse the text: empty, over 10,000 characters encoded, or naming `.env`); the clipboard, with a notice to paste it. No step is tried twice for the same prompt. The new chat counts as sent whenever Cursor raises no error (the command never returns anything), and Trama does not check afterwards that the chat really sent the prompt.
- **PATH.** Cursor runs its agent's commands without the PATH the extension gives the editor's terminals, so every instruction to Cursor's chat has a second line telling the agent to `export PATH="<folder of the bundled trama>:$PATH"` (absent when the package has no binary for the platform).
- **The agent.** Cursor sets `CURSOR_AGENT=1` in its chat agent's shell, and the CLI treats it as `TRAMA_AGENT` (ADR 0010): the developer's decisions are refused, a move to In progress takes the Task, and announcements made there carry `chat: cursor`.
- **Hooks.** In Cursor, **Get Started** and **Update Agent Skills** write Trama's entries for `beforeSubmitPrompt`, `stop`, `sessionEnd` and `afterShellExecution` into your own `~/.cursor/hooks.json` (never the project's), each running `"<bundled trama>" hook cursor`; the shell-command entry carries `"matcher": "trama"`, so Cursor runs it only for command lines containing `trama`. Update rewrites them for the new version's path, and activation leaves the file alone when its entries are already these. Other entries are kept; a file that is not valid JSON is left alone and you are told. The hook passes each editor window of the project only the event, the conversation and the project folder, never the prompt or a command line, never blocks Cursor, and gives up after one second for a prompt or five seconds for the other hooks.
- **Fine di un turno.** Una conversazione è di Trama dal primo prompt che inizia con `Use the trama-` o `/trama-`, chiunque lo scriva. Quando un turno viene interrotto o fallisce, i ghost annunciati dalla chat di Cursor vengono ritirati con il consueto avviso locale; chiudere la conversazione li ritira senza avviso, mentre una fine normale li lascia alla consegna della scheda o al periodo di inattività. Ogni fine di turno, normale, interrotta o fallita, e la chiusura della conversazione riportano a To do tutti i Task presi dall'agente nel progetto (si presume un agente alla volta); l'agente riprende un Task quando riparte.
- **Domande.** `trama question new` dalla chat agente di Cursor raggiunge la finestra del progetto attiva più di recente e apre il normale overlay locale. Nella sandbox di Cursor le skill riprovano una sola volta un `trama question new` inizialmente `unavailable` al di fuori della sandbox e continuano ad attenderlo anche quando Cursor lo sposta in background.

## Agent questions

Agents ask with `trama question new --root <project> --input -`, which reads the JSON request on standard input; see the [request and result contract](https://github.com/nicchia-code/trama/blob/main/docs/cli.md#question-rounds).

The active round opens immediately as an overlay inside the Trama panel, which comes to the front (or opens) over whatever tab it shows. The header names the agent and the step (`Question <n> of <total>`); an index on the left lists every question with its state (**Answered**, **Skipped**, **Missing**) and ends with **Summary**, and below 600 px it becomes a row of numbered dots. The question, its context, the option descriptions and their **Show details** are Markdown. The recommended option is chosen on the first visit; keys 1–9 pick an option; **Your answer (optional)** takes free text, alone or beside the chosen options. **Next** confirms and moves on (**Review** on the last question), **Back** and the index move without confirming, **Skip** skips one question.

The **Summary** shows every answer, with **Edit** to reopen a question, and **Send to agent** delivers the round once nothing is missing. **Skip all**, and the **Close** button, ask first (`Skip all unanswered questions?`) and then deliver at once, the agent using its recommendation for each skipped question. **Minimize** shrinks the round to a bar at the top of the panel with **Open questions**; closing the panel with a round open shows `Trama has questions from the agent waiting.` with **Reopen**. Esc and focus loss do nothing.

Each window has one FIFO shared by every `trama question new` caller, with no response deadline. Caller cancellation removes only that round. Closing the window, losing its channel, or removing its project interrupts every admitted active and queued round with `editor-interrupted`, disposes the controls and returns no partial answers. The agent must stop its workflow without fallback or retry. Initial editor absence instead returns `unavailable`, allowing its own question interface.

Local discovery chooses the most recently focused live window for the project unless a launching endpoint was supplied. Its records contain no question content and stay outside the repository. Unix sockets and Windows named pipes are user-private; Windows requires its built-in Windows PowerShell 5.1/.NET Framework bridge, not an additional runtime library.

The extension never calls a language model. The agent performs scans directly, comparing each Machine with the Model and Requirements.
