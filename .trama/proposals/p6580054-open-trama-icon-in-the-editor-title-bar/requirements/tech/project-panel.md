# Tecnologia del progetto e del pannello

## project
- L'estensione si avvia da sola solo nelle cartelle che contengono `.trama/model/system.md` (`activationEvents`); altrove si avvia quando il developer usa uno dei suoi comandi, compresa l'icona Open Trama, con l'attivazione implicita dei comandi dichiarati in `contributes.commands`. Nessun `activationEvents` nuovo: l'icona è dichiarata nel manifest e compare senza avviare l'estensione. The panel offers to initialize a workspace that has no `.trama/`; initializing runs the same code as `trama init` with the configured skills folder.
- When the package ships a `trama` binary for the platform, its folder is put first on the PATH of the editor's terminals so the agent finds it.
- Il `PATH` aggiunto dall'estensione vale per i terminali dell'editor, non per i comandi dell'agente di Cursor: Cursor li avvia come processi propri con il proprio ambiente (verificato nel suo codice, 3.22.12). Per questo l'istruzione alla chat di Cursor dice all'agente dove trovare `trama` (vedi `rules#agent-terminal`).
- `trama ids rewrite` non prende argomenti. Non è più rifiutato con `TRAMA_AGENT=1` o `CURSOR_AGENT=1`: esegue una decisione del developer anche quando la richiesta arriva dall'agente. Il pannello non ha un pulsante e non manda un messaggio per lanciarlo. Non crea un commit. `docs/cli.md` lo descrive. I messaggi del comando restano in inglese, come il resto dell'interfaccia.
- Le due soglie dei frammenti sono costanti in `src/core`, condivise da riga di comando ed estensione: 4.000 caratteri per il budget delle skill di Requisiti e 12.288 byte per un frammento. Il budget nasce dall'elenco delle skill che gli agenti ricevono all'avvio, il cui minimo misurato è circa 8.000 caratteri (Claude Code: 1% della finestra di contesto, documentazione delle skill; Codex: 2% della finestra, ripiego `DEFAULT_SKILL_METADATA_CHAR_BUDGET` di 8.000 caratteri in `codex-rs/ext/skills/src/render.rs`): 4.000 ne lascia metà alle skill di Trama e alle altre del developer.
- Il watcher dei Requisiti, nell'estensione e nella rigenerazione delle skill, segue anche i file dentro le cartelle delle Aree.
- La skill `trama-design` e il suo riferimento di formato descrivono le Aree come cartelle con `area.md` e frammenti, le due modalità delle skill di Requisiti, gli avvisi di `trama validate` e quando dividere un frammento; `trama proposal edit` accetta `requirements/<area>/area.md` e `requirements/<area>/<frammento>.md` e rifiuta `requirements/<area>.md` e percorsi più profondi. `docs/` descrive il formato nuovo e la migrazione con `trama skills update`.

## panel
- Markdown in the panel is rendered by a small renderer of our own in the webview code, with no new runtime library. One renderer serves the Diagram, the Board and the Requirements tabs, e anche l'overlay delle domande, and it is a plain function from text to DOM nodes that can be tested without a browser page.
- The renderer builds elements with the DOM API and sets text with `textContent`; it never uses `innerHTML` or similar, so no text from a file can inject markup or script. Links are only given an `href` when they are http or https, and are opened by the editor host in the system browser, not by navigating the webview.
- The messages between the Board and the editor host have no move and no take-back message: the host does not accept a request to move a Task or to take one back from the panel, and the Board never sends one. The panel's Task actions are only the launch messages (run a Task, run every Task in To do, run a design, Resolve Drifts), the decisions on Proposals, and opening links. Nessun messaggio decide su un singolo Drift. Moving a Task and taking it back stay in the command line (`trama task move`, `trama task take-back`), which the panel does not wrap.
- L'icona Open Trama è il comando esistente `trama.open` con `icon` `{ "light": …, "dark": … }` che punta a due SVG del pacchetto dell'estensione, in `menus.editor/title` con `"when": "workspaceFolderCount > 0"`, nel gruppo `navigation`. Gli ordini nel gruppo (`navigation@<n>`) mettono `trama.open` dopo `trama.sendDesignRequest`, così sta alla sua destra. Nessuna chiave di contesto nuova: la visibilità non dipende dal progetto né dalla scheda attiva.
- I due SVG sono ridisegnati da `trama-icon.png` (sei barre intrecciate): 16×16, un solo colore, il logo dentro 14×14 con 1 px di margine. Quello per i temi chiari è scuro, quello per i temi scuri è chiaro. Lo stesso paio è `WebviewPanel.iconPath` del pannello.
- L'icona dell'estensione (`icon` in `extension/package.json`) è un PNG 128×128 del logo nero su fondo bianco, ricavato da `trama-icon.png`.
- I file delle icone stanno dentro `extension/` e `extension/.vscodeignore` li include, così finiscono nel `.vsix`.
