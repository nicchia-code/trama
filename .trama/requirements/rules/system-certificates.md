# System certificates

## developer.REFRESH_SYSTEM_CERTIFICATES
- The mode is the setting `trama.systemCertificates`, off by default. Trama never turns it on, never offers to turn it on and never mentions it in a message about an error. Only the developer's user setting counts: a workspace value is ignored.
- Sources of the export, read only, with no choice left to the developer:
  - macOS: the certificates of the system keychains `/Library/Keychains/System.keychain` and `/System/Library/Keychains/SystemRootCertificates.keychain`. The user's `login` keychain is never read.
  - Windows: the store `Cert:\LocalMachine\Root`. The user's store (`Cert:\CurrentUser\Root`) is never read.
  - Linux: the first of these files that exists and can be read: `/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`, `/etc/ssl/ca-bundle.pem`, `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`, `/etc/ssl/cert.pem`.
- Content of the bundle: every certificate of the source that is a certificate authority, plus the public root authorities that the editor's runtime ships, each once. A certificate that cannot be read, or that is not a certificate authority, is left out without failing the export.
- The export fails when the source cannot be read (command missing, exit code other than 0, no Linux file found), when it has not finished within 30 seconds, when the source gives no certificate authority at all, or when the bundle cannot be written. A failed export never replaces or deletes the earlier bundle.
- The bundle is one file per user, at a fixed path (`tech#developer.REFRESH_SYSTEM_CERTIFICATES`), shared by every window and project. It is written whole or not at all: a process never reads a half-written bundle.
- When Trama exports, only while the mode is on:
  - when the developer turns the mode on (in the Settings tab, or in the wizard's `omp` step for the step's own processes, `rules#setup-wizard`);
  - when the extension starts and the bundle is missing or was last written more than 24 hours earlier;
  - when the developer presses `Refresh` or runs the `Refresh System Certificates` command.
  A second request while an export of the same window is running does nothing. While the mode is off nothing is exported, and the bundle already written stays on disk, unused.
- Variables: while the mode is on and a bundle exists, every process listed below receives `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`, `GIT_SSL_CAINFO`, `PIP_CERT`, `CARGO_HTTP_CAINFO`, `AWS_CA_BUNDLE` and `DENO_CERT`, each set to the bundle's path. Trama's values overwrite the same variables inherited from the editor's environment. With the mode off, or with no bundle, Trama sets none of them and the processes receive what the editor's environment gives.
- Processes: the terminals of the jobs (design, scan, import, Run, Resolve Drifts, Unify Drifts) and of Ask more, the omp Chat conversations, General included, the terminal that installs omp, the login terminals, the logout, `omp models --json`, `omp usage --json`, the version check, the update check and the update of omp. The commands the agent runs inherit them from omp. An omp that the developer starts by hand receives nothing from Trama.
- A process receives the variables only when it starts: a change of the mode or a new export counts for the processes started afterwards; terminals and conversations already open are not closed, restarted or told.
- Export failure while a bundle exists: the processes keep receiving the earlier bundle; the setting's state shows the failure and the time of the bundle in use; an automatic export (at start) also shows the editor warning of `ui#developer.REFRESH_SYSTEM_CERTIFICATES` once per failed export. Export failure without a bundle: the variables are not set and the state and the warning say why.
- After every export that ends, successful or not, and after every change of the mode, Trama checks omp again in silence, with the providers' state and the model suggestions, in the Settings tab and in the wizard's `omp` step when they are open, as after a change of the Cursor API key (`rules#developer.SET_CURSOR_API_KEY`).
- Java's tools and every program that reads a truststore instead of a PEM bundle are not covered.
- Certificate errors: a reason that Trama shows for a failure of omp is a certificate error when the text it comes from (omp's error output, the message of an ACP error, the output of a failed command) contains any of: `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`, `UNABLE_TO_GET_ISSUER_CERT`, `UNABLE_TO_VERIFY_LEAF_SIGNATURE`, `SELF_SIGNED_CERT_IN_CHAIN`, `DEPTH_ZERO_SELF_SIGNED_CERT`, `CERT_HAS_EXPIRED`, `CERT_UNTRUSTED`, `ERR_TLS_CERT_ALTNAME_INVALID`, or, ignoring case, `unable to get local issuer certificate`, `self signed certificate in certificate chain`, `self-signed certificate in certificate chain`, `certificate verify failed`, `SSL certificate problem`, `curl: (60)`.
- Where a certificate error replaces the reason, with the text of `ui#developer.REFRESH_SYSTEM_CERTIFICATES`, whatever the mode: the reason of the omp state in the Settings tab and in the wizard's `omp` step, the reason of the models list, the reason of a failed update of omp, the error of the usage line of omp Chat, the reason of a failed logout, the notice of a conversation that does not start, of an omp that exits and of a prompt that omp refuses, and the reason shown inside General. Where the place already shows omp's own lines (behind `Show details`), they stay there, unchanged. A reason that is not a certificate error is shown as before.
- Output written in a terminal is never read or changed.
