# Requirements: Tecnologia e vincoli, Team

Use when building Team: Manager mode in core, CLI and host, the people store in globalState, the Team view's webview code and its messages.

## team

- Core: `src/core/manager-mode.ts`, with `bun:test` tests, holds the pure logic: reading and writing `.trama/manager/mode.json` (`data#manager-mode`) and parsing the origin address into `<owner>/<repo>` (`rules#manager-mode`). The git call (`remote get-url origin`) uses the `git()` helper of `src/core/git.ts`: `spawnSync` with fixed arguments, no shell, `GIT_TERMINAL_PROMPT=0` and its timeout. Core does not depend on Bun.
- Core: `src/core/people.ts`, with tests, holds the validation of a person and of the stored value (`data#person`, `rules#person`) as zod 4 schemas and pure functions (next absence, initials, dropping old absences, adding and removing a repository). It does not touch `globalState`.
- CLI: `trama team show` (`cli#team`) lives in `src/cli/commands/team.ts` and talks to the editor through the client of `trama question new`, with a new request kind `team` carrying the window's secret and the project root; `trama project show`, `project new` and `project edit` get the Manager mode fields through `src/core/manager-mode.ts`.
- Host: `extension/src/host/team/people.ts` keeps the people behind a small injected store `{ get, update }` over `context.globalState`, as `trama.ompChatSendMode` does, so tests pass a map; it is the only module that reads or writes the key `trama.team`. `extension/src/host/manager-mode.ts` reads and writes Manager mode through the same in-process code of `trama project edit`.
- Host: the editor's socket (`tech#question-round`) answers the `team` request with the members of the team of the project it names, only after checking the secret and only for a terminal or conversation of this window; it answers with the errors of `cli#team` when Team is not available.
- Messages, webview → host, validated by `parseToHost` (`extension/src/host/messages.ts`): `setManagerMode { on: boolean }`; `savePerson { person }` (`id` absent for a new person); `addToTeam { id }`; `removeFromTeam { id }`; `undoRemoveFromTeam { id }`; `deletePerson { id }`, for which the host opens the confirmation dialog (`ui#person`). The host validates every person again with `src/core/people.ts` and refuses an invalid one without writing, answering with the messages of each field.
- Messages, host → webview: `managerMode { available, recorded, repository: string | null, reason: string | null }` at the `ready` of the webview, whenever Settings or Team becomes visible and after every write; `team { members: PersonView[], others: PersonView[], unreadable: number, error: string | null }` at the `ready`, whenever Team becomes visible and after every write. `PersonView` has the stored fields plus `initials` and `nextAbsence`.
- The side menu gets `manager: boolean` (Team available) in `menuState`, like `merge`, and shows the `Team` entry only with it.
- Webview: the view `team` lives in `extension/src/webview/team/`, mounted like `extension/src/webview/history/index.tsx`, with the People tab in its own component and the pure logic (ordering, initials, formatting of capacity and absences, narrow layout breakpoint) in `logic.ts`, tested without DOM. Components are the shadcn/ui ones already copied in `extension/src/webview/ui/` (`Tabs`, `Dialog`, `Popover`, `Command`, `Badge`, `Button`, `Checkbox`, `Select`, `Input`); a missing shadcn/ui component is copied there, never loaded from a CDN. The date fields are native `input type="date"` styled as the other inputs.
- Settings and wizard: the Manager Mode row is its own component in `extension/src/webview/settings/`, placed after the Solo mode row of the `Project` group, as the other rows that are not settings. No key in `contributes.configuration`: Manager mode is not a setting of the editor, is not in `SETTING_GROUPS` nor in `EXPLICIT_TITLES`, and `setSetting` does not accept it. The wizard keeps the choice in its state in every mode and sends it in `confirmSetup` as `manager`; the first setup passes it to `initializeProject` as `manager` of `trama project new`, the other modes call `project edit` with `manager` after saving the settings and before going on with the path, only when it differs from the project's value.
- `README.md`, `extension/README.md`, `docs/` and `CHANGELOG.md` describe Manager mode, the Team view and the People tab, and that the people stay in the editor and never in the repository; `docs/cli.md` describes `trama team show` and the Manager mode fields; `docs/uat.md` has the manual steps: turning Manager mode on and off, a project without GitHub origin, adding, editing, removing and deleting a person, the same person in two projects, the wizard in every mode.
