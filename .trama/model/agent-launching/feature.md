# Agent launching

How Trama gets the developer's coding agent to work. Trama never calls a model: it sends a one-line instruction that names a Trama skill (design, scan, implement or import) to the agent the developer uses, either in a terminal (the editor's own or a window of the system terminal) or in the editor's chat. After an ordinary Proposal is approved, a scan of what it changed is started the same way; se l'implementazione automatica è accesa e la scansione non trova Drift, lo stesso agente prosegue con i Task che ha archiviato.

Per essere veloce l'agente lavora in parallelo nella stessa cartella, senza worktree, quando ha dei sotto-agenti: il design esplora il Modello e il codice con più sotto-agenti insieme, la scansione dà una Machine a ciascun sotto-agente, e una corsa di implementazione realizza insieme fino a quattro Task che non riguardano la stessa cosa (vedi il Task). Un agente senza sotto-agenti fa lo stesso lavoro un passo alla volta.

Cursor è un editor di prima classe, come gli altri agenti: con il launcher «auto», che è la scelta predefinita, i pulsanti di Trama mandano l'istruzione alla chat integrata di Cursor e la chat la invia da sola, mentre in ogni altro editor lavorano nel terminale integrato. Chi preferisce il terminale può usare il Cursor CLI come qualunque altro comando dell'agente, anche in una finestra del terminale di sistema con il launcher «external-terminal». Trama segue la chat di Cursor con gli hook di Cursor (vedi l'Actor cursor-chat), così avvisi, Task presi e annunci si comportano come con il terminale.

Una richiesta di design si fa in due modi. Quick request chiede una riga in una casella e la manda subito, come sempre. Design… crea invece un file Markdown vuoto nel progetto e lo apre in una scheda dell'editor, dove il developer scrive una richiesta lunga e ben strutturata; chiudere la scheda, o premere il suo pulsante, la manda all'agente (vedi la Design request). La richiesta scritta resta un file del progetto finché la prima Proposal che ne nasce non è consegnata, e l'istruzione all'agente la nomina invece di contenerla, così resta di una riga.

L'interruttore multi-branch sta nel pannello, uno per copia di lavoro (vedi Multi-branch). Si accende solo se il comando dell'agente dei worktree è già configurato. Acceso, il lavoro che segue l'accettazione di una Proposal ordinaria non usa questo terminale né la chat: un terminale per worktree, nella cartella di quel worktree, esegue prima la scansione e poi i Task di quella Proposal. L'unione e il controllo finale sono del Worktree round.
