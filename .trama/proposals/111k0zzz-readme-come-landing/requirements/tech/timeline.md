# Timeline and signals

## issue/Published
- Core: `src/core/github.ts` gains a constant GraphQL query for the items of the linked Project (paginated, 100 at a time) with the fields of `rules#issue/Published`; still read-only, same runner, timeout per page.
- Core: `src/core/timeline.ts`, with `bun:test` tests, holds the pure logic: the state of an issue from what was read, the events between two reads, the sprints shown, working days, capacity, load, the four signals and the lanes and cells of the Timeline by person and by epic. It depends on no clock: today is a parameter.
- Host: the read's result for items joins the cache `trama.team.github` in `workspaceState` (`data#github-project`); the webview gets it in `teamGitHub` with the computed states and signals. The signal `Stale` uses the text fingerprints of the current snapshot, so it follows a change of the Model at the next picture without reading GitHub.
- Briefing: `trama comparison new` adds, for the Machine it opens, a section `## Published issues` that lists each published issue not `Not planned` whose references fall in it, with number, title and state as last read (or as published when nothing was read), and the instruction of `rules#issue/Published` on Drifts; `trama-compare` and `trama-scan` follow it. The scan of a closed issue uses the existing scan of a list of references of `trama-scan`, with `trama comparison new` and `refs`.
- Launches: Comment update and the scan of a closed issue are new `ResolvedAction` kinds of `extension/src/host/prompts.ts` with the terminal names `Update #<n>` and `Scan #<n>`; `roleOf` gives `Scan #<n>` the scan role and `Update #<n>` the execution role. Neither changes the memory of the last scan of the System. Messages webview → host `askIssueUpdate { issue }` and `scanIssue { issue }`, validated by `parseToHost`.
- CLI: `trama issue show <id>` of a published issue adds `## Changed since publishing` with the earlier and current text of each changed reference (`--json`: `changed`); `trama issue edit <id>` accepts `{ updated: true }`, which records `updated` (instant) and the current `texts`. The earlier text is the Model's text at the commit or working copy of publication when git has it, otherwise only the reference is named.
- Webview: the Timeline tab lives in `extension/src/webview/team/timeline.tsx`, laid out with CSS grid and Tailwind only (no chart library, no `ResizeObserver`); its pure layout is in `logic.ts`. The Issues tab adds states, signals and actions to its rows.
- `docs/` and `CHANGELOG.md` describe the Timeline, the signals and the two actions; `docs/uat.md` the manual steps: an issue moving through In progress, In review and Closed on GitHub, a sprint ending with open work, an overloaded person, an absence, a Model change making an issue stale and its Comment update, the Scan of a closed issue filing a Drift that leans towards fixing the code.
