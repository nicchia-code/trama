# Regole di avvio dell'agente

## agent-terminal
- The instruction sent to the agent is one line naming a skill: quick design request → "Use the trama-design skill. <the developer's request>" (the request is asked for in an input box when the button did not carry one; an empty request sends nothing); written design request → "Use the trama-design skill on the design request in `.trama/requests/<id>.md`. Bind the first Proposal you open to it with `--request <id>`." (see the Design request); scan of the whole System → "Use the trama-scan skill on the whole System."; scan of Features → "Use the trama-scan skill on the Feature `a`." or "…on the Features `a`, `b`."; implement → "Use the trama-implement skill on Task <id>."; implement all → "Use the trama-implement skill on every Task in the \"todo\" column. Take them from `trama task next --batch`, one group at a time, until it says there is none."; implement a design → "Use the trama-implement skill on every Task of Proposal <id> that is in the \"todo\" column. Take them from `trama task next --batch --proposal <id>`, one group at a time, until it says there is none."; import → "Use the trama-import skill on this repository." There is no instruction naming a Fix skill, and no button or command to ask for one.
- Reworking the stale Proposal of a Drift sends one line naming the design skill: "Use the trama-design skill, without asking questions. Proposal <p>, attached to Drift <d>, is stale: write a new Proposal that makes the same change on the current Model and Requirements, hand it over, and attach it to the Drift in place of the stale one." It is refused unless the Drift is open and its attached Proposal is open and stale.
- Il nome del terminale dell'agente dipende dall'istruzione: implement → il numero breve del Task (per esempio `T3`); implement a design → il numero breve della Proposal (per esempio `P2`); quick design request, written design request e rifacimento di una Proposal obsoleta → `Design`; scan del System, scan di Feature e scansione automatica dopo un'approvazione → `Scan`; implement all → `All tasks`; import → `Import`. Il numero breve è quello della copia di lavoro aperta al momento dell'invio, e il nome non cambia più finché il terminale resta aperto, anche se il numero cambia. Il nome non dipende dalla lingua scelta. Un terminale libero, integrato o finestra esterna, si riusa solo per un'istruzione che ha esattamente lo stesso nome; altrimenti se ne apre uno nuovo e il vecchio resta aperto, non più seguito.
- A scan of a Feature that does not exist in the Model is refused; an implement request is refused unless the Task exists, and an implement-a-design request unless the Proposal exists.
- Automatic scanning after an approval sends "Use the trama-scan skill on what Proposal <id> changed: its scan scope is in `trama proposal show <id>`. Link every Task you file to it with --proposal <id>." It needs `trama.autoScan` on, Hold scan off (see `scan-hold`), a configured agent command (or the chat launcher) and at least one affected Feature. L'istruzione non chiede mai di proseguire con l'implementazione: i Task archiviati restano in To do finché il developer non li avvia (per esempio con Run this design). A scan the developer starts by hand names no Proposal, so its Tasks belong to no design, it scans the Features or the System it names and it never goes on to implement.
- When a language is set, every instruction above ends, on the same line, with the sentence "Write everything you generate in <language>, except code, which always stays in English." where <language> is the setting's text, trimmed, as typed. It applies to every instruction sent to the agent: design, scan, import, implement, implement all, the rework of a stale Proposal and the automatic scan. Without a language (empty or only spaces) the instruction is exactly as before.
- In the chosen language go the prose the agent produces for Trama: the bodies, descriptions and introductions of Proposals, Model files, Requirements, Tasks and Drifts, the text of questions and their options, and the agent's replies in the conversation. Always English, whatever the language: code and its comments, commit messages and the project's own documentation; the names and titles of Model elements, Requirements, Proposals, Tasks and Drifts; IDs, Event names, the section titles Trama requires (for example "General", "What happens", "What should happen", "Where in the code") and the `(initial)` and `(final)` markers.
- Changing the language changes nothing already written. When the agent edits a file written in another language it keeps the existing text and writes only the new or rewritten text in the chosen language; it does not translate the whole file.
- Nella chat di Cursor l'istruzione ha una seconda riga, dopo la frase della lingua se c'è: `The trama command may not be on your PATH. Before anything else run: export PATH="<cartella del programma trama incluso nell'estensione>:$PATH"`. Serve perché Cursor avvia i comandi dell'agente senza il PATH dell'estensione. Senza un programma incluso per questa piattaforma la riga non c'è. Con il terminale e con la chat di altri editor l'istruzione resta di una riga.
- La scansione automatica dopo l'approvazione, in Cursor, parte da sola solo se la consegna ha usato `composer.createNew`. Se ha dovuto ripiegare sul deeplink o sugli appunti, non invia nulla: mostra l'avviso «Trama: Proposal <id> was approved. Scan the Features it affects?» con il pulsante «Scan now»; il pulsante invia la stessa istruzione di scansione con la stessa catena di consegna, e chiudere l'avviso non fa nulla.
- Ogni passo della consegna alla chat di Cursor che fallisce o non esiste passa al successivo senza avvisare il developer; solo il passaggio agli appunti lo avvisa. Non si prova mai due volte lo stesso passo per lo stesso prompt, per non creare due chat con lo stesso testo.
- Una conversazione è di Trama se un prompt inviato comincia con «Use the trama-» o «/trama-», che il prompt l'abbia scritto Trama con un pulsante o il developer a mano. Un prompt che nomina una skill di Trama ma in una conversazione già di Trama è un normale `PROMPT_SUBMITTED`. Le conversazioni del progetto che non lo sono non producono rilasci di Task né ritiro di annunci.
- Con il launcher «external-terminal» l'istruzione è la stessa degli altri terminali; cambia solo dove gira. La scansione automatica dopo un'approvazione apre la finestra esterna da sola, alle stesse condizioni del terminale integrato.
- Una finestra esterna si riusa solo se la corsa precedente di quel terminale è finita (il marcatore è arrivato), il terminale è stato rilevato da Trama tra Terminal.app, kitty e WezTerm, `trama.externalTerminalCommand` è vuota e lo scripting del terminale riesce. Quando una di queste condizioni manca in partenza, si apre una finestra nuova senza avvisi. Quando il riuso è stato tentato e lo scripting fallisce (per esempio la finestra è stata chiusa a mano), si apre una finestra nuova e il developer è avvisato (vedi `ui`).
- Con una corsa in corso, ogni nuova istruzione apre una finestra nuova e la vecchia non è più seguita per la fine del comando dell'agente: il suo marcatore, se arriva, non cambia lo stato dell'agente, ma rilascia i Task che quella finestra ha preso, che tornano in To do, e ritira i suoi annunci, come la fine del comando di un terminale integrato vecchio. Le finestre esterne non si chiudono mai da sole né per mano di Trama.
- Se la finestra esterna non si può aprire (piattaforma o cartella remota non supportata, nessun terminale trovato, il programma del terminale non parte, la riga di comando non si può scrivere o lo scripting di una finestra nuova fallisce) non parte nulla: l'istruzione va negli appunti e il developer è avvisato del motivo (vedi `ui`). Non si ripiega sul terminale integrato, nessun annuncio è creato e una richiesta di design scritta non è segnata come inviata.

## design-request
- Il titolo di una richiesta scritta è il testo del primo titolo `#` di primo livello fuori dai blocchi di codice, senza i `#` e gli spazi attorno; se non c'è, la prima riga non vuota, senza spazi attorno. Il titolo serve solo al fantasma dei launcher del terminale, integrato ed esterno: il nome del file non dipende dal testo.
- Un testo è vuoto quando, tolti gli spazi e gli a capo, non resta nulla. Send to agent su un testo vuoto non invia, non chiude la scheda e mostra l'avviso «Trama: write the design request before sending it.». Chiudere la scheda di una richiesta mai inviata con il testo vuoto su disco cancella il file senza avvisi.
- Chiudendo la scheda, il testo inviato è quello su disco in quel momento: se l'editor ha chiesto di salvare e il developer ha rifiutato, vale l'ultima versione salvata, e se questa è vuota la richiesta è cancellata.
- Il testo è salvato esattamente come il developer l'ha scritto: Trama non aggiunge front matter, titoli o sezioni e non lo riformatta.
- Una richiesta è inviata al più una volta: solo il primo invio che parte davvero la segna come inviata. Un invio annullato prima che l'istruzione parta (per esempio annullando la richiesta del comando dell'agente) non la segna, e la richiesta resta in Writing. Con il launcher del terminale l'invio fa un annuncio, come ogni richiesta di design.
- Solo la prima Proposal aperta dall'agente per una richiesta è legata a essa. Le Proposal che la seguono con `--requires` non sono legate. Legare una Proposal a una richiesta che non esiste non impedisce di crearla: il risultato dice solo che la richiesta non è stata trovata, e la Proposal non è legata a nulla.
- La consegna riuscita di una Proposal legata cancella il file della richiesta, se esiste ancora. Una consegna rifiutata non cancella nulla. Se il file è già sparito la consegna non fallisce. Se più Proposal sono legate alla stessa richiesta, la prima consegna la consuma; le altre consegnano normalmente.
- Chiudere la scheda dopo la cancellazione: solo se il documento non ha modifiche non salvate; con modifiche non salvate la scheda resta, e quello che il developer ne fa è affare dell'editor.
- La skill `trama-design`, ricevuta una richiesta scritta, legge tutto il file prima di esplorare il Model. Il contenuto è il punto di partenza dell'intervista, che resta completa: ogni decisione della richiesta è comunque presentata come domanda con le sue opzioni, mettendo come raccomandazione quella che la richiesta indica. Se il file non esiste più, la skill lo dice al developer e si ferma, senza aprire nessuna Proposal.
