# Requirements: Dati, Dati di Task, Drift e Proposal

Generated by Trama from `.trama/requirements/data/work.md`. Do not edit this file: change the Requirements through a Trama Proposal (or ask the developer).

These are the developer's Requirements for how the System is built. Follow them when you write code. The Model (`.trama/model/`) says what the System does; when a Requirement and the Model disagree, stop and tell the developer.
A section titled with a Model reference (such as `order/Paid`) applies to that element and to everything inside it.

## task

- One file `tasks/<id>-<slug>.md`. Front matter: `column` (`todo`, `doing` or `done`; default `todo`), `technical` (true or false; default false), `refs` (list of element or Requirement references), `drift` (ID of the Drift it resolves, or none), `proposal` (ID of the Proposal, the design, the Task comes from, or none; absent in Tasks written before this field existed), `agent` (who has taken the Task while the agent has taken it: the ID of the agent terminal that took it, or `cursor` when the agent of Cursor's chat took it, or `true` when it was taken without a known terminal or chat; `false` otherwise; default false, so Tasks written before this field existed are free; a Task marked `true` is released by the end of any agent terminal or of the chat), `created` (istante di creazione in UTC, ISO 8601; assente nei Task numerati scritti prima di questo campo), `finished` (istante in UTC, ISO 8601, in cui il Task è arrivato in Done da un'altra colonna; uno spostamento da Done a Done non lo cambia, uno spostamento fuori da Done lo toglie; assente nei Task arrivati in Done prima di questo campo). The H1 is the title; the body says what must be true when done, in domain words.
- The Board's To decide column is not a Task column; it shows open Proposals (never drafts) and open Drifts. Le Proposal allegate a un Drift aperto (nominate nel campo `proposal` di un Drift con `status: open`) non vi compaiono a sé: lo si calcola dai Drift, senza un campo nuovo nella Proposal.

## drift

- One file `drifts/<id>-<slug>.md`. Front matter: `status` (`open` or `resolved`; default `open`), `resolution` (`fix-code`, `proposal` or `dismissed`; none while open), `refs` (list of element or Requirement references), `proposal` (ID of the attached Proposal, or none), `task` (ID of the Task created when resolved as fix-code, or none), `origin` (ID of the Task the agent was implementing when it filed the Drift, or none; absent in Drifts written before this field existed, which have no origin), `option` (number, counted from 1 in the order of the Fix options section, of the option the developer chose when resolving as fix-code; none otherwise and in Drifts without options), `note` (the developer's note given with that choice, or none), `resolvedBy` (identità della Proposal di risoluzione che ha risolto il Drift, o nessuna; assente nei Drift risolti in altro modo e in quelli scritti prima che esistesse) e `created` (istante di creazione in UTC, ISO 8601; assente nei Drift numerati scritti prima di questo campo). The H1 is the title. The body is Markdown with three required sections, in this order: `## What happens`, what the code does today, `## What should happen`, what the Model or the Requirement says, and `## Fix options`; then one optional section, `## Where in the code`, with the places where the difference was seen. `dismissed` vuol dire che il developer ha tenuto il codice senza cambiare il Modello: nessuna Proposal era allegata, oppure lo ha deciso una risoluzione. Un Drift risolto da una risoluzione ha `resolution`, `option`, `note` e `task` come se il developer l'avesse risolto dalla riga di comando con la stessa decisione.
- Che un Drift aperto stia in una Proposal di risoluzione da decidere non è scritto nel Drift: si calcola dalle Proposal ancora in scrittura o aperte.
- `## Fix options` holds from two to five options, each a `###` heading with the option's title followed by its text, a Markdown description of that way to fix the code and what the developer gets from it. The first option is the agent's recommendation. Titles are unique within the Drift. The options are not part of the Model or of what a Requirement says: they only describe ways to reach what should happen.
- A Drift is not part of the Model, so the optional `## Where in the code` section may name files and code elements. The required sections are written at the level of behaviour (see the rules of the Drift) and name no code locations. Drifts written before the sections existed may name code locations in What happens; they stay as they are.
- Drifts written before the Fix options section existed have none: if they are Open the developer fixes their code without choosing an option; `option` and `note` stay empty.
- Resolved Drifts written before the two sections existed keep their free body; they are shown as one block.

## announcement

- One file `announcements/<id>.md` under `.trama/`. The ID is six random lowercase letters and digits, not a sequence, because announcements do not outlive their card. Front matter: `kind` (`proposal`, `task` or `drift`), `source` (`agent` when the agent announced it, `request` when Trama announced a design request o Resolve Drifts), `proposal` (ID of the Draft bound to it, or none until the Draft exists), `terminal` (ID of the agent terminal it belongs to, or none; absent in announcements written before this field existed, which belong to no terminal) and `touched` (when the agent last did something about it, as a date and time). The H1 is the title shown on the ghost.
- Il campo `chat` di un annuncio vale `cursor` quando l'annuncio è fatto dall'agente della chat di Cursor (`CURSOR_AGENT=1` senza `TRAMA_TERMINAL`); è assente altrimenti e negli annunci scritti prima che esistesse. Un annuncio con `chat` non ha `terminal`.
- `kind` vale anche `check` per un controllo. Un controllo ha nel front matter anche `phase` (`verifying` o `scanning`), assente negli altri annunci, e non ha mai `proposal`; il suo `source` è sempre `agent`. Ogni dichiarazione dell'agente sul controllo (annuncio e cambio di fase) aggiorna `touched`.
- Un annuncio di tipo `drift` può avere `proposal`: la Draft che quel Drift porterà allegata. Il campo `drift` che gli annunci di un rifacimento avevano non è più scritto; in un annuncio rimasto da prima è ignorato.
- The folder holds its own `.gitignore` that ignores everything in it, so announcements are never versioned; Trama writes it together with the first announcement. No other part of `.trama/` is ignored, except `requests/` (see the Design request), `scan-hold/` (see Scan hold) and `short-numbers/` (see the short numbers in General).
- Whether a question round is open is the only thing about question rounds that the Board learns, held in memory; nothing about the questions or the answers reaches the Board or the files.
- Notices about withdrawn announcements are held in memory by the panel and are not written anywhere.

## proposal

- One folder `proposals/<id>-<slug>/` with `proposal.md` and, beside it, a `model/` and a `requirements/` folder holding the full new version of every touched file at the same relative path it has under `.trama/`. Front matter of `proposal.md`: `status` (`draft`, `open`, `approved`, `rejected` or `discarded`; default `open`, so Proposals written before `draft` existed are already handed over; a new Proposal is written with `draft`), `kind` (`change`, `import` o `resolution`; default `change`), `requires` (list of Proposal IDs), `base` (touched path → SHA-256 of the file when the Proposal first touched it, or `new` for a file that did not exist), `delete` (list of paths the Proposal removes), `request` (ID della richiesta di design scritta a cui la Proposal è legata, o nessuno; resta anche dopo che la richiesta è stata consumata, ed è assente nelle Proposal scritte prima che esistesse), `created` (istante di creazione in UTC, ISO 8601; assente nelle Proposal numerate scritte prima di questo campo).
- Una Proposal con `kind: resolution` ha nel front matter `drifts`, la lista dei Drift che risolve, nell'ordine in cui l'agente li registra: ogni voce ha `drift` (identità del Drift), `decision` (`proposal` per adeguare il Modello al codice, `dismissed` per chiudere senza cambiare nulla, `fix-code` per correggere il codice; gli stessi valori di `resolution` del Drift), `option` (numero dell'opzione scelta, contato da 1, solo per `fix-code` e solo se il Drift ha opzioni) e `note` (testo libero, solo per `fix-code`, assente se vuoto). Un Drift compare una sola volta nella lista. Le altre Proposal non hanno `drifts`. La lista resta dopo l'approvazione come storia.
- The H1 of `proposal.md` is the title; the prose says why. Rejection appends a `## Feedback` section with the developer's text when it has any. Staleness is computed, never stored.
- Il campo `scanScope` di `proposal.md` è la lista dell'ambito di scansione, ogni voce con `ref` (un riferimento nella forma di `--ref`) e `reason` (`changed`, `removed, its container` o `leads into a change`). Lo scrive Trama quando la Proposal è approvata, solo per una Proposal ordinaria; non cambia più dopo. È assente nelle Proposal import e nelle risoluzioni, in quelle non ancora approvate e in quelle approvate prima che il campo esistesse.
