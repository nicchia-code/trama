# Solo merge

## solo-merge
- Core: `src/core/solo-merge.ts`, with `bun:test` tests on real temporary git repositories, holds availability (`rules#solo-merge`), the list and order of branches, the up-to-date check, the merge, the abort, reading and writing the remembered merge (`data#solo-merge`) and the end of a remembered merge (committed or abandoned). Every git call goes through `src/core/git.ts` (`tech#solo-switch`), with fixed arguments and no shell; `git fetch` has a time limit of 120 s, the others the helper's limit. Trama never passes a branch name through a shell and refuses names that start with `-`.
- Host: `extension/src/host/solo-merge.ts` runs Merge for the window: the progress notification, the `QuickPick`, the confirmations and the messages of `ui#solo-merge`; it opens the merge editor with the editor's command `git.openMergeEditor` on the first file with conflicts, falling back to opening the file when that command is missing. It watches the git directory (`git rev-parse --git-dir`, and `--git-common-dir` for the refs, read once per window and again when git's configuration changes) with a `FileSystemWatcher` on `HEAD`, `MERGE_HEAD`, `index` and the refs, and checks the remembered merge at activation and at every execution check (`tech#agent-launching`). There is no watcher on the files of the working copy (`**/*`) and no listener of `onDidSaveTextDocument`: a change or save of a file of the project never works out the Merge state.
- The Merge state of `menuState` is worked out only while the side menu is visible (`quality#menu-laterale`): when it becomes visible and, while it is visible, after the 150 ms pause of the git directory's watcher. Every git call of that state, of the menu and of Merge in the editor host runs asynchronously (`quality#General`): `src/core/git.ts` gives an asynchronous form (`execFile` without shell, the same fixed arguments, `GIT_TERMINAL_PROMPT=0` and time limit) that the host uses, and keeps the synchronous one only for the command line. A state still being worked out leaves the menu with the last one; two runs never overlap, and a run asked meanwhile starts once at the end.
- Side menu (`tech#menu-laterale`): `menuState` carries `merge`, absent with Solo mode off, as `{ available: boolean, reason?: "inProgress" | "detached" | "changes" | "agent", trackedTrama: boolean, open?: { branch: string, conflict: boolean } }`. The menu sends `merge`, `openMergeEditor`, `reconcileMerge` and `abortMerge`, validated like the other messages.
- Launches: `AgentAction` (`extension/src/protocol.ts`) gains `{ kind: "mergeScan", base: string, incoming: string }` and `{ kind: "reconcileMerge", branch: string }`, neither of which the panel can send. `mergeScan` goes through the same `send` as the scan of `Scan System`, with `rememberDeliveredScan`, the check title `Scanning System` and the terminal name `Scan`, but without `confirmScanSystem`. `reconcileMerge` has the terminal name `Merge` and files no cards.
- Instructions (`rules#agent-terminal`): scan after a merge → "Use the trama-scan skill on the whole System. A merge brought in `<base>...<incoming>`: mark `merge` on every Drift whose Where in the code lies in a file `git diff --name-only <base>...<incoming>` lists."; reconcile → "Use the trama-merge skill to resolve the conflicts of the merge of `<branch>` in progress.". Both take the usual sentences of every instruction.
- Skill `trama-merge`, shipped with the others in `.agents/skills` (or `trama.skillsDir`) and installed and updated like them: it resolves the conflicts of the merge in progress as `rules#solo-merge` says, asks with `trama question new` as the other skills do, ends with one line telling the developer to review the staged files and commit, and has the `## Language` section of the other skills.
- `trama-scan` and `trama-compare`: with a merge range in the instruction, the main agent passes the range to every sub-agent that compares a Machine, and each Drift whose Where in the code lies in a file of the range gets `merge: true` in `trama drift new` or in `trama comparison move … delivered`. `trama-resolve-drifts`: for a Drift with `merge`, the question always has the option of the behaviour the code already has and recommends it (`rules#drift-resolution`, `rules#question-round`).
- `docs/` and `CHANGELOG.md` describe Merge, its conditions, the conflicts, the scan after a merge and the Drifts from a merge; `docs/uat.md` has the manual steps: a clean merge, a fast-forward, already up to date, a failed fetch, a conflict resolved in the editor, a conflict reconciled by the agent, an abort from the menu, an abort outside Trama, a window reloaded during a merge.
