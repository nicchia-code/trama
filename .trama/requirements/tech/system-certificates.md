# System certificates

## developer.REFRESH_SYSTEM_CERTIFICATES
- Manifest: `trama.systemCertificates` is `"type": "boolean"`, `"default": false`, `scope: "application"`, with the `markdownDescription` of `ui#developer.REFRESH_SYSTEM_CERTIFICATES`, last key of the `omp` group of `SETTING_GROUPS` (`extension/src/host/settings-schema.ts`). Only the user value is read (`inspect(key).globalValue === true`), with a function `configuredSystemCertificates` next to the other readers of `extension/src/host/agent.ts`; a value that is not a boolean counts as off, so a cloned repository cannot turn it on.
- One host module, `extension/src/host/system-certificates.ts`, owns the export, the bundle path, the state and the variables; the names of the variables and the paths live only there. It keeps the state in memory: `exporting`, the `count` and `exportedAt` of the bundle on disk, and the `error` of the last failed export of this window.
- Export, never through a shell, with fixed arguments and a 30 s timeout:
  - macOS: `execFile("/usr/bin/security", ["find-certificate", "-a", "-p", "/Library/Keychains/System.keychain", "/System/Library/Keychains/SystemRootCertificates.keychain"])`;
  - Windows: `execFile(<SystemRoot>\System32\WindowsPowerShell\v1.0\powershell.exe, ["-NoProfile", "-NonInteractive", "-Command", <fixed script>])`, the script writing every certificate of `Cert:\LocalMachine\Root` as PEM (`[Convert]::ToBase64String($_.RawData, 'InsertLineBreaks')` between the `BEGIN`/`END CERTIFICATE` lines); the script is a constant of the module;
  - Linux: `fs.readFile` of the first readable file of the list in `rules#developer.REFRESH_SYSTEM_CERTIFICATES`.
- Building the bundle is a pure function tested with `bun:test`: it takes the source text and `tls.rootCertificates`, splits the PEM blocks, keeps a block only when `new crypto.X509Certificate(block)` succeeds and `ca` is true, drops duplicates by `fingerprint256`, and returns the PEM text and the count; zero certificate authorities from the source is the failure `no certificate authority found`.
- Bundle path: macOS `~/Library/Caches/Trama/system-certificates.pem`, Windows `%LOCALAPPDATA%\Trama\system-certificates.pem`, Linux `$XDG_CACHE_HOME/trama/system-certificates.pem` (`~/.cache` when unset). The folder is created when missing; the file is written to `<path>.<pid>.tmp` and renamed over the bundle, so the rename is the only change other processes see. `exportedAt` is the file's `mtime`; `count` is read back from the file at activation.
- `systemCertificatesEnv(on: boolean): Record<string, string>` is synchronous: with `on` and a bundle on disk it gives the nine variables of `rules#developer.REFRESH_SYSTEM_CERTIFICATES` set to the bundle's path, otherwise `{}`. It is merged after the inherited environment and after `cursorKeyEnv`, so it wins, in every place listed by `tech#developer.SET_CURSOR_API_KEY` and also in `installOmp` (`extension/src/host/agent.ts`), which today passes no environment. Callers pass `configuredSystemCertificates()`, except the processes the wizard starts.
- Wizard: `agentCheckWanted`, `installOmp` and `ompLogin` carry in addition `systemCertificates?: boolean`, the step's value, validated by `parseToHost` (`extension/src/host/messages.ts`) as a boolean when present; without it the saved setting counts. The host uses it for that check (with its update), that installer terminal and that login terminal only. Checking the box in the step sends `systemCertificatesExport` (no data) when no bundle exists or the state is older than 24 hours, then a new `agentCheckWanted` when the export ends; unchecking it sends `agentCheckWanted` at once.
- Messages: host → webview `systemCertificates { exporting: boolean, count?: number, exportedAt?: string, error?: string }` (ISO time), sent at `ready`, when the Settings view becomes visible and at every change of the module's state; webview → host `refreshSystemCertificates` and `systemCertificatesExport`, without data, which start an export only when none is running and the setting (or, from the wizard, the step's value) is on. The component of the state line lives next to the omp state box in the module shared by the Settings tab and the wizard (`tech#setup-wizard`).
- Triggers: activation (when on, and the bundle is missing or its `mtime` is older than 24 h), `onDidChangeConfiguration` with `affectsConfiguration("trama.systemCertificates")` turning it on, the message and the command. After the export, and after the setting is turned off, the host runs `refreshOmp(true)` and the wizard check, as after `saveTypedCursorKey`. Exports never block a launch: a launch during an export uses the bundle already on disk, or none.
- Command: `trama.refreshSystemCertificates` in `contributes.commands` with the title of `ui#developer.REFRESH_SYSTEM_CERTIFICATES`, category `Trama`, and in `menus.commandPalette` with `"when": "config.trama.systemCertificates"`.
- Certificate errors: a pure function `isCertificateError(text: string): boolean` in a module that host and webview both import (next to `extension/src/protocol.ts`), with the markers of `rules#developer.REFRESH_SYSTEM_CERTIFICATES`, and a function that gives the text of `ui#developer.REFRESH_SYSTEM_CERTIFICATES` for the mode. Where a reason is built: `ompModels` (`extension/src/host/model-lists.ts`) also keeps the error output of a failed run, only to test it; the update and its check (`extension/src/host/omp-update.ts`), the logout, the usage runner (`extension/src/host/omp-chat/usage.ts`), and the reasons of `START_FAILED`, `EXITED`, `SESSION_NOT_RESUMED`, the failed start of a job and a refused prompt (`tech#omp-acp`) test the error output and the error message they already keep. The test and the text are computed in the host; the webview receives the reason already written, as today.
- Tests with `bun:test`: the bundle builder (duplicates, non-CA certificates, unreadable blocks, an empty source, the public roots added); the path per platform; the atomic write with a failing rename leaving the earlier bundle; `systemCertificatesEnv` on, off and without a bundle, and its precedence over inherited variables and next to `CURSOR_ACCESS_TOKEN`; the fake terminal of `test/host-agent-terminals.test.ts` with the variables in the `env` of the job, login and installer terminals and never in the command line; `ompModels` and the omp Chat `spawn` with the variables; the 24 h rule at activation; `parseToHost` for the new messages and fields; `isCertificateError` on each marker and on reasons that are not certificate errors; the reason texts with the mode on and off.
- `CHANGELOG.md` describes System Certificates, the stores it reads, the variables it overwrites and that Java is not covered; `docs/uat.md` has the steps to try it behind `mitmproxy` with its authority trusted in the system store, with the mode off (certificate error text) and on (omp answers).
