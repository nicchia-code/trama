# Changelog

## Unreleased

## 0.0.3

- The Trama panel has a fourth tab, Settings, that lists every `trama.*` setting in groups (Agent, Models, Drift autopilot, Runs, Project) with its title and explanation, and the control that fits it. Changes are saved at once in your user settings, never in the workspace's; raising the Drift autopilot asks for confirmation first in a modal question. The tab shows a workspace value when it overrides a setting, and it follows a Trama setting changed from anywhere (the editor's settings, a settings file, the tab) at once. `trama.maxParallelAgents` is now an integer setting, a whole number of at least 1.
- The Settings tab no longer shows the technical key of a setting, neither on the page nor in its explanation; a failed save names the setting by its title, as `Trama: could not save Max Parallel Agents: <reason>.`.
- In the Settings tab each setting's explanation is no longer on the page: an «i» next to its title opens it in a bubble when hovered or focused, closed by leaving it, losing focus or Esc, and an enum's bubble lists every value with the chosen one marked `(current)`.
- A fix Task can be closed without changes when the code already does what its Drift says: `trama task move <id> done --unchanged <note>` moves it to Done with the note and its Drift to Dismissed in one step. Such a Task is marked `(no changes)` and carries a `no changes` badge with its note on the Board, and is not counted by the Scan button or scanned at the end of a run. The `trama-implement` skill checks the Drift's premise against the code before writing any code, and reports the Tasks closed without changes apart.
- Withdrawing the automatic-resolution delegation during a Run no longer marks the Tasks that had not started as failed: they stay in their column without a badge, and a Task already started finishes normally.
- In the automatic Run, a fix Task closed without changes is a success: it is not reported as failed, carries no `autopilot failed` badge, and its origin becomes runnable as after any Done fix Task; the `trama-implement` skill no longer reports it with `trama agent-event failed`.
- A window whose project changes while a question round is still open no longer shows that round over the other project's panel: the round waits out of sight, its answers kept, and comes back when the window is on its project again; the window's other rounds wait behind it, and no answer is lost or left orphaned.
- The editor title bar shows an Open Trama icon at the right of every editor group in a window with a folder open, also without a Trama project and also while the panel is the active tab; on an unsent design request it sits to the right of Send to agent. The `Open` command is now titled `Open Trama` in the palette.
- The `trama-scan`, `trama-implement` and `trama-import` skills follow the Drift rules: Fix options reach what should happen without changing the Model or the Requirements; a Drift without Fix options comes with a Proposal when no fix of the code respects both; they read the resolved Drifts on the same references before filing and name a recurring one with `--previous`. `trama-import` files a Drift for each difference between the documentation and the code, instead of a doubt; its doubts keep only the code that looks buggy where the documentation says nothing, and behaviour it could not determine.
- `drift new --previous <id>` records the resolved Drift a new one follows, making it recurring; a Drift whose origin Task fixes another Drift follows that one by itself. Recurring Drifts are left out of the Drift autopilot in every mode.
- `drift show` of a recurring Drift has a `Follows Drift <id> <title> (<resolution>)` line under its title; `drift list` and the textual `board` mark it `(recurring)`; the Snapshot and the JSON of these commands carry `previous`.
- The Board card, the resolution rows and the Diagram details of a recurring Drift show a `recurring` badge whose tooltip and accessible name say `Recurring: follows Drift <id> – <title>`.
- `drift list --ref <ref>` (repeatable) keeps only the Drifts that concern the same thing as one of the references, with the test that decides Task blocks; combined with `--all` it shows the resolved ones too. A reference that does not resolve is a usage error.
- `drift new` with no `--option` files a Drift without Fix options, which needs `--proposal` (its Draft fixes the Model or the Requirements); without it the filing is refused. One or more than five options are still refused.
- An approval no longer starts a scan of the Features it touched, from the panel, from the command line or through a Drift: the `trama.autoScan` setting and the «Scan now» notice are removed. A leftover `trama.autoScan` value is ignored and not rewritten; manual scans are unchanged.
- A Proposal's scan scope is computed from the Model and Requirements whenever it is needed (validation, hand-over, approval and `proposal show`) and is no longer saved at approval; the `## Scan scope` of an open Proposal is always current. Approved Proposals that saved one keep it as history.
- Registrations on one Proposal (`proposal edit`, `proposal delete`, `proposal resolve-drift`, and the Task files written inside a Proposal) run one after the other under a lock per Proposal, so sub-agents writing at the same time no longer lose each other's files or recorded bases. The lock is a file in `proposals/.locks/`, kept out of Git; a lock older than 30 seconds is taken as left by a dead process.

## 0.0.2

- Windows (win32-x64) is packaged and smoke-tested by the release workflow, and a manual run can release a single platform. Windows is untested: its test suite has known failures and nobody has tried the package by hand.
- On Windows, Copilot's hook file carries the PowerShell form `& "<trama.exe>" copilot-hook` in `windows` next to `command`, and Cursor's `hooks.json` uses `& "<trama.exe>" cursor-hook`. Update skills replaces Trama's entries in either form instead of adding new ones. The Cursor form has not been tried on Cursor.
- `trama validate` refuses Windows device names (`con`, `prn`, `aux`, `nul`, `com1` to `com9`, `lpt1` to `lpt9`) as Feature, Machine and Actor IDs and as Area and fragment names on every platform, so a project opens on Windows too. Names that only contain one of them stay valid.
- Proposal hashes and comparisons read the Model and Requirement files with LF line endings: a CRLF checkout (`core.autocrlf`) no longer makes a Proposal stale, and its shown changes, touched files and scan scope match a Linux checkout.

## 0.0.1

- First public release, under the GNU AGPL v3 (`AGPL-3.0-only`); the `.vsix` now ships the license text. Earlier tags and releases are gone, and versions restart from 0.0.1.
- The automatic Run no longer carries a fixed list of Task identities from its launch: before each group it reads the authorized Tasks from `trama drift autopilot --json`, so an origin Task whose fix Tasks became Done during the Run is picked up, and nothing outside the authorization is started.
- When the Drift autopilot leaves `disabled`, the window that coordinates the project imports the jobs the other editor windows still run, before it judges the barrier: a Run, scan or Resolve Drifts started in another window during `disabled` is no longer unknown to the coordinator that already held the role.
- The Drift autopilot grants no new automatic step while a live editor window does not answer the project coordinator's jobs request in time: one answering window is no longer enough. The status shows that reason, and the coordinator keeps its role meanwhile.
- With the Drift autopilot `disabled`, a window no longer shares its jobs or send reservations with the other editor windows of the project: another window's Run, scan or Resolve Drifts no longer makes Resolve Drifts or the Run buttons unavailable here, and a send no longer waits behind another window's send. Sharing starts when the autopilot is enabled.
- The Scan button's count restarts when the System scan's instruction is delivered (written to the terminal, sent to the chat, left ready in the chat or copied to the clipboard), not when its check finishes: a scan that fails, is interrupted or has its check withdrawn no longer leaves the count up, and the editor no longer tracks scan launches in memory.
- An agent terminal that went idle or whose command ended is no longer followed: a later idle signal, command end or close of that terminal no longer releases the Tasks the resumed agent took or withdraws its announcements.
- An agent terminal's instruction stays one line: the job ID is no longer written into it. The commands that take `--job` (`announce check`, `proposal new --automatic --resolution`, `drift autopilot`, `agent-event failed`) read the terminal's job from `TRAMA_JOB` when `--job` is absent; a chat job still gets its ID in the text.
- A Drift whose question was skipped in one editor window stays out of automatic resolution in every window: the skip, the later answer and a developer scan are forwarded to the project coordinator.
- An automatic resolution whose approval is refused now fails only the Drifts the refusal names (or whose decision no longer applies); the other Drifts stay open in the Proposal for the developer.
- Rejecting or discarding an automatic resolution no longer marks its undecided Drifts as failed; they stay open, unmarked, for the developer's own decision.
- Add coordinated Drift autopilot modes (`disabled`, `enabled`, `yolo`) with cross-window scan/Run barriers, host-only approval, job-scoped authorization and implementation Runs.
- Resolve Drifts pressed in a window that does not coordinate the project now asks the coordinator, over the local channel, to resume automatic resolution; until a coordinator resumes, that window says why the automatic part waits.
- Autopilot leaves out of automatic resolution a Drift whose Model elements no longer exist, so it stays for the developer instead of failing in the resolution agent.
- Resolve Drifts no longer clears failed automatic cases: a Drift whose automatic fix failed or was excluded gets manual questions on a click, even with full delegation.
- A refused automatic start (mode, barrier or Drift changed at the last moment) releases its reservation and records no failure; its Drifts or Tasks stay eligible for the next cycle.
- Track critical Drifts and failed check outcomes; expose automatic resolution status and critical markers in the CLI and Board.
- Autopilot: a failed or interrupted scan no longer suspends the delegation; it counts as finished.
- Autopilot status reports the last failed or interrupted scan as information; it changes no phase.
- A finished check's outcome reaches the editor over the local channel instead of a marker file, so the System scan memory and the autopilot no longer race for it.
- Add `trama.submitWhileRunning` (`disabled` by default): while a Trama run is in progress, the Run buttons are disabled and launches are refused with "A run is in progress"; `enabled` allows Runs during a run.
- Make the Board's Done column collapsible; it starts collapsed each time the panel opens.
