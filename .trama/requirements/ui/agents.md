# Interfaccia del lavoro dell'agente

## design-request
- Le richieste di design hanno due pulsanti, uno accanto all'altro, nella barra della Board: il Diagramma e la scheda Requirements non hanno pulsanti per progettare una modifica: «Quick request…» apre la casella di una riga di oggi, con titolo «Quick Design Request», e «Add Work Item…» apre il documento Markdown della richiesta scritta. Il tooltip di «Quick request…» è «Ask an agent to design a change in one line»; quello di «Add Work Item…» è «Write a work item in Markdown and send it to an agent». Lo stesso documento si apre anche con «+ Work Item» in fondo alla colonna Work Items della Board (vedi `panel/Board`), l'unico altro pulsante che lo apre.
- Il pulsante della scheda si chiama «Send to agent», con l'icona `send` del tema dell'editor, e compare solo sulle schede delle richieste mai inviate. Il suo tooltip è «Send to agent (closing the tab sends it too)».
- Il file nuovo è completamente vuoto: nessun testo segnaposto, nessun commento, nessun modello. La scheda mostra il nome del file, cioè data e ora; questo vale anche per la richiesta di setup di Start from Scratch.
- Testo fantasma, solo visivo e mai nel file, all'inizio della prima riga, grigio (il colore del testo disattivato del tema dell'editor), su una sola riga:
  - richiesta di design (Add Work Item… o + Work Item): «Describe the change to design: behaviour, edge cases, requirements. Close this tab or press Send to agent when you are done.»
  - richiesta di setup: «Describe the application to build: what it does and who it is for. Close this tab or press Send to agent when you are done.»
- Il testo fantasma si vede solo sulle schede delle richieste mai inviate e solo finché il documento non ha nessun carattere (nemmeno uno spazio o un a capo). Sparisce alla prima battuta e torna se il developer cancella tutto; non si vede mai su una richiesta inviata. È in inglese e non segue `trama.language`.
- Dopo l'invio non compare nessun messaggio di conferma oltre a quelli della consegna; la scheda è chiusa. Chiudere una richiesta vuota non mostra nessun messaggio.

## agent-terminal
- La descrizione di `trama.agent`, in inglese, elenca i valori: `chat` (the editor's chat: Copilot in VS Code, Cursor in Cursor; the default), `omp` (omp in the editor's integrated terminal) e `claude` (Claude Code in the editor's integrated terminal). Quella di `trama.terminalLocation`: `panel` (the terminal area; the default) e `editor` (a terminal tab beside the active editor); vale solo per `omp` e `claude`. Quella di `trama.autoExit`: close the agent's terminal as soon as the agent is idle or its command ends (default on); with it off, idle terminals stay open and every instruction still opens a new one.
- `trama.submitWhileRunning` è un interruttore, spento per impostazione predefinita. La sua descrizione, in inglese, è «Let a run start while another run started by Trama is in progress. Off (the default): Run, Run this design and Run Ready Tasks are unavailable while a run started by Trama is in progress. On: a run can start while another one is in progress.»
- Con `panel` Trama non mostra il terminale dell'agente quando lo apre: l'area dei terminali non si apre se è chiusa, il terminale visibile al suo interno resta quello che era, e cursore e tastiera restano nell'editor o nel pannello in cui erano. Il terminale compare nell'elenco dei terminali con il suo nome, da dove il developer lo apre a mano. Vale per ogni avvio dai pulsanti e dai comandi.
- Con `editor` la scheda del terminale si apre in un gruppo accanto a quello attivo, così il pannello Trama resta visibile; se la scheda precedente dell'agente è ancora aperta, una scheda nuova si apre nel gruppo in cui Trama aveva aperto quella, senza creare un altro gruppo. Quando Trama apre la scheda, la porta in primo piano nel suo gruppo ma non le dà il focus: il cursore e la tastiera restano nell'editor o nel pannello in cui erano. Il titolo della scheda è il nome del terminale: il numero breve del Task o l'identità permanente della Proposal (per esempio `T3`, `a1b2c3d4`), oppure `Design`, `Scan`, `All tasks`, `Drifts` o `Import` (vedi `rules`).
- Con `trama.autoExit` acceso il terminale, nell'area o in scheda, sparisce da solo appena l'agente ha finito, senza avvisi: ciò che l'agente ha archiviato è sulla Board. Nessun messaggio sostituisce il resoconto dell'agente.
- L'avviso della shell sostituita su Windows è un messaggio informativo senza pulsanti: `Trama: the default terminal shell (<shell>) is not supported for agents on Windows; the agent runs in Windows PowerShell.`, con `<shell>` il nome del programma della shell predefinita (per esempio `cmd.exe` o `wsl.exe`).
- Tutti questi testi sono in inglese e non seguono `trama.language`.

## agent-launching
- Non c'è nessuna scelta dell'agente alla prima corsa: senza un valore in `trama.agent` vale `chat`.
- Le descrizioni delle impostazioni, in inglese: `trama.analysis`, `trama.scan` e `trama.execution` dicono quali lavori usano quel modello (`trama.scan` anche i sotto-agenti che confrontano le Machine, compresi quelli del pre-flight dei Run; nessuna descrizione nomina una scansione dopo l'approvazione), che il nome va scritto come lo accetta l'agente scelto in `trama.agent` (omp, Claude Code o la chat di Cursor; per Copilot il nome mostrato nel selettore dei modelli della chat), che vuoto lascia il modello predefinito dell'agente, che in Copilot il modello resta anche nel selettore della chat e che ai sotto-agenti delle chat `trama.scan` arriva con Update skills; `trama.maxParallelAgents` dice: how many sub-agents the agent may run at once, in a scan, in the exploration of a design and in a run of Tasks (default 20; agents without sub-agents ignore it).
- La descrizione dell'impostazione `trama.driftAutoPilot`, nella lingua fissa delle impostazioni esistenti, distingue `disabled` (flusso manuale, predefinito), `enabled` (raccomandazione, approvazione e correzione dei non critici), `yolo` (anche dei critici). Specifica ambito solo utente, urgenza della posizione del developer, attesa iniziale degli scan, esecuzione delle origini, che uno scan fallito o interrotto non sospende la delega e possibilità di cicli automatici senza limite aggiuntivo; disabilitare ferma nuovi passi ma non uccide un Task iniziato. Non si aggiunge un controllo di configurazione distinto sulla Board.
- `trama.driftAutoPilot` ha `enumDescriptions`, mostrate nella scheda Settings e nelle impostazioni dell'editor. `trama.driftAutoPilot`: `disabled` «Manual: you decide on every Drift (the default).», `enabled` «The agent recommends, approves and fixes non-critical Drifts on its own.», `yolo` «Like enabled, critical Drifts included: the ones where your decision is urgently needed.».
- Non ci sono più i comandi `Trama: Set System 1 API Key` e `Trama: Clear System 1 API Key`, né l'impostazione `trama.system1`.
- L'avviso del modello non trovato in Copilot è un messaggio di avvertimento senza pulsanti: `Trama: no Copilot model is named "<nome>" (<impostazione>). The instruction was sent with the model chosen in the chat.`, con `<nome>` il valore del ruolo e `<impostazione>` il nome dell'impostazione, per esempio `trama.scan`. Non c'è più l'avviso dei ruoli in chat.
- Tutti questi testi sono in inglese e non seguono `trama.language`.
