# Requirements: Tecnologia e vincoli, Tecnologia di design request

Usa quando lavori su richieste di design scritte.

## design-request

- + Add Work Item e Start from Scratch scrivono subito il file vuoto con l'ID nuovo, creando la cartella e il suo `.gitignore` se mancano, e lo aprono con `vscode.window.showTextDocument` in una scheda non in anteprima. Non si usano documenti senza titolo. Start from Scratch aggiunge l'ID all'elenco delle richieste di setup in `ExtensionContext.workspaceState` (chiave `trama.setupDesignRequests`) prima di aprire la scheda. La casella di una riga della richiesta rapida (`showInputBox` con titolo «Quick Design Request») e il suo prompt sono rimossi.
- L'host salva da sé ogni documento aperto di un file in `.trama/requests/` del progetto al più 300 ms dopo l'ultima modifica (`workspace.onDidChangeTextDocument` seguito da `TextDocument.save()`), senza dipendere dall'impostazione `files.autoSave` dell'editor.
- La chiusura della scheda si riconosce con `window.tabGroups.onDidChangeTabs` (schede chiuse), solo quando nessun'altra scheda mostra più lo stesso file; il testo da inviare si legge dal file su disco. La chiusura della finestra non passa da lì e non invia nulla.
- L'elenco degli ID inviati sta in `ExtensionContext.workspaceState`. Un ID entra nell'elenco solo quando l'istruzione è davvero partita.
- Send to agent è un comando dell'estensione con un'icona nella barra del titolo dell'editor (`menus.editor/title`, gruppo `navigation`), visibile solo quando il documento attivo è un file in `.trama/requests/` del progetto mai inviato. Una chiave di contesto impostata dall'host decide la visibilità. Il comando salva il documento, manda l'istruzione e, solo se è partita, chiude la scheda senza che questa chiusura invii una seconda volta.
- `trama proposal new` accetta `request` e lo scrive nel campo `request` della Proposal. `trama proposal move <id> open` cancella `.trama/requests/<id>.md` della Proposal legata dopo che la consegna è riuscita, insieme a `.trama/requests/<id>.images/` con tutto ciò che contiene (`consumeRequest` in `src/core/design-requests.ts`), e lo dice nel suo output. Né la riga di comando né l'estensione hanno altri comandi per le richieste.
- L'estensione si accorge della cancellazione del file (dalla consegna o da fuori) con l'osservatore dei file che già usa per `.trama/` e chiude la scheda del file solo se non ha modifiche non salvate. Quando vede sparire `requests/<id>.md`, in Writing come in Sent, cancella `requests/<id>.images/` se esiste; chiudendo una richiesta vuota mai inviata cancella il file e la cartella. All'attivazione sul progetto cancella ogni `requests/<id>.images/` senza il suo `requests/<id>.md`. Un file dentro una cartella delle immagini non è mai una richiesta: `requestIdAt` resta limitato ai file `.md` direttamente in `requests/`.
- Incolla e trascina li fa l'editor Markdown integrato di VS Code (e di Cursor), senza provider di incolla o trascina dell'estensione. Il `package.json` dell'estensione contribuisce in `configurationDefaults` il default di `markdown.copyFiles.destination` con la chiave `**/.trama/requests/*.md` e il valore `${documentBaseName}.images/${fileName}`, così un file incollato o trascinato da fuori dal progetto è copiato in `requests/<id>.images/` con il suo nome (con `markdown.copyFiles.overwriteBehavior` predefinito, un nome già presente prende un numero). `engines.vscode` non cambia. Le impostazioni `markdown.editor.filePaste.*` e `markdown.editor.drop.*` restano quelle dell'editor: per default si copiano i file multimediali che vengono da fuori dal progetto e si collegano quelli del progetto. Un valore utente o di workspace di `markdown.copyFiles.destination` sostituisce il default dell'estensione: Trama non lo legge e non lo corregge.
- La skill `trama-design` (in `skills/trama-design/SKILL.md`) descrive la richiesta scritta: leggere il file nominato dall'istruzione e guardare le immagini che collega (file locali e indirizzi web, quando l'agente può), ignorando in silenzio quelle che non riesce a vedere; scrivere a parole ciò che conta e non copiare, collegare o citare le immagini della richiesta nella Proposal, nel Modello, nei Requisiti, nelle Specs o nei Task; intervistare in modo completo; passare `request` solo alla prima `trama proposal new` del design. L'istruzione di una riga all'agente non cambia.
- Il testo fantasma è una decorazione dell'editor (`vscode.window.createTextEditorDecorationType` con `after.contentText` e `after.color` uguale a `new vscode.ThemeColor("disabledForeground")`), un tipo per la richiesta di design e uno per quella di setup, creati una volta dall'host e liberati con lui. L'host la applica a `Range(0, 0, 0, 0)` di ogni editor visibile (`window.visibleTextEditors`) che mostra un file in `.trama/requests/` del progetto mai inviato quando `document.getText()` è la stringa vuota, e la toglie con `setDecorations(type, [])` negli altri casi. La ricalcola a ogni `window.onDidChangeVisibleTextEditors` e a ogni `workspace.onDidChangeTextDocument` di un file di richiesta, e quando la richiesta diventa inviata; così vale anche per le schede che l'editor ripristina dopo un riavvio.
- La skill `trama-setup` (in `skills/trama-setup/SKILL.md`) legge la richiesta e ne guarda le immagini come `trama-design`, con le stesse regole sul loro uso; apre la sua Proposal con `trama proposal new` con `{ title, kind: setup, body, request }`, la consegna con `trama proposal move <id> open` e, se la consegna l'ha approvata, dice al developer che la Proposal è approvata e i Task partono; altrimenti riporta il motivo che la consegna stampa.
