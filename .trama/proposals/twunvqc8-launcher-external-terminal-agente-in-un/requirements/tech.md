# Technology and constraints

## General
- Language: TypeScript in strict mode (ES2022, ES modules, bundler module resolution) with `noUncheckedIndexedAccess` on, so every indexed read may be undefined.
- Runtime, package manager, test runner and compiler of the command line: Bun (`bun install`, `bun test`, `bun build --compile`). Type checking is `tsc --noEmit`.
- Only three runtime libraries: `yaml` (front matter and settings files), `cytoscape` and `elkjs` (drawing and laying out the Diagram).
- Layers: `src/core` holds the Model, Requirements, Proposals, Tasks, Drifts and Snapshot logic and must not depend on Bun, so the editor extension reuses it; `src/cli` is the command line; `extension/src` is the VS Code extension (a host running in Node, bundled as CommonJS, and a webview running in the browser).
- The command line is one standalone binary named `trama`, built with `bun build --compile`. The agent skills are embedded in the binary.
- Persistent project information is plain Markdown (with YAML front matter where needed) in a `.trama/` folder at the project root, versioned with the project's git. There is no database or network service; the extension's user-local question socket and transient discovery records are the exception to project-file storage.
- Trama never calls a language model and never reads the project's code; the agent does, through the command line.
- The extension targets VS Code (engine `^1.95.0`) and is packaged as one `.vsix` per platform (`linux-x64`, `darwin-arm64`), each with the command-line binary inside. Tagged releases (`v*`) are built and published by a GitHub Actions workflow on Bun 1.4.0, which type-checks, runs the tests and smoke-tests the packaged binary.
- Cursor è un editor supportato al pari di VS Code, riconosciuto da `vscode.env.appName` che, in minuscolo, contiene «cursor». Versioni provate: 3.22.12 e 3.23.12 (VS Code 1.128.0 sotto). Funziona nella finestra dell'editor; la finestra degli agenti di Cursor (Agents Window) non è supportata. I comandi interni di Cursor che Trama usa non sono documentati e possono cambiare: ognuno ha sempre un ripiego (vedi `agent-terminal`).
- Agent skills live in `skills/` (trama-design, trama-scan, trama-implement, trama-import) and are installed into the project's `.agents/skills` by default, or `.claude/skills` for Claude Code.
- `examples/shop` is a complete sample Trama project (Model and Requirements of an online shop) used by the demo scripts, the harness and the manual acceptance run; it is data, not part of the System.
- L'unica comunicazione di rete che Trama fa da sé è la richiesta HTTP a ntfy per gli avvisi al developer (vedi `notice`), e solo se il developer ha indicato un argomento. Nessun'altra chiamata di rete, nessuna telemetria.

## agent-terminal
- The agent runs in a terminal named "Trama agent", created in the project folder with the environment variable `TRAMA_AGENT=1`; the command line refuses the developer-only commands (approve, reject, discard, resolve a Drift, take a Task back, `trama ids rewrite`) while it is set. This stops an agent that runs them by mistake, not one that clears the variable on purpose (ADR 0005).
- Settings: `trama.agentCommand` (command that starts the agent; `{prompt}` is replaced by the shell-quoted prompt, or the prompt is appended if missing), `trama.agentLauncher` (`auto`, the default, `terminal`, `external-terminal` or `chat`), `trama.externalTerminalCommand` (empty by default, see below), `trama.autoScan` (default on) and `trama.skillsDir` (default `.agents/skills`).
- The setting `trama.language` is free text, empty by default, and is read each time an instruction is sent. It is part of the instruction only: it is not saved in the project, in `.trama/` or in the skills, so an agent that the developer starts without Trama does not receive it. Trama does not check that the text names a real language. The interface of Trama stays in English.
- Il launcher «auto» sceglie la chat quando l'editor è Cursor e il terminale integrato altrimenti, mai quello esterno; in Cursor un launcher pronto non richiede `trama.agentCommand`. «terminal», «external-terminal» e «chat» scelti a mano vincono sempre.
- In Cursor il launcher della chat prova in quest'ordine e passa al successivo se un passo manca o fallisce. 1) `composer.createNew` con `{ partialState: { text, richText, unifiedMode: "agent" }, openInNewTab: true, autoSubmit: true }`: crea una chat nuova e la invia da sola (provato su Cursor 3.22.12: scattano gli hook `beforeSubmitPrompt` e `sessionStart`; comando interno non documentato). Il passo è riuscito se il comando non lancia un errore: il valore che restituisce non conta, perché è sempre vuoto (Cursor 3.23.12), e un valore vuoto non fa mai passare al deeplink. Dopo un passo riuscito Trama non controlla che la chat abbia davvero inviato il prompt. 2) Il deeplink `cursor://anysphere.cursor-deeplink/prompt` con `text`, `workspace` (il nome della cartella del progetto, che porta il link alla finestra giusta) e `mode=agent`, aperto con `vscode.env.openExternal`: Cursor mostra una conferma e aspetta l'Invio. Cursor rifiuta un testo vuoto, di oltre 10.000 caratteri una volta codificato, che contiene `.env` o altri schemi simili, e in quel caso si passa al passo 3. 3) Gli appunti, con l'avviso «Trama: the prompt is on the clipboard. Paste it into your agent chat.».
- Negli altri editor il launcher della chat esegue `workbench.action.chat.newChat` e `workbench.action.chat.open` con il prompt in modalità agent, come prima; non è un'API documentata e se fallisce il prompt va negli appunti.
- Il Cursor CLI (`agent`) è un comando dell'agente come gli altri: con i launcher del terminale, integrato o esterno, `trama.agentCommand` può essere `agent {prompt}`. Non è provato che il suo sandbox lasci passare `trama ask`.
- Il launcher «external-terminal» funziona su Linux e macOS, le piattaforme dei pacchetti dell'estensione, e solo quando il progetto è aperto in locale (`vscode.env.remoteName` vuoto): non c'è Windows e un workspace remoto (SSH, WSL, container) è un caso di finestra che non si può aprire.
- Rilevamento del terminale esterno, usato solo se `trama.externalTerminalCommand` è vuota. Linux: la variabile d'ambiente `TERMINAL` se punta a un programma eseguibile, poi `xdg-terminal-exec`, poi `x-terminal-emulator`, poi il primo trovato nel PATH tra `gnome-terminal`, `konsole`, `xfce4-terminal`, `kitty`, `wezterm`, `alacritty`, `foot` e `xterm`. macOS: Terminal.app. Per ogni terminale riconosciuto Trama conosce la forma dei suoi argomenti per eseguire un comando in una cartella; un programma preso da `TERMINAL` o da `x-terminal-emulator` che non è riconosciuto riceve il comando con `-e`.
- `trama.externalTerminalCommand` è il comando che apre il terminale esterno al posto del rilevamento: un modello in cui `{command}` è sostituito dalla riga di comando dell'agente (vedi sotto) citata come un unico argomento per la shell; se `{command}` manca, la riga è aggiunta in fondo. Il processo parte nella cartella del progetto. Vale solo nelle impostazioni utente, non in quelle del workspace, perché esegue un comando scelto dal developer e il file del workspace può arrivare da un repository altrui. Con questa impostazione non vuota si apre sempre una finestra nuova.
- La riga di comando che gira nella finestra esterna è uno script per una shell POSIX: imposta `TRAMA_AGENT=1`, `TRAMA_TERMINAL` con l'identità del terminale e il `PATH` con la cartella del programma `trama` incluso davanti (come per il terminale integrato); esegue il comando dell'agente con l'istruzione citata per la shell; scrive il marcatore di fine; poi lascia la finestra aperta con la shell di login del developer. La finestra si chiama «Trama agent» quando il terminale lo permette.
- Il marcatore di fine è un file nella cartella `external-terminals/` di `ExtensionContext.globalStorageUri`, con nome `<id del terminale>-<numero della corsa>.end` e per contenuto lo stato di uscita del comando. Lo script lo scrive con un nome provvisorio e poi lo rinomina, così l'estensione non lo legge a metà. L'estensione osserva la cartella, legge il marcatore, lo cancella e lo conta come `terminal.COMMAND_ENDED` solo se corrisponde alla corsa in corso di quel terminale. Un marcatore di una corsa vecchia, o di un terminale che Trama non segue più, si cancella e non conta. All'avvio dell'estensione i marcatori rimasti si cancellano senza effetto, quindi chiudere l'editor mentre l'agente lavora non manda nessun avviso.
- Il riuso di una finestra libera usa lo scripting del terminale stesso e ricorda l'identificativo della finestra o del riquadro aperto. Terminal.app: AppleScript, aprendo la finestra con `do script` e riusandola con `do script … in` la stessa scheda. kitty: Trama lo avvia con il controllo remoto limitato a un proprio socket (`allow_remote_control=socket-only` e `--listen-on`) e lo riusa con `kitten @ send-text`. WezTerm: `wezterm cli send-text` sul riquadro aperto. Il riuso riesce se il comando di scripting termina senza errore; altrimenti è fallito. La riga scritta nella finestra riusata è la stessa di una finestra nuova, con la stessa identità `TRAMA_TERMINAL` e un numero di corsa nuovo.
- La riga di comando e l'istruzione sono citate per la shell con le stesse regole del terminale integrato; l'istruzione non passa mai per un file o per il marcatore.

## panel
- Markdown in the panel is rendered by a small renderer of our own in the webview code, with no new runtime library. One renderer serves the Diagram, the Board and the Requirements tabs, e anche l'overlay delle domande, and it is a plain function from text to DOM nodes that can be tested without a browser page.
- The renderer builds elements with the DOM API and sets text with `textContent`; it never uses `innerHTML` or similar, so no text from a file can inject markup or script. Links are only given an `href` when they are http or https, and are opened by the editor host in the system browser, not by navigating the webview.
- The messages between the Board and the editor host have no move and no take-back message: the host does not accept a request to move a Task or to take one back from the panel, and the Board never sends one. The panel's Task actions are only the launch messages (run a Task, run every Task in To do, run a design), the decisions on Proposals and Drifts, and opening links. Moving a Task and taking it back stay in the command line (`trama task move`, `trama task take-back`), which the panel does not wrap.

## design-request
- Design… scrive subito il file vuoto con l'ID nuovo, creando la cartella e il suo `.gitignore` se mancano, e lo apre con `vscode.window.showTextDocument` in una scheda non in anteprima. Non si usano documenti senza titolo.
- L'host salva da sé ogni documento aperto di un file in `.trama/requests/` del progetto al più 300 ms dopo l'ultima modifica (`workspace.onDidChangeTextDocument` seguito da `TextDocument.save()`), senza dipendere dall'impostazione `files.autoSave` dell'editor.
- La chiusura della scheda si riconosce con `window.tabGroups.onDidChangeTabs` (schede chiuse), solo quando nessun'altra scheda mostra più lo stesso file; il testo da inviare si legge dal file su disco. La chiusura della finestra non passa da lì e non invia nulla.
- L'elenco degli ID inviati sta in `ExtensionContext.workspaceState`. Un ID entra nell'elenco solo quando il launcher ha davvero mandato l'istruzione.
- Send to agent è un comando dell'estensione con un'icona nella barra del titolo dell'editor (`menus.editor/title`, gruppo `navigation`), visibile solo quando il documento attivo è un file in `.trama/requests/` del progetto mai inviato. Una chiave di contesto impostata dall'host decide la visibilità. Il comando salva il documento, manda l'istruzione e, solo se è partita, chiude la scheda senza che questa chiusura invii una seconda volta.
- `trama proposal new` accetta `--request <id>` e lo scrive nel campo `request` della Proposal. `trama proposal submit` cancella `.trama/requests/<id>.md` della Proposal legata dopo che la consegna è riuscita e lo dice nel suo output. Né la riga di comando né l'estensione hanno altri comandi per le richieste.
- L'estensione si accorge della cancellazione del file (dalla consegna o da fuori) con l'osservatore dei file che già usa per `.trama/` e chiude la scheda del file solo se non ha modifiche non salvate.
- La skill `trama-design` (in `skills/trama-design/SKILL.md`) descrive la richiesta scritta: leggere il file nominato dall'istruzione, intervistare in modo completo, passare `--request <id>` solo alla prima `trama proposal new` del design.

## proposal
- The command line has `trama proposal submit <id>` for the agent's hand-over and `trama proposal discard <id>` for the developer's discard (a developer-only command). Every command that registers, writes or deletes a file of a Proposal sends an open Proposal back to Draft and says so in its output.

## drift
- `trama drift new` takes `--happens` and `--should` (the text of the two sides) and the optional `--where` (the text of Where in the code), in place of `--body`, which is removed. It also takes from two to five fix options: each `--option <title>` is followed by its `--option-text <text>`, in the order of the options. Creating a Drift with fewer than two, more than five, an option without title or text, or a title without its text is refused. The skills that file Drifts (`trama-scan`, `trama-implement`, `trama-import`) write both sides and the options, the recommended one first, follow the writing guidelines of the Drift, and put code locations only in `--where`.
- `trama drift replace-proposal <id> --proposal <p>` attaches a newer Proposal in place of the stale one; it is not a developer-only command, since the agent runs it. The skill `trama-design` uses it when asked to rework the stale Proposal of a Drift.
- `trama drift resolve` stays developer-only; `--fix-code`, `--accept-proposal` and `--dismiss` apply the rules of the Drift. `--fix-code` takes `--option <n>` (the number of the chosen option) and the optional `--note <text>`. When `--fix-code` is given without `--option` for a Drift that has options and the command runs in an interactive terminal, it shows the options as a numbered menu with the recommended one as the default, taken by pressing Enter, then asks for an optional note, empty for none; in a non-interactive run it is refused, saying that an option must be chosen. `--option` with `--accept-proposal` or `--dismiss`, and `--note` with them, are refused.

## task
- The command line that moves a Task to In progress as the agent, and `trama task show`, report the blocking Drifts or fix Task by ID and title. `trama drift new` accepts the origin Task (`--task <id>`). The skill `trama-scan` files Drifts without an origin.
- `trama task next` prints the next runnable Task, with its ID and title, and moves nothing. With `--proposal <id>` it considers only the Tasks linked to that Proposal, and is refused when the Proposal does not exist. When no Task is runnable it says so on its first line and lists each Task still in To do within that scope, with the Drift or the fix Task that blocks it, marked as in `trama task list`. Both outcomes end successfully.
- The skill `trama-implement`, asked for several Tasks, takes each one from `trama task next` (with `--proposal <id>` when asked for a design), implements it, and asks again until the command says there is none. It files its Drift with the origin Task, leaves that Task In progress and asks `trama task next` again: a Drift does not end the run. Asked for one named Task, it stops at once when the move to In progress is refused because the Task is blocked, names the Task and the Drift (or fix Task) the refusal names, and takes no other Task. Its final report says what it implemented, which Drifts it filed, and which Tasks in To do were left unrun, each with the Drift or fix Task that blocks it.
- `trama task show` scrive nel testo del task tutto ciò che serve a realizzarlo, senza rimandi ad altri comandi o a skill. Un riferimento a una macchina include l'albero degli stati e gli eventi con chi li riceve, gli stessi fatti di `trama machine`. Un riferimento a uno stato include le transizioni in uscita, anche quelle ereditate dagli stati che lo contengono, segnate come ereditate. Un riferimento a un evento include le transizioni che vi reagiscono, gli stessi fatti di `trama event`. Un riferimento a un'area intera include il testo di ogni sua sezione. Nella parte dei Requisiti, ogni sezione General che ha testo è scritta per intero; il comando non nomina le skill `trama-req-*` da caricare.
- La skill `trama-implement` legge Modello e Requisiti di un task solo con `trama task show`. Per quel task non lancia `trama state`, `trama event`, `trama paths`, `trama machine`, `trama requirements` e non apre le skill `trama-req-*`. La lettura del codice resta. Se una transizione che il task deve realizzare non compare in quel testo, può lanciare un solo comando per quella transizione, `trama state` oppure `trama event`, e non riprende il giro. Dopo il codice non rifà il giro.
- Mentre scrive un task, può eseguire i test aggiunti o modificati per quel task e i test già esistenti del comportamento che il task cambia. Non esegue la suite intera del progetto, il lint né la build dopo ogni task.
- Test, lint e build del progetto girano una volta, alla fine della corsa. Un task chiesto per nome è da solo la sua corsa. In una corsa di più task la suite è dopo l'ultimo, quando `trama task next` dice che non ne resta uno eseguibile.
- Se quella verifica fallisce, l'agente corregge il codice e la rilancia, senza rileggere il Modello, prima del resoconto. I task restano nella colonna in cui sono. Se non sa quale task ha rotto la verifica, lo dice nel resoconto e si ferma, senza un altro giro di lettura.

## announcement
- `trama announce <proposal|task|drift> "<title>"` prints the new announcement's ID. It is not developer-only: the agent runs it.
- `trama proposal new`, `trama task new` and `trama drift new` take an optional announcement ID (`--announcement <id>`). The command that hands a Proposal over needs no ID, since the Draft is already bound.
- Every terminal Trama starts for an agent gets the environment variable `TRAMA_TERMINAL`, an ID of six random lowercase letters and digits that stays with the terminal for as long as it exists, including when it is reused. `trama announce`, and a `trama proposal new` that makes an announcement of its own, copy that variable into the announcement's `terminal`; without the variable the announcement has none. The announcement Trama makes for a design request gets the ID of the terminal it types into.
- The command line writes and deletes the announcement files; the extension also deletes them, when it withdraws them. The Snapshot reads them like the other project files, and the panel refreshes when they change.
- The extension owns the fifteen minutes of quiet and the end of the agent's command: it watches the terminals Trama started and the open question round, withdraws the announcements and keeps the notices. It counts the end of a command only when the terminal reports it with the command line Trama typed, compared after trimming; any other end is ignored, as are ends that arrive without a command line. It withdraws only the announcements whose `terminal` is the terminal where the command ended or that was closed. The command line alone never withdraws an announcement on its own.
- The skills `trama-design`, `trama-scan`, `trama-import` and `trama-implement` tell the agent to announce each card as soon as it knows it will create it and to pass the ID when it creates it: `trama-design` for the Proposals it writes after the first, `trama-scan` for each Task and each Drift, `trama-import` for each Proposal and `trama-implement` for the Drift it files. They tell it never to wait for an announcement to be shown before going on.

## project
- The extension starts only in workspaces that contain `.trama/model/system.md`. The panel offers to initialize a workspace that has no `.trama/`; initializing runs the same code as `trama init` with the configured skills folder.
- When the package ships a `trama` binary for the platform, its folder is put first on the PATH of the editor's terminals so the agent finds it.
- Il `PATH` aggiunto dall'estensione vale per i terminali dell'editor, non per i comandi dell'agente di Cursor: Cursor li avvia come processi propri con il proprio ambiente (verificato nel suo codice, 3.22.12). Per questo l'istruzione alla chat di Cursor dice all'agente dove trovare `trama` (vedi `rules#agent-terminal`).
- `trama ids rewrite` non prende argomenti. È riservato al developer, come `trama proposal discard`: rifiutato con `TRAMA_AGENT=1` e, per la stessa guardia, con `CURSOR_AGENT=1`. Il pannello non ha un pulsante e non manda un messaggio per lanciarlo. Non crea un commit. `docs/cli.md` lo descrive. I messaggi del comando restano in inglese, come il resto dell'interfaccia.

## question-round
- Expose `trama ask`, reading the round as JSON from standard input and waiting until it can print the result as JSON to standard output. When no editor is connected for the project it prints explicit editor unavailability instead of an answer. Keep diagnostics off standard output so agents can consume the result. This command displays no terminal question interface.
- L'overlay fa parte del webview del pannello, nello stesso bundle delle schede, senza nuove librerie runtime e senza un secondo webview. La Quick Pick e l'input box nativi non si usano più per le domande; il loro codice sparisce.
- Lo stato del round (domande, posizione, risposte confermate, scelte e testo non confermati, riepilogo, riduzione a barra) vive nell'host dell'estensione, non nel webview. Il webview riceve lo stato e manda solo le azioni del developer; l'host le controlla e risponde con lo stato nuovo. Così un pannello chiuso e riaperto, o un webview ricreato, mostra il round esattamente come era. Il testo scritto arriva all'host mentre si scrive, con un breve ritardo, per non perderlo se il pannello si chiude.
- Quando un round entra in Asking, l'host crea il pannello se non c'è o lo porta in primo piano (`reveal` con focus), poi gli manda il round. Il comportamento è lo stesso in VS Code e in Cursor.
- La notifica dopo la chiusura del pannello è `vscode.window.showInformationMessage` con il pulsante `Reopen`; non si può ritirare, quindi `Reopen` controlla se il round esiste ancora.
- The extension accepts `trama ask` question requests over a user-local Unix-domain socket, or a named pipe on Windows, accessible only to the current OS user. Do not expose an HTTP port or remote service and do not add runtime libraries for this transport.
- Supply the launching window's endpoint in the environment of Trama agent terminals. `trama ask` without that address discovers a live endpoint for the same project through user-local runtime records outside the repository, using focus recency to select a window. Stale records are not a reachable editor.
- Preserve workspace/project routing independently of the process working directory, through `trama ask --root <project>`.
- Propagate the interruption of `trama ask` (SIGINT or SIGTERM) and its disconnection to the round's lifecycle. Close controls only for the affected round and release its queue position. Client-side timeouts that are not signalled to Trama cannot be detected; observable cancellation or disconnection is required to remove those rounds.
- Distinguish initial editor connection failure from loss of an established editor connection after sending a validated round. Connection failure before submission returns initial editor unavailability. Closure or failure of the editor connection after submission and before a complete result returns the shared `editor-interrupted` error without answers; do not wait for a response timeout or translate it into the fallback result.
- For `editor-interrupted`, `trama ask` prints the error with its code and message as JSON on stdout and exits with failure, keeping diagnostics on stderr. This ends the waiting operation, not external agent processes. The agent skills enforce stopping the workflow awaiting those decisions.
- Dalla shell dell'agente di Cursor (`CURSOR_AGENT=1`) `trama ask` dice all'editor che la richiesta viene dall'agente di Cursor, così nasce l'avviso sulla domanda. Il sandbox di Cursor nasconde i socket sotto `XDG_RUNTIME_DIR` (indizio nel suo programma `cursorsandbox`; non provato): se `trama ask` risponde che l'editor non è raggiungibile mentre il comando gira nel sandbox (`CURSOR_SANDBOX` impostato), le skill dicono all'agente di ripeterlo una volta fuori dal sandbox, chiedendo il permesso a Cursor, e solo dopo di usare le sue domande.
- `docs/cli.md` e le skill `trama-design` e `trama-import` descrivono i campi facoltativi `context` e `details` della richiesta di `trama ask`.
- Cursor sposta in background un comando che dura più di 30 secondi (documentato nel suo strumento di attesa). Le skill dicono all'agente di aspettare la fine di `trama ask` fino al risultato, senza considerarlo fallito né ripeterlo.

## notice
- L'impostazione `trama.ntfy` è una stringa, vuota per default (vuota o di soli spazi vuol dire non impostata, come `trama.language`), dichiarata con scope `application`: vale solo nelle impostazioni utente e viene ignorata nelle impostazioni del workspace, così l'argomento non finisce in un `.vscode/settings.json` versionato con il progetto. Non è salvata in `.trama/` né altrove nel progetto.
- L'impostazione è letta ogni volta: quando sta per nascere un avviso, quando scadono i dieci secondi e quando scade l'attesa del secondo tentativo. Il valore, tolti gli spazi ai bordi, è valido se è un nome di argomento che rispetta `^[A-Za-z0-9_-]{1,64}$`, inviato a `https://ntfy.sh/<argomento>`, oppure un URL assoluto `http://` o `https://` di un argomento (per un server proprio) usato così com'è e senza credenziali dentro. Qualunque altro valore è non valido. Trama non controlla che l'argomento esista.
- L'invio è fatto dall'host dell'estensione, che già osserva i terminali, i round di domande e l'invio delle istruzioni, con la `fetch` globale di Node: nessuna nuova libreria runtime. La riga di comando non partecipa.
- Ogni tentativo è una sola richiesta `POST` all'URL dell'argomento, con il testo UTF-8 come corpo e le intestazioni `Title` (solo ASCII), `Priority` (da 1 a 5) e `Tags`. È un successo solo una risposta HTTP 2xx; ogni altro stato, errore di rete o mancata risposta entro 10 secondi è un fallimento. Non usare credenziali, token né azioni di ntfy.
- Il ritardo di dieci secondi e l'attesa del secondo tentativo sono fissi, non impostazioni. I timer vivono nell'host dell'estensione e sono fermati quando l'avviso viene annullato o l'estensione è disattivata.
- La composizione del testo è una funzione pura dai fatti (tipo di avviso, nome del progetto, domanda, esito, conteggi) a titolo, messaggio, priorità e tag, verificabile senza editor né rete.

## cursor-chat
- Le voci di Trama stanno in `~/.cursor/hooks.json` (`version: 1`), per gli hook `beforeSubmitPrompt`, `stop` e `sessionEnd`. Ognuna è il comando `"<percorso assoluto del programma trama incluso nell'estensione>" cursor-hook`, e questo comando le identifica come voci di Trama. Le altre voci del file non si toccano; un file mancante si crea; un file che non è JSON valido non si riscrive e il developer lo viene a sapere. Gli hook di Cursor non ereditano il `PATH` dell'estensione, per questo il percorso è assoluto: è riscritto da Update skills perché cambia a ogni aggiornamento. Gli hook sono a livello utente e non del progetto, così non entrano nel repository e non toccano i colleghi.
- `trama cursor-hook` legge da standard input il JSON che Cursor passa all'hook (`hook_event_name`, `conversation_id`, `workspace_roots`, e `prompt` per `beforeSubmitPrompt`, `status` per `stop` con `completed`, `aborted` o `error`, `reason` per `sessionEnd`). Trova l'editor del progetto con le stesse registrazioni locali di `trama ask`, usando la prima cartella di `workspace_roots` che contiene `.trama/model/system.md`, gli manda l'evento e finisce subito. Non blocca mai Cursor: per `beforeSubmitPrompt` risponde `{"continue": true}` e per gli altri `{}`, esce con 0 anche senza editor, senza progetto Trama o con un errore, e non scrive altro su standard output.
- L'host dell'estensione traduce gli eventi così. Un `beforeSubmitPrompt` il cui `prompt` comincia con «Use the trama-» o «/trama-» segna la conversazione come di Trama; per una conversazione di Trama ogni `beforeSubmitPrompt` è `PROMPT_SUBMITTED`. `stop` con `completed` è `AGENT_STOPPED`, con `aborted` o `error` è `AGENT_INTERRUPTED`. `sessionEnd` con `window_close` o `user_close` è `CONVERSATION_CLOSED` e la conversazione non è più di Trama; con gli altri motivi non produce nulla, perché lo `stop` ha già riferito. Gli eventi di conversazioni che non sono di Trama si ignorano. L'elenco delle conversazioni di Trama sta solo nella memoria dell'host: si perde al riavvio dell'editor, e le conversazioni già aperte non sono più seguite finché non ricevono un nuovo prompt di Trama.
- I comandi che registrano un'azione dell'agente (spostare un Task in In progress, annunciare, `trama ask`) e la guardia sui comandi del developer trattano `CURSOR_AGENT=1` come `TRAMA_AGENT=1`: Cursor imposta la variabile nella shell del suo agente (verificato in `cursor-agent-exec`, 3.22.12 e 3.23.12) e non nei terminali del developer. Vale la riserva dell'ADR 0005, e la scelta è registrata in un nuovo ADR. Un annuncio fatto così, senza `TRAMA_TERMINAL`, porta il campo `chat` (vedi `announcement` in `data`).
- `AGENT_STOPPED`, `AGENT_INTERRUPTED` e `CONVERSATION_CLOSED` agiscono sui Task presi e sugli annunci con `chat` del progetto di `workspace_roots`; `PROMPT_SUBMITTED` annulla gli avvisi sulla fine del turno dello stesso progetto.

## worktree-round
- `trama.worktreeAgent` è una stringa, scope solo utente, default vuoto, come `trama.agentCommand`: `{prompt}` è sostituito dal prompt quotato per la shell, oppure il prompt è accodato se manca. Se la chiave non c'è nel file delle impostazioni utente, Trama la scrive vuota, senza sovrascrivere un valore già presente.
- Il terminale del worktree nasce nella cartella del worktree, si chiama «Trama agent», con `TRAMA_AGENT=1`, ed esegue `trama.worktreeAgent`. Non usa il launcher della chat. La cartella è sorella del repository: `<cartella padre>/<nome del repository>.trama-worktrees/<id>`, e per il merge `.../merge`.
- Il worktree si crea con git dal commit in testa al branch corrente (`git worktree add -b`). Se il branch `trama/<id>` o `trama/merge` esiste già, l'accettazione o l'unione è rifiutata e il motivo è detto.
- `terminal.COMMAND_ENDED` di un terminale di worktree rilascia solo i Task presi in quel worktree. La fine del terminale ordinario non li rilascia.
- La Board del progetto aperto legge Proposal, Task e Drift dei worktree del giro, e scrive lì la decisione su un Drift. `trama task next` nella cartella aperta non vede quei Task.

## multi-branch
- L'estensione non dichiara `trama.multiBranch`. Una chiave già presente in un file di impostazioni resta dov'è: non è letta e non è cancellata.
- Il pannello e `trama proposal approve` leggono `.trama/multi-branch/state`. L'interruttore è acceso solo se, tolto al più un a capo finale, il testo è `on`.
- Accendere scrive `on` solo se `trama.worktreeAgent`, tolti gli spazi agli estremi, non è vuoto, creando la cartella e il `.gitignore` se mancano. Spegnere scrive `off`, creando cartella e `.gitignore` allo stesso modo. Un'accensione rifiutata non scrive.
- Il pannello osserva quel file. Un cambio, anche da un'altra finestra sullo stesso progetto, aggiorna l'interruttore su tutte le schede, anche quelle nascoste.
- Gli avvisi del pannello sono messaggi di avviso dell'editor. `trama proposal approve` stampa lo stesso testo. Acceso, il comando segue la stessa strada del pannello verso il worktree; spento o illeggibile, applica la Proposal nella cartella aperta.
