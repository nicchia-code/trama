# Tecnologia del progetto

## project
- L'estensione si avvia da sola in ogni finestra, appena l'editor ha finito di avviarsi (`onStartupFinished` in `activationEvents`), anche nelle cartelle senza progetto Trama; fra gli `activationEvents` resta anche `workspaceContains:.trama/model/system.md`. I comandi dichiarati in `contributes.commands`, compreso Open Trama, e l'apertura della vista di Trama nella barra laterale la avviano anche prima, con l'attivazione implicita. L'icona della barra delle attività e la vista sono dichiarate nel manifest e compaiono senza avviare l'estensione, anche senza cartelle; il contenuto della vista lo disegna l'estensione (`tech#menu-laterale`), che l'apertura della vista avvia. In una cartella senza `.trama/` il pannello mostra Get Started, una vista del webview del pannello; Import from Code e Start from Scratch inizializzano con lo stesso codice di `trama project new` (`trama --root <cartella> project new --input '{"skillsDir":"<cartella delle skill configurata>"}'`), e la conferma della sovrascrittura rilancia lo stesso comando con `force: true`. Dopo l'inizializzazione l'host aggiorna il pannello e poi manda l'istruzione di import o apre la richiesta di setup.
- When the package ships a `trama` binary for the platform, its folder is put first on the PATH of the editor's terminals so the agent finds it.
- Pulizia di Copilot. Le versioni precedenti scrivevano il file `copilot-hooks.json` nella cartella `ExtensionContext.globalStorageUri` e lo registravano nelle impostazioni utente in `chat.hookFilesLocations`. A ogni attivazione dell'estensione, al controllo all'apertura di Trama e a Update skills fatto dall'editor, l'estensione cancella quel file se c'è e toglie da `chat.hookFilesLocations` soltanto la voce con il suo percorso assoluto, con `ConfigurationTarget.Global` e senza toccare le altre voci; senza file e senza voce non scrive nulla. Un errore nella pulizia all'attivazione non mostra nulla; al controllo all'apertura e a Update skills si comporta come gli altri errori di quei passi (vedi `rules#project`). Nessuna pulizia tocca ciò che le versioni precedenti scrivevano per Cursor (`~/.cursor/hooks.json`, `~/.cursor/agents/`): l'estensione non legge e non scrive più nessun file di Cursor.
- Le due soglie dei frammenti sono costanti in `src/core`, condivise da riga di comando ed estensione: 4.000 caratteri per il budget delle skill di Requisiti e 12.288 byte per un frammento. Il budget nasce dall'elenco delle skill che gli agenti ricevono all'avvio, il cui minimo misurato è circa 8.000 caratteri (Claude Code: 1% della finestra di contesto, documentazione delle skill; Codex: 2% della finestra, ripiego `DEFAULT_SKILL_METADATA_CHAR_BUDGET` di 8.000 caratteri in `codex-rs/ext/skills/src/render.rs`): 4.000 ne lascia metà alle skill di Trama e alle altre del developer.
- Il watcher dei Requisiti, nell'estensione e nella rigenerazione delle skill, segue anche i file dentro le cartelle delle Aree.
- La skill `trama-design` e il suo riferimento di formato descrivono le Aree come cartelle con `area.md` e frammenti, le due modalità delle skill di Requisiti, gli avvisi di `trama model check` e quando dividere un frammento; `trama proposal edit` accetta in `edit` `requirements/<area>/area.md` e `requirements/<area>/<frammento>.md` e rifiuta `requirements/<area>.md` e percorsi più profondi. `docs/` descrive il formato nuovo e la migrazione con `trama project edit`.
- `trama proposal edit` accetta in `edit` anche `tasks/<nome>.md`, solo per una Proposal ordinaria non allegata a un Drift (vedi `tech#proposal`). La skill `trama-design` e il suo riferimento di formato descrivono i file dei Task della Proposal e la sezione `## Already present`.
- Il controllo all'apertura di Trama (vedi `rules#project`) parte dal gestore di `trama.open` nell'host dell'estensione, dopo aver aperto o portato in primo piano il pannello, senza attenderlo; l'apertura per un round di domande non passa da lì. Usa lo stesso codice di `trama project edit` per le skill dell'agente, i file di omp, le skill ritirate e le skill di Requisiti, saltando la migrazione delle Aree e la creazione delle Aree di partenza, e ne legge il risultato strutturato invece del testo: anche la scrittura di `.omp/agents/trama-analysis.md` e di `.omp/WATCHDOG.yml` dice quali file ha davvero cambiato. Nessun processo resta in vita, nessuna rete, nessun ricordo della versione nel workspace: il confronto dei contenuti basta.
