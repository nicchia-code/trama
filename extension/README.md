# Trama for VS Code

Shows the Trama Model of your project (`.trama/model/`) as a read-only Diagram, its Requirements (`.trama/requirements/`) in a read-only Requirements tab, and a Board of Proposals, Drifts and Tasks. The Board is read-only for Tasks: it offers no arrows, dragging or Take back button, and the editor accepts no message to move a Task or take it back; moving a Task and taking it back stay in the command line (`trama task move`, `trama task take-back`). Descriptions, Requirements, Proposal bodies, Task bodies and Drift texts are shown as Markdown. You never edit the Diagram: you ask your coding agent, then approve or reject its Proposals. Requirement files you may also edit by hand; the extension regenerates the `trama-req-*` agent skills whenever they change.

- **Trama: Open** opens the Diagram/Board/Requirements tab (offers **Initialize Project** when the workspace has no `.trama/`).
- **Trama: Quick Design Request…**, **Trama: Scan System** and the Quick request, Scan and Run buttons send a prompt to your agent.
- **Trama: Design…** and the **Design…** buttons create an empty file `.trama/requests/<id>.md`, named after the local date and time (for example `2026-10-04T19-05-12.md`, with `-2`, `-3`, … when taken), and open it in a tab where you write a design request at length. The folder has its own `.gitignore`, so requests are never versioned. Trama saves the file by itself shortly after every change, whatever `files.autoSave` says, so closing the tab never asks to save. **Send to agent** in the editor title (or closing the tab) sends the agent `Use the trama-design skill on the design request in .trama/requests/<id>.md. …` and closes the tab; with the terminal launcher the ghost on the Board takes the request's title. An empty text sends nothing: **Send to agent** warns, and closing the tab deletes the file silently. If the instruction does not leave (for example you cancel the agent command prompt), the request stays on disk unsent; reopen it from the Explorer to send it. A request is sent once: Trama remembers the sent ones across restarts, and a sent request reopened can be edited but has no **Send to agent**, and closing it sends nothing. Closing the editor window sends nothing either. The agent binds its first Proposal to the request, and handing that Proposal over deletes the file; its tab closes unless it has unsaved changes.
- **Trama: Import from Code** asks your agent to describe the existing code as Proposals (a first one for the System and its Actors, then one per Feature, each requiring the first). They describe the code as it is and list their doubts; approving them starts no Scan.
- **Trama: Update Agent Skills** installs this version's skills into the project, adds the starting Requirement Areas to projects created before they existed, converts Areas still written as one file `requirements/<area>.md` into a folder with `area.md` and `main.md`, and regenerates the Requirement skills; its notification says which Areas it converted or left, and the mode of the Requirement skills (one per fragment, or one index per Area).

Cards are named on the Board, in the panel and in the buttons by their **short number**: `P3` for a Proposal, `T3` for a Task, `D3` for a Drift. The number is temporary and belongs to this working copy (it is kept in `.trama/short-numbers/`, which is never versioned), so another copy or worktree may give the same card another number; a card that is closed (a decided Proposal, a resolved Drift, a Task in Done) has no number and shows its permanent eight-character identity instead, never both. The two look alike, in the same place and font, and are told apart by the tooltip and accessible name, **Short number (temporary)** or **Permanent ID**. Everything Trama writes into files, branches and instructions to the agent uses the identity. The command line accepts the number too (`trama task move T3 doing`); see the [CLI conventions](https://github.com/nicchia-code/trama/blob/main/docs/cli.md#conventions).

Where the prompt goes is set by `trama.agentLauncher`:

- `auto` (default): the chat in Cursor, the integrated terminal (in the terminal area) in every other editor; never the editor tab nor the external terminal. Choosing `terminal`, `terminal-tab`, `external-terminal` or `chat` by hand always wins.
- `terminal`: runs `trama.agentCommand` in an integrated terminal named after its work, for example `omp {prompt}`, `claude {prompt}`, `codex {prompt}`, `copilot -i {prompt}`, or Cursor's CLI `agent {prompt}`; `{prompt}` is replaced by the shell-quoted prompt. The name is the short number of the Task to implement (`T3`) or of the Proposal whose design runs (`P2`), otherwise `Design` (quick or written design request, rework of a stale Proposal), `Scan` (by hand or after an approval or a worktree round), `All tasks` or `Import`; it is the number in this working copy when the instruction is sent and never changes while the terminal is open. A busy terminal is never reused; reuse also requires the same project, question endpoint and name, so an instruction with another name opens a new terminal and leaves the old one open, no longer followed. The terminal has `TRAMA_AGENT=1`, so the agent cannot approve, reject or resolve, and `TRAMA_QUESTION_ENDPOINT` routes its question rounds back to the launching window. Worktree terminals are named `Trama agent`.
- `terminal-tab`: the same agent terminal, with the same name, folder, environment, reuse and end of command, opened as an editor tab titled with that name instead of in the terminal area. The first tab opens in a group beside the active one, so the Trama panel and the question overlay stay visible; while the previous agent tab is still open, a new tab (needed while the agent is still working, or for an instruction with another name) opens in the group where Trama opened that one, without creating another group, and beside the active group again once that group is gone. Trama remembers the group it opened the tab in and does not follow a tab you move. Opening or reusing the tab brings it to the front of its group without taking the focus, so you keep typing where you were; closing it closes the terminal. Worktree terminals always stay in the terminal area.
- `external-terminal`: runs `trama.agentCommand` in a window of your system's default terminal, outside the editor (see [External terminal](#external-terminal)). Linux and macOS only.
- `chat`: starts a new agent conversation in the editor's chat. In VS Code it goes to Copilot's chat, or to the clipboard if the chat is not available. In Cursor, see below.

Agents run the `trama` CLI, so it must be on their `PATH`. `trama.autoScan` scans what a Proposal changed (its scan scope) after it is approved. `trama.autoImplement` (on by default) lets that same agent go on to implement the Proposal's Tasks when the scan files no Drift. `trama.skillsDir` is where Initialize installs the agent skills (`.claude/skills` for Claude Code).

`trama.language` is the language the agent writes in, typed as free text (`Italian`, `Deutsch`…) and empty by default. When it is set, every instruction Trama sends to the agent, with either launcher, ends with `Write everything you generate in <language>, except code, which always stays in English.` That covers the text the agent writes for Trama (Proposals, Model and Requirement text, Task and Drift texts, questions and replies); code, its comments, commit messages, the project's own documentation, names and titles, IDs, Event names and the section titles Trama requires stay English. The setting is read at each launch, changes nothing already written, is not saved in the project (an agent you start without Trama does not receive it) and leaves the Trama interface in English.

`trama.ntfy` is the name (for example `my-trama-alerts`) or the full URL of an [ntfy](https://ntfy.sh) topic, empty by default, and it only applies in your user settings (a workspace value is ignored, so the topic never lands in a file kept with the project). When it is set, Trama sends a notification to that topic in two cases, so that you know the agent is waiting for you when you are away from the computer: a question round the agent asked that stays unanswered for 10 seconds, and the end of the agent command (finished, failed with its exit code, or ended) unless another instruction is written into a terminal within 10 seconds. It covers agents that Trama starts in a terminal and Trama's conversations in Cursor's chat (at the end of each turn, see Cursor below), not the chat of other editors and not an agent you start yourself. The question notice shows the project folder, the question you have in front of you with its position in the round and the labels of its options; the end notice shows the project folder, how the command ended and the Board counts (to decide, To do, In progress). It never contains answers, paths, file contents, Proposals, Tasks or Drifts. A topic name is sent to `https://ntfy.sh`, where anyone who knows the name can read the notifications, so use a long, hard-to-guess name or your own server. If a notification cannot be sent, Trama tries once more after 10 seconds and then tells you in the editor, once, until a notification goes through again. A notification is kept only in memory: if the window closes or the computer sleeps before it is sent, it is lost. The messages are in English whatever `trama.language` says. This request is the only network call Trama makes by itself.

## External terminal

With `trama.agentLauncher` set to `external-terminal`, every instruction (a button, an automatic scan after an approval, the rework of a stale Proposal) opens a window of your system terminal in the project folder and runs `trama.agentCommand` there, with the instruction quoted for the shell. It works on Linux and macOS, and only when the project is open locally (not over SSH, in WSL or in a container). `auto` never chooses it.

- **Which terminal.** Unless `trama.externalTerminalCommand` is set, Trama detects it. Linux: the program `$TERMINAL` points to, then `xdg-terminal-exec`, then `x-terminal-emulator`, then the first of `gnome-terminal`, `konsole`, `xfce4-terminal`, `kitty`, `wezterm`, `alacritty`, `foot` and `xterm` found on the `PATH`. macOS: Terminal.app. A program taken from `TERMINAL` or `x-terminal-emulator` that Trama does not know receives the command with `-e`.
- **`trama.externalTerminalCommand`.** Opens the terminal instead of the detected one: `{command}` is replaced by `sh -c '<the agent's command line>'`, so a terminal that takes a program and its arguments after `-e` or `--` runs it; the words are appended when `{command}` is missing. For example `alacritty -e {command}`. It starts in the project folder and only applies in your user settings, because it runs a command you chose and a workspace file can come from someone else's repository. With it set, every instruction opens a new window.
- **What runs in the window.** A POSIX shell script that sets `TRAMA_AGENT=1`, `TRAMA_TERMINAL` (the terminal's identity) and a `PATH` with the bundled `trama` first, runs the agent command, writes the end marker, and then leaves the window open in your login shell so you can read what the agent reported. The instruction is only quoted into that command line; it never goes through a file or the marker. The window is titled with the instruction's name (see `terminal` above) when the terminal takes a title (Terminal.app, gnome-terminal, konsole, xfce4-terminal, kitty, alacritty, foot, xterm, and WezTerm, whose new window names its tab and window through `wezterm cli set-tab-title` and `set-window-title`; not a terminal of your own command), and the title is given once, when the window opens, and never changes afterwards.
- **How the end is known.** The script leaves `<terminal id>-<run number>.end` in the `external-terminals/` folder of the extension's global storage, holding only the exit status, under a temporary name and then renamed. The extension watches the folder, reads the marker, deletes it, and counts it as the end of the agent command only if it belongs to the run in progress of the window it follows; the notice (`trama.ntfy`), the Tasks the agent had taken and the ghosts of that window then behave as with the integrated terminal. Older markers, those of a window no longer followed and those left when the editor starts are deleted without effect, so closing the editor while the agent works sends no notice. The end never comes from waiting for the terminal's process.
- **Reuse.** A free window is written into again, instead of opening another, only when the previous run of that window has ended, the terminal Trama detected is Terminal.app, kitty or WezTerm, `trama.externalTerminalCommand` is empty, the instruction has the same name as the window (see `terminal` above) and the terminal's own scripting succeeds (AppleScript `do script … in` for Terminal.app, `kitten @ send-text` on a kitty that Trama started with remote control limited to its own socket, `wezterm cli send-text` for WezTerm). The line is the same as in a new window, with the same `TRAMA_TERMINAL` and a new run number. If a condition is missing at the start, a new window opens without a word, and the old one stays open, no longer followed; with any other terminal every instruction opens a new window. While a run is still going, a new instruction always opens a new window and the old one is no longer followed: its marker, if it comes, counts for nothing.
- **When it fails.** If the window cannot be opened nothing starts: the instruction is copied to the clipboard and the error `Trama could not open an external terminal: <reason>. The instruction was copied to the clipboard.` is shown, with the reason `external terminals are not supported on this platform`, `external terminals are not available in a remote workspace`, `no terminal was found; set trama.externalTerminalCommand`, `the terminal could not be started` or the system's error message. Trama never falls back to the integrated terminal. If a reuse was tried and its scripting fails (for example you closed the window), a new window opens and the warning `Trama could not reuse the external terminal window: <reason>. A new window was opened.` is shown. These texts are always in English.
- **Limit.** Trama never closes a window and never learns that you closed one: an external window sends no close event. If you close it while the agent works, no end arrives: its ghost is withdrawn after the fifteen minutes of quiet, and a Task the agent took stays taken until the agent moves it or you take it back.

## Cursor

Cursor is supported like VS Code (tested on 3.22.12 and 3.23.12), in the editor window; Cursor's Agents Window is not supported.

- **Delivery.** The chat launcher tries, in order, and moves on silently when a step is missing or fails: a new chat that sends the prompt by itself (Cursor's internal `composer.createNew`); the prompt deeplink, which opens a chat that waits for your confirmation and Enter (skipped when Cursor would refuse the text: empty, over 10,000 characters encoded, or naming `.env`); the clipboard, with a notice to paste it. No step is tried twice for the same prompt. The new chat counts as sent whenever Cursor raises no error (the command never returns anything), and Trama does not check afterwards that the chat really sent the prompt.
- **PATH.** Cursor runs its agent's commands without the PATH the extension gives the editor's terminals, so every instruction to Cursor's chat has a second line telling the agent to `export PATH="<folder of the bundled trama>:$PATH"` (absent when the package has no binary for the platform).
- **Automatic scan.** After an approval it starts by itself only when the new chat sends it by itself. Otherwise nothing is sent and a notice `Trama: Proposal <id> was approved. Scan the Features it affects?` offers **Scan now**, which sends the same scan through the whole chain.
- **The agent.** Cursor sets `CURSOR_AGENT=1` in its chat agent's shell, and the CLI treats it as `TRAMA_AGENT` (ADR 0010): the developer's decisions are refused, a move to In progress takes the Task, and announcements made there carry `chat: cursor`.
- **Hooks.** In Cursor, **Initialize Project** and **Update Agent Skills** write Trama's entries for `beforeSubmitPrompt`, `stop` and `sessionEnd` into your own `~/.cursor/hooks.json` (never the project's), each running `"<bundled trama>" cursor-hook`; Update rewrites them for the new version's path. Other entries are kept; a file that is not valid JSON is left alone and you are told. The hook passes the editor only the event, the conversation and the project folder, never the prompt, never blocks Cursor and gives up after one second.
- **End of a turn.** A conversation is Trama's from its first prompt starting with `Use the trama-` or `/trama-`, whoever typed it. When one of its turns is interrupted or fails, the ghosts announced from Cursor's chat are withdrawn with the usual notice; closing the conversation withdraws them silently; a normal end leaves them to the card or the quiet period. With `trama.ntfy` set, every end of a turn sends an end notice (`The agent stopped and may be waiting for you.` or `The agent was interrupted or failed.`), and a new prompt to a Trama conversation takes back the waiting ones. Every end of a turn, normal, interrupted or failed, and the closing of the conversation send every Task the agent has taken in the project back to To do (one agent at a time is assumed); the agent takes a Task again when it resumes.
- **Questions.** `trama ask` from Cursor's chat agent goes to the most recently active window of the project and gets the ntfy question notice. In Cursor's sandbox the skills retry an unavailable `trama ask` once outside it, and wait for `trama ask` even after Cursor moves it to the background.

## Agent questions

Agents ask with `trama ask --root <project>`, which accepts the JSON request on stdin; see the [request and result contract](https://github.com/nicchia-code/trama/blob/main/docs/cli.md#question-rounds).

The active round opens immediately as an overlay inside the Trama panel, which comes to the front (or opens) over whatever tab it shows. The header names the agent and the step (`Question <n> of <total>`); an index on the left lists every question with its state (**Answered**, **Skipped**, **Missing**) and ends with **Summary**, and below 600 px it becomes a row of numbered dots. The question, its context, the option descriptions and their **Show details** are Markdown. The recommended option is chosen on the first visit; keys 1–9 pick an option; **Your answer (optional)** takes free text, alone or beside the chosen options. **Next** confirms and moves on (**Review** on the last question), **Back** and the index move without confirming, **Skip** skips one question.

The **Summary** shows every answer, with **Edit** to reopen a question, and **Send to agent** delivers the round once nothing is missing. **Skip all**, and the **Close** button, ask first (`Skip all unanswered questions?`) and then deliver at once, the agent using its recommendation for each skipped question. **Minimize** shrinks the round to a bar at the top of the panel with **Open questions**; closing the panel with a round open shows `Trama has questions from the agent waiting.` with **Reopen**. Esc and focus loss do nothing.

Each window has one FIFO shared by every `trama ask` caller, with no response deadline. Caller cancellation removes only that round. Closing the window, losing its channel, or removing its project interrupts every admitted active and queued round with `editor-interrupted`, disposes the controls and returns no partial answers. The agent must stop its workflow without fallback or retry. Initial editor absence instead returns `unavailable`, allowing its own question interface.

Local discovery chooses the most recently focused live window for the project unless a launching endpoint was supplied. Its records contain no question content and stay outside the repository. Unix sockets and Windows named pipes are user-private; Windows requires its built-in Windows PowerShell 5.1/.NET Framework bridge, not an additional runtime library.

The extension never calls an LLM.
