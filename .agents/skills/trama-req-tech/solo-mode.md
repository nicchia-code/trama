# Requirements: Tecnologia e vincoli, Solo mode

Use when building Solo mode: the core module, the CLI input, the host messages and the Settings and wizard rows.

## solo-switch

- Core: `src/core/solo-mode.ts`, with `bun:test` tests, holds the pure logic: reading and validating `.trama/solo/mode.json` (`data#solo-switch`), building the block for a kind, a prefix and a skills folder, and replacing or removing the block in the text of the exclusion file (`rules#solo-switch`). The git calls (`rev-parse`, `ls-files`) use the `git()` helper of `src/core/git.ts`, shared: fixed arguments, no shell, `GIT_TERMINAL_PROMPT=0` and its time limit; the editor host uses its asynchronous form (`tech#solo-merge`), the command line the synchronous one.
- No key in `contributes.configuration`: Solo mode is not a setting of the editor, is not in `SETTING_GROUPS` nor in `EXPLICIT_TITLES`, and `setSetting` does not accept it.
- CLI (`cli#General`): `trama project new` and `trama project edit` accept `solo?: "off" | "folders" | "files"`. With `solo`, `project new` writes the Solo mode file and the block before any other file of `.trama/` and of the skills, and on a refusal or failure creates nothing. `project edit` with only `solo` writes only Solo mode and does not reinstall the skills; with `skillsDir` too, the block uses that folder. Without `skillsDir` the block uses `.agents/skills`, the default. The result, also with `--json`, carries `solo` (the value now) and `tracked` (`rules#solo-switch`). Outside a git repository a `solo` other than `off` fails with exit 1 and the message `Solo mode needs a git repository.`
- `trama project show --json` carries `solo` with the same value, so the extension and the agent read Solo mode from the command line.
- Host (`extension/src/host/`): one module reads and writes Solo mode through the same in-process code of `trama project edit`, with the configured `trama.skillsDir`. Webview → host: `setSoloMode { solo: "off" | "folders" | "files" }`, validated by `parseToHost` (`extension/src/host/messages.ts`). Host → webview: `soloMode { available: boolean, solo: "off" | "folders" | "files", tracked: string[] }`, at the `ready` of the webview and after every write; the host keeps the last value, works it out again asynchronously only at the first need in the window, after every write and when git's directory reports a change of `index` or `info/exclude`, and sends the last value, without starting git, every time the Settings view becomes visible; outside a project it is not sent.
- Settings tab: the row is drawn by its own component in `extension/src/webview/settings/`, placed after the `trama.skillsDir` field of the `Project` group, as the other rows that are not settings (`OmpStatusBox`, `Providers`).
- Wizard: the choice lives in the wizard's state like the excluded folders, only in the first setup and empty-Model modes, and travels in `confirmSetup` as `solo`. The first setup passes it to `initializeProject` (`extension/src/host/project.ts`) as `solo` of `trama project new`; the empty-Model mode calls `project edit` with `solo` after saving the settings and before launching the path, only when it differs from the project's value.
- Repair: the background check of the skills at every ordinary opening (`rules#project`) also calls the repair of `rules#solo-switch`.
- `docs/` and `CHANGELOG.md` describe Solo mode: what it keeps out of git, that it holds only for the working copy, `.git/info/exclude` and its block, the two kinds, the tracked files and that `.trama/` is then versioned nowhere. `docs/uat.md` has the manual steps: turning it on and off, switching kind, a file already tracked, a folder without git, the first setup with Solo mode.
