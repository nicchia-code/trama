# Regole di avvio dell'agente

## agent-terminal
- The instruction sent to the agent is one line naming a skill: written design request → "Use the trama-design skill on the design request in `.trama/requests/<id>.md`. Bind the first Proposal you open to it with the `request` field." (see the Design request); scan of the whole System → "Use the trama-scan skill on the whole System."; implement → "Use the trama-implement skill on Task <id>."; implement all → "Use the trama-implement skill on every Task in the \"todo\" column. Take them from `trama task list --input '{"runnable":true,"max":<N>}'`, one group at a time, until it says there is none."; import → "Use the trama-import skill on this repository." Non c'è più l'istruzione della richiesta rapida di una riga né quella che realizza i Task di un design. Non c'è più l'istruzione dello scan di Feature: l'unico scan che Trama lancia è quello di tutto il Sistema, da `Scan System` del menu laterale (`rules#work`). There is no instruction naming a Fix skill, and no button or command to ask for one.
- Ogni istruzione che può avere sotto-agenti (design, scan di ogni tipo, implement, implement all, Resolve Drifts, Unify Drifts, import) porta sulla stessa riga, dopo l'istruzione e prima della frase dei sotto-agenti e di quella della lingua, la frase "Run at most N sub-agents at once." con N il valore di `trama.maxParallelAgents`: un intero da 1 in su; vuoto, non intero o minore di 1 vale 20. Le istruzioni di implementazione passano lo stesso N anche come `max` di `trama task list`.
- Resolve Drifts nomina la skill `trama-resolve-drifts` con l'identità permanente del solo Drift scelto con `Resolve` e manda la richiesta manuale, che chiede le decisioni con un round di domande. Non c'è più nessuna richiesta automatica; l'unica istruzione con tutti i Drift aperti è quella di Unify Drifts (`rules#developer.UNIFY_DRIFTS`). Il rifacimento della Proposal obsoleta di un Drift non ha più un'istruzione.
- Il nome del terminale dell'agente dipende dall'istruzione: implement → il numero breve del Task (per esempio `T3`); written design request → `Design`; richiesta di setup di Start from Scratch → `Setup`; scan del System → `Scan`; implement all → `All tasks`; Resolve Drifts, con `Resolve` → `Drifts`; Unify Drifts → `Unify`; import → `Import`. Il Run di un gruppo di una sequenza per modello di `Run all` (`rules#agent-launching`) che non è il gruppo dei Settings si chiama `All tasks · <modello>`, con il modello del gruppo come scritto, tolti gli spazi attorno; il gruppo dei Settings resta `All tasks`. Il numero breve è quello della copia di lavoro aperta al momento dell'invio, e il nome non cambia più finché il terminale resta aperto, anche se il numero cambia. Il nome non dipende dalla lingua scelta. Nessun terminale si riusa: ogni istruzione ne apre uno nuovo, e un terminale a riposo lasciato aperto (`trama.autoExit` spento) non è più seguito.
- Il terminale, o la conversazione di omp Chat, che `Ask more` apre si chiama `Ask <numero breve>` (per esempio `Ask T3`, `Ask P2`, `Ask D1`) o `Ask question`, con le regole del numero breve scritte sopra. Delle frasi che questa sezione aggiunge alle istruzioni porta solo quella della lingua: niente frase del limite, dei sotto-agenti, del Drift blocker, di Parallel Execution, di Sub-agents Context Sharing né delle domande (vedi `rules#developer.ASK_MORE`).
- An implement request is refused unless the Task exists, and a Resolve request on one Drift unless that Drift is open.
- A scan the developer starts by hand names no Proposal, so its Tasks belong to no design, it scans the whole System and it never goes on to implement. Non esiste una scansione automatica dopo un'approvazione: l'approvazione crea da sé i Task del design (vedi `rules#task`).
- Le istruzioni di implementazione (implement e implement all) non cambiano testo: il pre-flight è un passo della skill trama-implement, non un'istruzione nuova. Fa eccezione il Run di `Run all` che appartiene a una sequenza per modello o che deve lasciare fuori delle Proposal (`rules#agent-launching`), con le identità permanenti delle Proposal nell'ordine di creazione: un gruppo senza Task sul ruolo → "Use the trama-implement skill on every Task in the \"todo\" column that belongs to the Proposals `a`, `b`. Take them from `trama task list --input '{"runnable":true,"proposals":["a","b"],"max":<N>}'`, one group at a time, until it says there is none."; il gruppo dei Settings con Proposal da lasciare fuori → "Use the trama-implement skill on every Task in the \"todo\" column except those of the Proposals `a`, `b`. Take them from `trama task list --input '{"runnable":true,"notProposals":["a","b"],"max":<N>}'`, one group at a time, until it says there is none."; con una sola Proposal, "the Proposal `a`". Senza Proposal da nominare l'istruzione è quella di sempre.
- Ogni istruzione (design, scan, import, implement, implement all, Resolve Drifts e Unify Drifts) va a omp, l'unico agente: in un terminale integrato nuovo, nell'area dei terminali o in una scheda secondo `trama.terminalLocation`, oppure in una conversazione nuova di omp Chat quando omp Chat è in uso (`rules#omp-chat`). Un progetto appena inizializzato, con il Modello vuoto o con il pannello mai aperto, non cambia nulla. `trama.agent` non esiste più: un valore rimasto nelle impostazioni utente, `cursor` compreso, non si legge e non si cancella, senza avvisi. Non c'è nessuna scelta dell'agente al primo avvio e nessun comando personalizzato: i valori delle vecchie impostazioni `trama.agentLauncher`, `trama.terminalAgent`, `trama.agentCommand` e `trama.externalTerminalCommand` sono ignorati.
- Disabled for now: no instruction carries the language sentence, whatever `trama.language` holds. When enabled, and a language is set, every instruction above ends, on the same line, with the sentence "Write everything you generate in <language>, except code, which always stays in English." where <language> is the setting's text, trimmed, as typed. It applies to every instruction sent to the agent: design, scan, import, implement, implement all, Resolve Drifts e Unify Drifts. Without a language (empty or only spaces) the instruction is exactly as before.
- Con `trama.driftBlocker` acceso, le istruzioni che possono registrare Drift (scan del System, implement, implement all, import e Unify Drifts) portano sulla stessa riga, dopo la frase del limite e quella dei sotto-agenti e prima di quella della lingua, la frase "The Drift blocker is on: follow its steps whenever you file a Drift, and tell your sub-agents." Design e Resolve Drifts non la portano. Spento, assente o non booleano, l'istruzione resta esattamente com'era; il pre-flight resta un passo della skill, non un'istruzione nuova.
- In the chosen language go the prose the agent produces for Trama: the bodies, descriptions and introductions of Proposals, Model files, Requirements, Tasks and Drifts, the text of questions and their options, and the agent's replies in the conversation. Always English, whatever the language: code and its comments, commit messages and the project's own documentation; the names and titles of Model elements, Requirements, Proposals, Tasks and Drifts; IDs, Event names, the section titles Trama requires (for example "General", "What happens", "What should happen", "Where in the code") and the `(initial)` and `(final)` markers.
- Changing the language changes nothing already written. When the agent edits a file written in another language it keeps the existing text and writes only the new or rewritten text in the chosen language; it does not translate the whole file.
- Ogni istruzione, per ogni lavoro, porta la frase `Ask the developer only with \`trama question new\`, as the skill says, never with your own question tool; run it with no time limit and wait until it ends.`. Sta sulla stessa riga, dopo la frase del Drift blocker e prima di quella della lingua.
- Con `trama.autoExit` acceso all'invio, ogni istruzione di un lavoro con l'hook, nel terminale o in omp Chat, porta dopo la frase delle domande e prima di quella della lingua `Trama closes this session as soon as you finish: end with one short line at most, with no summary or report.`; mai Ask more né General.
- Su Windows, quando la shell predefinita dei terminali non è Windows PowerShell 5.1, PowerShell 7 o Git Bash, il terminale dell'agente si apre con Windows PowerShell (vedi `tech#agent-terminal`) e Trama mostra l'avviso della shell sostituita (vedi `ui#agent-terminal`) solo la prima volta in quella finestra dell'editor: i terminali successivi della stessa finestra non lo mostrano più finché la finestra non si riapre. Per il resto la corsa non cambia: nome, hook, fine del comando e chiusura sono quelli di ogni terminale dell'agente.
- Con omp la fine della corsa la dice l'agente: quando ha finito (il suo hook avvisa l'editor con `trama hook idle`, vedi `tech#agent-hook`), quando il suo comando finisce senza che l'hook abbia parlato (agente interrotto, in errore o ucciso) o quando il terminale è chiuso. omp resta aperto in attesa del prossimo prompt, quindi di norma il comando non finisce da sé; il prompt scritto a mano dopo la fine non rimette la corsa in corso. Non c'è quiete: senza un segnale la corsa resta in corso finché il terminale non è chiuso, l'editor non riparte o il controllo di esecuzione non trova che il processo dell'agente non esiste più (`rules#time`); un agente vivo ma fermo resta in corso.
- Con `trama.autoExit` acceso (predefinito) Trama chiude il terminale dell'agente appena riceve l'hook a riposo o la fine del comando, con `terminal.dispose()`, in ogni posizione (area o scheda) e per ogni istruzione; lo chiude allo stesso modo quando il controllo di esecuzione trova l'agente scomparso. La chiusura rilascia i Task presi e ritira gli annunci di quel terminale solo se l'hook, la fine del comando o il controllo non l'hanno già fatto: nessun avviso doppio. Con `trama.autoExit` spento il terminale resta aperto a riposo e non è più seguito. Le chat non si chiudono mai.
- omp prima di ogni lancio (`agent-launching`). Vale per ogni istruzione (design, scan, import, implement, implement all e ogni Run di una sequenza per modello, Resolve Drifts, Unify Drifts) e per Ask more, nel terminale o in omp Chat; non vale per la ripresa di una conversazione di omp Chat dopo una ricarica. La conversazione General ne usa solo la ricerca di omp, con le sue regole (`rules#omp-chat-general`). In quest'ordine:
  1. Trama trova il programma omp (`tech#agent-launching`). Se manca, il lancio non parte: nessun terminale, nessuna conversazione, nessun annuncio, nessun lavoro; una sequenza per modello si ferma come quando l'istruzione di un Run non parte; compare l'avviso di omp mancante (`ui#agent-terminal`). Il lavoro non riparte da sé quando omp viene installato.
  2. Se l'esito dell'ultimo controllo degli aggiornamenti vale ancora (sotto), il lancio parte subito.
  3. Altrimenti Trama controlla se c'è una versione nuova di omp. Se non c'è, il lancio parte.
  4. Se c'è, Trama esegue l'aggiornamento di omp, con la notifica di avanzamento (`ui#agent-terminal`), e il lancio parte quando l'aggiornamento finisce, con la versione nuova.
  5. Se il controllo o l'aggiornamento falliscono, il lancio parte con l'omp di prima e compare l'avviso dell'aggiornamento fallito, una volta per controllo.
- L'esito di un controllo, riuscito o fallito, vale un'ora dal momento del controllo, per tutte le finestre dell'editor e per lo stesso programma omp: un cambio di `trama.ompPath` o la fine del terminale di installazione lo dimenticano. Un lancio che arriva mentre un controllo o un aggiornamento è in corso aspetta quello, senza un secondo controllo né un secondo aggiornamento. La verifica del passo `omp` del wizard (`rules#setup-wizard`) fa lo stesso controllo, con la stessa validità, e aggiorna allo stesso modo.
- Trama non chiede conferma prima di aggiornare omp: l'aggiornamento è sempre automatico, come ha deciso il developer.
