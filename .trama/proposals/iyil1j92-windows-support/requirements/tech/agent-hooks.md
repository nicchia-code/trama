# Tecnologia degli hook degli agenti del terminale

## agent-hook
- Con omp il comando scritto nel terminale carica il modulo `dist/omp-hook.js` dell'estensione con `--hook <percorso citato>`, subito dopo `omp`. Il modulo è costruito da `extension/src/omp/trama-hook.ts` con `bun run build:extension` ed è incluso nel pacchetto. Se il file non c'è, il comando è quello di prima e la corsa non ha hook. Il modulo non fa nulla se `TRAMA_TERMINAL` non è impostata. omp lo carica in ogni sessione dello stesso processo, la principale e ogni sotto-agente (provato con omp 18.4.4), e un sotto-agente finito è parcheggiato dopo `task.agentIdleTtlMs` (7 minuti per default) chiudendo la sua sessione: per questo ogni gestore distingue le sessioni con `ctx.agent.kind` (`"main"` o `"sub"`).
- Fine del lavoro con omp: il modulo ascolta `session_stop` (scatta solo per la sessione principale, quando il turno sta per finire e i job asincroni dell'agente sono fermi) e `session_shutdown`, e solo quando `ctx.agent.kind` è `"main"` esegue con `pi.exec`, con timeout di 3 secondi, `trama agent-event idle`, senza mai bloccare né far fallire omp. Il `session_shutdown` di un sotto-agente non manda mai nulla; senza `ctx.agent` (un omp che non lo dà) `session_shutdown` non manda nulla e resta solo `session_stop`. `session_stop` non ritorna niente, quindi non chiede mai una continuazione. Il modulo non manda nessun segnale di vita: `agent_start`, `agent_end` e i timer di prima non si usano più.
- Con Claude Code il comando scritto nel terminale passa gli hook con `--settings <json citato>`: un oggetto `{"hooks": {"Stop": [{"hooks": [{"type": "command", "command": "<trama> agent-event idle", "timeout": 3}]}], "SessionEnd": [{"hooks": [{"type": "command", "command": "<trama> agent-event idle", "timeout": 3}]}]}}` dove `<trama>` è il percorso assoluto citato del programma `trama` incluso nell'estensione. `Stop` scatta quando l'agente principale finisce di rispondere; `SessionEnd` quando Claude Code esce. `SubagentStop` non è nell'oggetto: i sotto-agenti non dicono nulla. Nessun file è installato: gli hook valgono solo nei terminali di Trama, come il modulo di omp. Se Claude Code rifiuta l'opzione, il comando parte lo stesso e la corsa non ha hook.
- Su Windows Claude Code esegue i comandi degli hook con Git Bash, qualunque sia la shell del terminale. Per questo `<trama>` nel JSON di `--settings` è sempre citato per Git Bash, con il percorso assoluto scritto a barre in avanti (per esempio `'C:/Users/…/bin/trama.exe' agent-event idle`); solo il JSON intero è poi citato per la shell del terminale. Su Linux e macOS non cambia nulla.
- `trama agent-event idle` ha `TRAMA_TERMINAL` come identità, trova l'editor del progetto come `trama ask` (con `TRAMA_QUESTION_ENDPOINT` o con le registrazioni locali), gli manda il messaggio `agent-idle` con il terminale e finisce subito. Esce con 0 anche senza editor, senza progetto Trama o senza `TRAMA_TERMINAL`; esce con 2 solo per un uso sbagliato. `trama agent-event alive` non esiste più: un `agent-alive` ricevuto da un hook vecchio è ignorato. L'editor conta `agent-idle` come `agent-hook.IDLE` per quel terminale, nel progetto della sua finestra; un `agent-idle` da un terminale già a riposo o chiuso non fa nulla.
- Ogni corsa nel terminale ha un hook, perché gli agenti del terminale sono solo omp e Claude Code: `agent-hook.IDLE` e la chiusura del terminale finiscono il job, rilasciano i Task presi e ritirano gli annunci di quel terminale; la fine del comando che Trama ha scritto fa lo stesso, perché arriva solo quando l'agente esce senza che l'hook abbia parlato. Con `trama.autoExit` acceso, l'editor chiude il terminale subito dopo (vedi `agent-terminal`).
