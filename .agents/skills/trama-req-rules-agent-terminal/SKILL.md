# Requirements: Regole di business, Regole di avvio dell'agente

Generated by Trama from `.trama/requirements/rules/agent-terminal.md`. Do not edit this file: change the Requirements through a Trama Proposal (or ask the developer).

These are the developer's Requirements for how the System is built. Follow them when you write code. The Model (`.trama/model/`) says what the System does; when a Requirement and the Model disagree, stop and tell the developer.
A section titled with a Model reference (such as `order/Paid`) applies to that element and to everything inside it.

## agent-terminal

- The instruction sent to the agent is one line naming a skill: written design request → "Use the trama-design skill on the design request in `.trama/requests/<id>.md`. Bind the first Proposal you open to it with `--request <id>`." (see the Design request); scan of the whole System → "Use the trama-scan skill on the whole System."; scan of Features → "Use the trama-scan skill on the Feature `a`." or "…on the Features `a`, `b`."; implement → "Use the trama-implement skill on Task <id>."; implement all → "Use the trama-implement skill on every Task in the \"todo\" column. Take them from `trama task next --batch --max <N>`, one group at a time, until it says there is none."; import → "Use the trama-import skill on this repository." Non c'è più l'istruzione della richiesta rapida di una riga né quella che realizza i Task di un design. There is no instruction naming a Fix skill, and no button or command to ask for one.
- Ogni istruzione che può avere sotto-agenti (design, scan di ogni tipo, implement, implement all, Resolve Drifts, import) porta sulla stessa riga, dopo l'istruzione e prima della frase dei sotto-agenti e di quella della lingua, la frase "Run at most N sub-agents at once." con N il valore di `trama.maxParallelAgents`: un intero da 1 in su; vuoto, non intero o minore di 1 vale 20. Le istruzioni di implementazione passano lo stesso N anche a `trama task next --batch --max <N>`.
- Resolve Drifts instrada la modalità corrente e nomina la skill `trama-resolve-drifts` con le identità permanenti dei Drift fotografati, in ordine di creazione: con `Resolve all` tutti i Drift aperti fuori da ogni risoluzione, con `Resolve` soltanto il Drift scelto. In `disabled` manda la richiesta manuale attuale; in `enabled` separa critici/eccezioni manuali e non critici automatici; in `yolo` soltanto le eccezioni restano manuali. La richiesta automatica nomina la raccolta e impone di verificare `trama drift autopilot --json`, scegliere la prima Fix option, consegnare una risoluzione `--automatic` e lasciare approvazione e Run all'host. Non usa il testo manuale che impone domande su ogni Drift. Il rifacimento della Proposal obsoleta di un Drift non ha più un'istruzione.
- Il nome del terminale dell'agente dipende dall'istruzione: implement → il numero breve del Task (per esempio `T3`); written design request → `Design`; richiesta di setup di Start from Scratch → `Setup`; scan del System e scan di Feature → `Scan`; implement all → `All tasks`; Resolve Drifts, con `Resolve all` o con `Resolve` → `Drifts`; import → `Import`. Il Run di un gruppo di una sequenza per modello (`rules#agent-launching`), in `Run all` come nel Run automatico, che non è il gruppo dei Settings si chiama `All tasks · <modello>`, con il modello del gruppo come scritto, tolti gli spazi attorno; il gruppo dei Settings resta `All tasks`. Il numero breve è quello della copia di lavoro aperta al momento dell'invio, e il nome non cambia più finché il terminale resta aperto, anche se il numero cambia. Il nome non dipende dalla lingua scelta. Nessun terminale si riusa: ogni istruzione ne apre uno nuovo, e un terminale a riposo lasciato aperto (`trama.autoExit` spento) non è più seguito.
- A scan of a Feature that does not exist in the Model is refused; an implement request is refused unless the Task exists, and a Resolve request on one Drift unless that Drift is open.
- A scan the developer starts by hand names no Proposal, so its Tasks belong to no design, it scans the Features or the System it names and it never goes on to implement. Non esiste una scansione automatica dopo un'approvazione: l'approvazione crea da sé i Task del design (vedi `rules#task`).
- Le istruzioni di implementazione (implement, implement all e il Run automatico della risoluzione dei Drift) non cambiano testo: il pre-flight è un passo della skill trama-implement, non un'istruzione nuova. Fa eccezione il Run di `Run all` che appartiene a una sequenza per modello o che deve lasciare fuori delle Proposal (`rules#agent-launching`), con le identità permanenti delle Proposal nell'ordine di creazione: un gruppo senza Task sul ruolo → "Use the trama-implement skill on every Task in the \"todo\" column that belongs to the Proposals `a`, `b`. Take them from `trama task next --batch --proposal a --proposal b --max <N>`, one group at a time, until it says there is none."; il gruppo dei Settings con Proposal da lasciare fuori → "Use the trama-implement skill on every Task in the \"todo\" column except those of the Proposals `a`, `b`. Take them from `trama task next --batch --not-proposal a --not-proposal b --max <N>`, one group at a time, until it says there is none."; con una sola Proposal, "the Proposal `a`". Senza Proposal da nominare l'istruzione è quella di sempre. Il Run automatico di un gruppo usa la sua istruzione di sempre con le sole identità autorizzate del gruppo.
- L'autopilota è un flusso separato dallo scan: lo scan continua a fermarsi al resoconto e non realizza i Task archiviati. Dopo la barriera l'host avvia la risoluzione e, dopo la sua approvazione e la fine dell'agente, un'istruzione separata di `trama-implement` sulle sole correzioni e origini autorizzate, con il filtro `trama task next --batch --task <id> ... --max <N>`. Entrambe le nuove istruzioni conservano lingua, limite e launcher; la risoluzione usa il nome del terminale già previsto per Resolve Drifts, il Run quello della corsa di Task.
- L'agente si legge da `trama.agent` a ogni invio, per ogni istruzione (design, scan, import, implement, implement all e Resolve Drifts): un progetto appena inizializzato, con il Modello vuoto o con il pannello mai aperto, non cambia nulla. Con `chat` l'istruzione va alla chat dell'editor: la chat di Cursor in Cursor, la chat di Copilot in ogni altro editor. Con `omp` o `claude` l'istruzione va in un terminale integrato nuovo, nell'area dei terminali o in una scheda secondo `trama.terminalLocation`, e non va mai alla chat, nemmeno quando il terminale non si può usare. Non c'è nessuna scelta dell'agente al primo avvio e nessun comando personalizzato: i valori delle vecchie impostazioni `trama.agentLauncher`, `trama.terminalAgent`, `trama.agentCommand` e `trama.externalTerminalCommand` sono ignorati.
- When a language is set, every instruction above ends, on the same line, with the sentence "Write everything you generate in <language>, except code, which always stays in English." where <language> is the setting's text, trimmed, as typed. It applies to every instruction sent to the agent: design, scan, import, implement, implement all, Resolve Drifts e le istruzioni automatiche della delega dei Drift. Without a language (empty or only spaces) the instruction is exactly as before.
- Con `trama.experimentalDriftBlocker` acceso, le istruzioni che possono registrare Drift (scan del System e di Feature, implement, implement all, il Run automatico della delega e import) portano sulla stessa riga, dopo la frase del limite e quella dei sotto-agenti e prima di quella della lingua, la frase "The experimental Drift blocker is on: follow its steps whenever you file a Drift, and tell your sub-agents." Design, Resolve Drifts e la risoluzione automatica non la portano. Spento, assente o non booleano, l'istruzione resta esattamente com'era; il pre-flight resta un passo della skill, non un'istruzione nuova.
- In the chosen language go the prose the agent produces for Trama: the bodies, descriptions and introductions of Proposals, Model files, Requirements, Tasks and Drifts, the text of questions and their options, and the agent's replies in the conversation. Always English, whatever the language: code and its comments, commit messages and the project's own documentation; the names and titles of Model elements, Requirements, Proposals, Tasks and Drifts; IDs, Event names, the section titles Trama requires (for example "General", "What happens", "What should happen", "Where in the code") and the `(initial)` and `(final)` markers.
- Changing the language changes nothing already written. When the agent edits a file written in another language it keeps the existing text and writes only the new or rewritten text in the chosen language; it does not translate the whole file.
- Nella chat di Cursor l'istruzione ha una seconda riga, dopo la frase della lingua se c'è. Su Linux e macOS è `The trama command may not be on your PATH. Before anything else run: export PATH="<cartella del programma trama incluso nell'estensione>:$PATH"`. Su Windows è `The trama command may not be on your PATH. Run it by its full path: <percorso assoluto di trama.exe incluso nell'estensione>`, senza un comando di shell, perché la shell dell'agente di Cursor su Windows non è nota. Serve perché Cursor avvia i comandi dell'agente senza il PATH dell'estensione. Senza un programma incluso per questa piattaforma la riga non c'è. Con il terminale e con la chat di Copilot l'istruzione resta di una riga.
- Ogni istruzione, per ogni lavoro e ogni agente, porta la frase `Ask the developer only with \`trama ask\`, as the skill says, never with your own question tool.`. Nel terminale e nella chat di Copilot sta sulla stessa riga, dopo la frase del Drift blocker e prima di quella della lingua; nella chat di Cursor è una riga a sé, dopo quella sul `PATH` oppure, senza quella, subito dopo l'istruzione.
- Su Windows, quando la shell predefinita dei terminali non è Windows PowerShell 5.1, PowerShell 7 o Git Bash, il terminale dell'agente si apre con Windows PowerShell (vedi `tech#agent-terminal`) e Trama mostra l'avviso della shell sostituita (vedi `ui#agent-terminal`) solo la prima volta in quella finestra dell'editor: i terminali successivi della stessa finestra non lo mostrano più finché la finestra non si riapre. Per il resto la corsa non cambia: nome, hook, fine del comando e chiusura sono quelli di ogni terminale dell'agente.
- Ogni passo della consegna alla chat di Cursor che fallisce o non esiste passa al successivo senza avvisare il developer; solo il passaggio agli appunti lo avvisa. Non si prova mai due volte lo stesso passo per lo stesso prompt, per non creare due chat con lo stesso testo.
- Una conversazione è di Trama se un prompt inviato nomina, in qualunque punto e anche dopo `/`, il nome intero di una skill con cui Trama avvia un lavoro (`trama-design`, `trama-scan`, `trama-implement`, `trama-import`, `trama-resolve-drifts` o `trama-setup`), non seguito da una lettera, una cifra o un trattino; le skill `trama-req-*` non contano. Vale sia che il prompt l'abbia scritto Trama con un pulsante sia che l'abbia scritto il developer a mano. Un prompt che nomina una skill di Trama ma in una conversazione già di Trama è un normale `PROMPT_SUBMITTED`. Le conversazioni del progetto che non lo sono non producono rilasci di Task né ritiro di annunci.
- Con omp e con Claude Code la fine della corsa la dice l'agente: quando ha finito (il suo hook avvisa l'editor con `trama agent-event idle`, vedi `tech#agent-hook`), quando il suo comando finisce senza che l'hook abbia parlato (agente interrotto, in errore o ucciso) o quando il terminale è chiuso. Entrambi restano aperti in attesa del prossimo prompt, quindi di norma il comando non finisce da sé; il prompt scritto a mano dopo la fine non rimette la corsa in corso. Non c'è quiete: senza un segnale la corsa resta in corso finché il terminale non è chiuso o l'editor non riparte.
- Con `trama.autoExit` acceso (predefinito) Trama chiude il terminale dell'agente appena riceve l'hook a riposo o la fine del comando, con `terminal.dispose()`, in ogni posizione (area o scheda) e per ogni istruzione. La chiusura rilascia i Task presi e ritira gli annunci di quel terminale solo se l'hook o la fine del comando non l'hanno già fatto: nessun avviso doppio. Con `trama.autoExit` spento il terminale resta aperto a riposo e non è più seguito. Le chat non si chiudono mai.
