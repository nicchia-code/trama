# Tecnologia dei round di domande

## question-round
- Expose `trama ask`, reading the round as JSON from standard input and waiting until it can print the result as JSON to standard output. When no editor is connected for the project it prints explicit editor unavailability instead of an answer. Keep diagnostics off standard output so agents can consume the result. This command displays no terminal question interface.
- L'overlay fa parte del webview del pannello, nello stesso bundle delle schede, senza nuove librerie runtime e senza un secondo webview. La Quick Pick e l'input box nativi non si usano più per le domande; il loro codice sparisce.
- Lo stato del round (domande, posizione, risposte confermate, scelte e testo non confermati, riepilogo, riduzione a barra) vive nell'host dell'estensione, non nel webview. Il webview riceve lo stato e manda solo le azioni del developer; l'host le controlla e risponde con lo stato nuovo. Così un pannello chiuso e riaperto, o un webview ricreato, mostra il round esattamente come era. Il testo scritto arriva all'host mentre si scrive, con un breve ritardo, per non perderlo se il pannello si chiude.
- Quando un round entra in Asking, l'host crea il pannello se non c'è o lo porta in primo piano (`reveal` con focus), poi gli manda il round. Il comportamento è lo stesso in VS Code e in Cursor.
- La notifica dopo la chiusura del pannello è `vscode.window.showInformationMessage` con il pulsante `Reopen`; non si può ritirare, quindi `Reopen` controlla se il round esiste ancora.
- The extension accepts `trama ask` question requests over a user-local Unix-domain socket, or a named pipe on Windows, accessible only to the current OS user. Do not expose an HTTP port or remote service and do not add runtime libraries for this transport.
- Su Windows la named pipe è quella di Node (`net`, `\\.\pipe\trama-question-<uuid>`), senza ponte PowerShell, senza `Add-Type` e senza nessun altro processo: il codice che avvia PowerShell per la pipe o per verificare le ACL sparisce. Poiché una pipe di Node lascia connettere in lettura anche altri utenti locali, ogni richiesta all'editor, su ogni piattaforma, porta il segreto della finestra letto dal suo record di discovery (vedi `data#question-round`): una richiesta senza il segreto giusto non riceve nessuna risposta e la connessione si chiude. Su Windows Trama si affida ai permessi predefiniti di `%LOCALAPPDATA%`, senza controllarli; su Linux e macOS il socket e la cartella dei record mantengono i permessi e i controlli di oggi.
- Supply the launching window's endpoint in the environment of Trama agent terminals. `trama ask` without that address discovers a live endpoint for the same project through user-local runtime records outside the repository, using focus recency to select a window. Stale records are not a reachable editor.
- Preserve workspace/project routing independently of the process working directory, through `trama ask --root <project>`.
- Propagate the interruption of `trama ask` (SIGINT or SIGTERM) and its disconnection to the round's lifecycle. Close controls only for the affected round and release its queue position. Client-side timeouts that are not signalled to Trama cannot be detected; observable cancellation or disconnection is required to remove those rounds.
- Su Windows `SIGTERM` non arriva al processo: `trama ask` si annulla con Ctrl+C (`SIGINT`) o con la chiusura del suo output o della sua connessione, e `docs/cli.md` lo dice. Un processo ucciso senza preavviso conta come disconnessione appena l'editor vede chiudersi la pipe.
- Distinguish initial editor connection failure from loss of an established editor connection after sending a validated round. Connection failure before submission returns initial editor unavailability. Closure or failure of the editor connection after submission and before a complete result returns the shared `editor-interrupted` error without answers; do not wait for a response timeout or translate it into the fallback result.
- For `editor-interrupted`, `trama ask` prints the error with its code and message as JSON on stdout and exits with failure, keeping diagnostics on stderr. This ends the waiting operation, not external agent processes. The agent skills enforce stopping the workflow awaiting those decisions.
- Nella sandbox di Cursor su Linux (`CURSOR_SANDBOX` impostato) il processo dei comandi dell'agente è rimappato all'UID 0 e l'UID vero dell'utente sta in `CURSOR_ORIG_UID` (documentazione di Cursor, Run Modes; riprodotto con `unshare --user --map-root-user`): calcolando la cartella dei record di discovery con `process.getuid()` la riga di comando cercava `trama-q-0` e rispondeva sempre `unavailable`. Quando `CURSOR_SANDBOX` è impostato e `CURSOR_ORIG_UID` è un intero, la riga di comando usa quell'UID al posto di `process.getuid()` nel nome della cartella dei record (`trama-q-<uid>`), così `trama ask`, le segnalazioni di attività, gli annunci e `trama drift autopilot` raggiungono l'editor anche dalla sandbox. I controlli di proprietario e permessi della cartella e dei socket restano quelli di oggi. Fuori dalla sandbox nulla cambia; su macOS la cartella resta quella di oggi, anche nella sandbox.
- Se con `CURSOR_SANDBOX` impostato `trama ask` non raggiunge comunque l'editor (per esempio perché la sandbox non lascia connettere al socket o non mostra la cartella dei record), il risultato `unavailable` ha come `reason` «Editor not reachable from Cursor's sandbox. Run the same trama ask once more outside the sandbox; if the editor is still unavailable, stop and tell the developer to open the project in the editor with Trama.». Senza `CURSOR_SANDBOX` il `reason` è «Editor not available for this project. Do not ask in any other way: stop, tell the developer to open the project in the editor with Trama, and run the same trama ask again when they say to continue.». Nessuno dei due testi nomina più lo strumento di domande dell'agente. `status: "unavailable"` resta un risultato distinto, con uscita 0. `docs/cli.md` riporta i due testi e non dice più che questo risultato permette lo strumento di domande dell'agente.
- `docs/cli.md` e le skill `trama-design`, `trama-import` e `trama-resolve-drifts` descrivono i campi facoltativi `context` e `details` della richiesta di `trama ask`.
- Cursor sposta in background un comando che dura più di 30 secondi (documentato nel suo strumento di attesa). Le skill `trama-design`, `trama-import` e `trama-resolve-drifts` dicono all'agente di lanciare `trama ask` con l'attesa predefinita e, se Cursor lo sposta in background, di aspettare soltanto la fine di quel comando con lo strumento di Cursor che attende un comando in background (`AwaitShell` sul suo identificativo), che torna appena il comando finisce, e poi leggerne subito il risultato. Se quell'attesa scade prima che il comando finisca, perché il developer non ha ancora risposto, la riprende sullo stesso comando. Non usano un timer o un'attesa di durata fissa, `sleep`, letture periodiche dell'output del terminale né controlli a intervalli; non chiudono il turno per farsi risvegliare; non considerano fallito `trama ask` né lo ripetono.
- `trama-scan` e `trama-implement` non ripetono il formato e le regole di `trama ask`: quando hanno una domanda rimandano alla sezione «Asking» di `trama-design`, come fa `trama-setup`, e valgono anche per loro le regole sull'attesa in Cursor qui sopra.
- Il messaggio di rifiuto del tool di domande dell'agente è lo stesso per i quattro agenti, in inglese: «In Trama's work, ask the developer only with `trama ask --root <project>`, as the Trama skill says. This question tool is disabled here.». `<project>` resta scritto così: l'agente conosce il suo progetto. Lo usano l'hook di omp, quello di Claude Code e gli hook della chat di Cursor e di Copilot (vedi `tech#agent-hook` e `tech#editor-chat`).
