# Data

## General
- Persistent project information lives in files under `.trama/`: `model/` (the Model), `requirements/` (one file per Area), `proposals/`, `tasks/`, `drifts/`. Files are Markdown; Proposals, Tasks and Drifts start with YAML front matter followed by an H1 that is their title and a free prose body. Question rounds, editor-discovery information, announcements and written design requests are transient, not project information.
- Model layout: `model/system.md` (System), `model/actors/<actor>.md` (one per Actor), `model/<feature>/feature.md` and `model/<feature>/<machine>.md`. Features cannot be nested. Only `.md` files are allowed in the Model; files and folders starting with a dot are ignored.
- Features, Machines and Actors share one namespace of IDs. An ID is the folder or file name, kebab-case matching `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`; `system`, `feature`, `actors` and `requirements` are reserved. Event names are `UPPER_SNAKE_CASE` and unique within their owner.
- Proposal, Task e Drift non condividono un contatore. L'identità di una scheda nuova è di otto caratteri, lettere minuscole e cifre (`^[a-z0-9]{8}$`), estratta a caso; se in quella cartella è già usata da una scheda dello stesso tipo, se ne estrae un'altra. È unica per tipo: un Task e una Proposal possono avere la stessa stringa. Il file, o la cartella per una Proposal, si chiama `<id>-<slug>`, dove lo slug è il titolo in minuscolo, ridotto a lettere e cifre ASCII separate da trattini singoli, tagliato a 40 caratteri, e `untitled` se non resta nulla. Una scheda nuova ha nel front matter `created`, l'istante di creazione in UTC come data e ora ISO 8601. Una scheda il cui nome è ancora `NNNN-<slug>`, con NNNN di almeno quattro cifre, resta leggibile: la sua identità è quel numero, accettato come `12` o `0012`, e non ha `created`. Un comando cita una scheda con l'identità intera, con un prefisso univoco fra le schede di quel tipo, o con il nome completo del file o della cartella. Un argomento di sole cifre cita solo una scheda numerata, mai un'identità casuale. Un prefisso che combacia con più schede è rifiutato e il comando elenca le identità.
- A Requirement Area is `requirements/<area>.md`: front matter with a required `description`, one H1 with the Area's title, optional prose that applies to the whole Area, then `## General` and `## <element reference>` sections. A section must name an element of the Model that exists and appear once per file.
- Element references: `order` (Feature, Machine or Actor), `order/Paid` (State, any depth), `order/Paid/user.CANCEL` (Transitions on an Event), `user.CANCEL` (Event). Requirements are referenced as `requirements/<area>` or `requirements/<area>#<section>`, with `#General` for the general section.
- Numero breve temporaneo: ogni Proposal, Task e Drift vivo ha, in più della sua identità permanente, un numero intero positivo, unico per tipo, che si scrive con la lettera del tipo davanti e senza zeri iniziali: `P3` per una Proposal, `T3` per un Task, `D3` per un Drift. Non sta nel nome del file, nel front matter né in nessun altro file versionato: sta solo nel file `.trama/short-numbers/assigned` di questa copia di lavoro, che ha una riga per scheda viva nella forma `<tipo> <identità permanente> <numero>`, con il tipo `proposal`, `task` o `drift`. La cartella `short-numbers/` non è versionata: ha un suo `.gitignore` che ignora tutto ciò che contiene (il testo `*`), scritto insieme al primo `assigned`. Ogni copia di lavoro, compreso ogni worktree, ha il proprio file, e la stessa scheda può avere numeri diversi in copie diverse.

## task
- One file `tasks/<id>-<slug>.md`. Front matter: `column` (`todo`, `doing` or `done`; default `todo`), `technical` (true or false; default false), `refs` (list of element or Requirement references), `drift` (ID of the Drift it resolves, or none), `proposal` (ID of the Proposal, the design, the Task comes from, or none; absent in Tasks written before this field existed), `agent` (true while the agent has taken the Task, false otherwise; default false, so Tasks written before this field existed are free), `created` (istante di creazione in UTC, ISO 8601; assente nei Task numerati scritti prima di questo campo). The H1 is the title; the body says what must be true when done, in domain words.
- The Board's To decide column is not a Task column; it shows open Proposals (never drafts) and open Drifts.

## drift
- One file `drifts/<id>-<slug>.md`. Front matter: `status` (`open` or `resolved`; default `open`), `resolution` (`fix-code`, `proposal` or `dismissed`; none while open), `refs` (list of element or Requirement references), `proposal` (ID of the attached Proposal, or none; the agent may replace it while the Drift is open), `task` (ID of the Task created when resolved as fix-code, or none), `origin` (ID of the Task the agent was implementing when it filed the Drift, or none; absent in Drifts written before this field existed, which have no origin), `option` (number, counted from 1 in the order of the Fix options section, of the option the developer chose when resolving as fix-code; none otherwise and in Drifts without options), `note` (the developer's note given with that choice, or none) e `created` (istante di creazione in UTC, ISO 8601; assente nei Drift numerati scritti prima di questo campo). The H1 is the title. The body is Markdown with three required sections, in this order: `## What happens`, what the code does today, `## What should happen`, what the Model or the Requirement says, and `## Fix options`; then one optional section, `## Where in the code`, with the places where the difference was seen. `dismissed` means the developer kept the code and no Proposal was attached.
- `## Fix options` holds from two to five options, each a `###` heading with the option's title followed by its text, a Markdown description of that way to fix the code and what the developer gets from it. The first option is the agent's recommendation. Titles are unique within the Drift. The options are not part of the Model or of what a Requirement says: they only describe ways to reach what should happen.
- A Drift is not part of the Model, so the optional `## Where in the code` section may name files and code elements. The required sections are written at the level of behaviour (see the rules of the Drift) and name no code locations. Drifts written before the sections existed may name code locations in What happens; they stay as they are.
- Drifts written before the Fix options section existed have none: if they are Open the developer fixes their code without choosing an option; `option` and `note` stay empty.
- Resolved Drifts written before the two sections existed keep their free body; they are shown as one block.

## proposal
- One folder `proposals/<id>-<slug>/` with `proposal.md` and, beside it, a `model/` and a `requirements/` folder holding the full new version of every touched file at the same relative path it has under `.trama/`. Front matter of `proposal.md`: `status` (`draft`, `open`, `approved`, `rejected` or `discarded`; default `open`, so Proposals written before `draft` existed are already handed over; a new Proposal is written with `draft`), `kind` (`change` or `import`; default `change`), `requires` (list of Proposal IDs), `base` (touched path → SHA-256 of the file when the Proposal first touched it, or `new` for a file that did not exist), `delete` (list of paths the Proposal removes), `request` (ID della richiesta di design scritta a cui la Proposal è legata, o nessuno; resta anche dopo che la richiesta è stata consumata, ed è assente nelle Proposal scritte prima che esistesse), `created` (istante di creazione in UTC, ISO 8601; assente nelle Proposal numerate scritte prima di questo campo).
- The H1 of `proposal.md` is the title; the prose says why. Rejection appends a `## Feedback` section with the developer's text when it has any. Staleness is computed, never stored.

## design-request
- Un file `requests/<id>.md` sotto `.trama/`, creato vuoto da Design…, quindi anche in Writing. L'ID è la data e l'ora locali di creazione con i secondi, nella forma `AAAA-MM-GGTHH-MM-SS` (per esempio `2026-10-04T19-05-12`); se quel file esiste già, l'ID prende il suffisso `-2`, `-3`, … fino al primo libero. Il file contiene solo il testo Markdown del developer, senza front matter; può non avere un titolo.
- La cartella ha un suo `.gitignore` che ignora tutto ciò che contiene, così le richieste non sono mai versionate; Trama lo scrive insieme alla prima richiesta.
- Quali richieste sono state inviate non sta nel file né sotto `.trama/`: l'estensione tiene l'elenco degli ID inviati nel proprio stato per l'area di lavoro, che sopravvive ai riavvii dell'editor. Un ID il cui file non esiste più è tolto dall'elenco. Un file in `requests/` il cui ID non è nell'elenco è una richiesta in Writing.

## announcement
- One file `announcements/<id>.md` under `.trama/`. The ID is six random lowercase letters and digits, not a sequence, because announcements do not outlive their card. Front matter: `kind` (`proposal`, `task` or `drift`), `source` (`agent` when the agent announced it, `request` when Trama announced a design request), `proposal` (ID of the Draft bound to it, or none until the Draft exists), `terminal` (ID of the agent terminal it belongs to, or none; absent in announcements written before this field existed, which belong to no terminal) and `touched` (when the agent last did something about it, as a date and time). The H1 is the title shown on the ghost.
- Il campo `chat` di un annuncio vale `cursor` quando l'annuncio è fatto dall'agente della chat di Cursor (`CURSOR_AGENT=1` senza `TRAMA_TERMINAL`); è assente altrimenti e negli annunci scritti prima che esistesse. Un annuncio con `chat` non ha `terminal`.
- The folder holds its own `.gitignore` that ignores everything in it, so announcements are never versioned; Trama writes it together with the first announcement. No other part of `.trama/` is ignored, except `requests/` (see the Design request), `multi-branch/` (see Multi-branch) and `short-numbers/` (see the short numbers in General).
- Whether a question round is open is the only thing about question rounds that the Board learns, held in memory; nothing about the questions or the answers reaches the Board or the files.
- Notices about withdrawn announcements are held in memory by the panel and are not written anywhere.

## question-round
- The request is a JSON object containing `questions` in presentation order. Each question contains a unique non-empty `id`, non-empty `question`, `options` containing `{label, description}`, a zero-based `recommended` option index and a `multi` boolean.
- Una domanda può avere anche `context`, una stringa Markdown con lo sfondo della decisione; un'opzione può avere anche `details`, una stringa Markdown con la spiegazione estesa (per esempio pro e contro). Entrambi sono facoltativi: assenti, la domanda e l'opzione si mostrano senza. Le richieste senza questi campi restano valide come prima.
- A completed round contains one answer per question ID. Each answer identifies whether it was answered or skipped, preserves the original labels of selected options and holds free text when supplied. Ogni risposta, a scelta singola o multipla, può avere opzioni scelte e testo libero insieme, oppure solo il testo; skips contain no fabricated answer. La forma del risultato non cambia.
- Initial editor unavailability is a distinct result, not an empty completed round or a collection of skipped answers. Editor loss after admission is a distinct interruption error, identified as `editor-interrupted`, with a message and no answers; it must not be represented as initial editor unavailability. Invalid input is a distinct error with the offending question or field identified.
- Pending questions, navigation position, choices and free answers remain in memory only for the lifetime of their round. Do not write them to `.trama/`, the Board or discovery files.
- Per ogni domanda il round tiene in memoria la risposta confermata (o il salto) e, separatamente, quello che è scelto o scritto senza conferma; tiene anche se la domanda corrente è stata aperta dal riepilogo, se il riepilogo è mostrato e se l'overlay è ridotto. Solo la risposta confermata e i salti arrivano all'agente.
- Editor-discovery records contain the project identity, window identity, local endpoint and focus recency needed to route requests. Store them outside the repository in user-local runtime storage, never in project-versioned files.

## notice
- Gli avvisi stanno solo nella memoria dell'host dell'estensione. Non sono scritti in `.trama/`, né su altri file, né mostrati sulla Board; spariscono con la finestra, e al riavvio non ne riparte nessuno.
- Un avviso ha un tipo (domanda o fine del comando), il nome del progetto (il nome della cartella del progetto), il round a cui si riferisce (domanda) oppure l'esito del comando riportato dal terminale (finito bene, finito con errore e relativo codice, oppure non riportato). Titolo, testo, priorità (da 1 a 5) e tag si compongono solo al momento dell'invio.
- Il testo di una domanda e le etichette delle sue opzioni sono quelli che l'agente ha fornito, nella sua lingua, senza traduzioni. Le risposte del developer non fanno mai parte di un avviso.
- Per ogni finestra l'host dell'estensione tiene solo in memoria un fatto: se l'avviso di errore dell'editor è già stato mostrato dopo l'ultimo invio riuscito.

## worktree-round
- Il giro non è un file del progetto. Trama lo ricava dai worktree git il cui branch è `trama/<id di una Proposal>` o `trama/merge`, e dalle cartelle sorelle del repository.
- Il Merge Drift è un file `.trama/merge-drift.md` nel worktree di merge, con le sezioni `## What happens`, `## What should happen` e `## Fix options`, come un Drift. Non è un file `drifts/` della cartella aperta e non resta dopo l'unione.
- Il Task di riconciliazione è un file di Task nel worktree di merge con `merge: true` nel front matter, `technical: true` e `column` come gli altri Task. Non è copiato nella cartella aperta dall'unione.

## multi-branch
- Una cartella `.trama/multi-branch/`, locale a questa copia di lavoro e non versionata. Il file `state` contiene `on` oppure `off`, con al più un a capo finale. La cartella ha un suo `.gitignore` che ignora tutto ciò che contiene (il testo `*`), scritto insieme al primo `state`.
- Cartella o file assenti: l'interruttore è spento. Un file presente che, tolto al più un a capo finale, non è `on` né `off`: l'interruttore è spento e il developer è avvisato.
