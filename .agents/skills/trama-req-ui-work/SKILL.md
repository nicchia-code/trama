# Requirements: Interfaccia, Interfaccia di Drift e Task

Generated by Trama from `.trama/requirements/ui/work.md`. Do not edit this file: change the Requirements through a Trama Proposal (or ask the developer).

These are the developer's Requirements for how the System is built. Follow them when you write code. The Model (`.trama/model/`) says what the System does; when a Requirement and the Model disagree, stop and tell the developer.
A section titled with a Model reference (such as `order/Paid`) applies to that element and to everything inside it.

## drift

- The details of a Drift in the Diagram and its card in the Board's To decide column show a comparison in two columns. The left one is headed "What happens" and holds the Drift's What happens text; the right one is headed "What should happen", with the word "Model" or "Requirements" beside the heading (Requirements when the Drift points only to Requirements), and holds the What should happen text. Both texts are rendered as Markdown. The two sides are told apart by their headings, not by colour alone.
- Each column ends with one button, "Keep this", and under it one line saying what choosing it does. Right column: "A Task is created for the agent to fix the code with the chosen option" ("…to fix the code" when the Drift has no options). Left column with an attached Proposal that can be approved: "Approves Proposal <id> and changes the Model to match". Left column without a Proposal: "Closes the Drift; nothing changes". These two buttons are the only way to decide on a Drift in the panel: there is no separate Fix code, Accept Proposal or Dismiss button.
- In the right column, between the What should happen text and its Keep this, a group of radio buttons headed "Fix options" offers the Drift's options, in their order, each with its title in bold and its text rendered as Markdown. The first option, the agent's recommendation, is marked "(recommended)" and is selected when the Drift first shows; exactly one option is always selected, and the developer changes the selection by clicking an option or with the arrow keys. Under the group, a multi-line field labelled "Note (optional)" takes free text. A Drift without options shows neither the group nor the heading, only the field.
- The right Keep this fixes the code with the selected option and the text of the field when it is not empty; the left Keep this takes neither. The selection and the text of a Drift stay as the developer left them while the Board or the Diagram refresh during the session, and closing the panel forgets them, like which cards are open.
- The accessible name of each button says the side and the Drift, for example "Keep what should happen for <Drift title>"; the right one also says the selected option, for example "Keep what should happen for <Drift title> with option <option title>". The group of options is named "Fix options for <Drift title>" and the field "Note for <Drift title>".
- The columns sit side by side and stack, what happens first, when the panel is narrow. The attached Proposal keeps its link, and the Board card keeps its link to the Diagram or to the Requirement.
- When the Drift has a Where in the code section, a collapsible block headed "Where in the code" sits under the two columns, across their whole width, closed when it first shows; its text is rendered as Markdown. Opening or closing it changes nothing else, and it is not part of either side's Keep this. The block is absent when the Drift has no such section. A Board card keeps it closed unless the developer opened it during the session, like the other cards.
- When the attached Proposal cannot be approved, the left Keep this looks disabled and is marked as disabled for assistive technology, but stays focusable and still receives the click. Clicking it changes nothing and shows a warning in the editor that names the Proposal and says why: still being written ("wait until the agent hands it over"); rejected or discarded ("it will not change the Model: keep what should happen to have the code fixed"); stale ("the Model changed since it was written") with a "Rework Proposal" button that asks the agent to rework it; any other reason (invalid, waiting for other Proposals, already approved) is shown as it is reported for the Proposal. The left line under the button names the same reason in short.
- The right Keep this is always available.
- `trama drift show` shows the two sides as two blocks headed "What happens" and "What should happen", then a block headed "Fix options" with the options as a numbered list, each with its title and its text, the first marked "(recommended)", then, when the Drift has one, a block headed "Where in the code", then the attached Proposal with its state and, when it cannot be approved, the reason. A Drift without options has no Fix options block. A Drift resolved by fixing the code also shows a block headed "Chosen option" with the number and title of the option, when there was one, and a block headed "Note" when the developer gave one. The texts are printed as the Markdown they were written in. A resolved Drift written before the two sections existed shows its body as one block headed "Description".

## task

- `trama board` lists Proposals the agent is still writing in their own group, "In writing", marked "(draft)", apart from the Proposals to decide, and `trama proposal list` marks them "(draft)".
- `trama board` lists each design once, in its derived column, with the Proposal's ID and title and its Tasks underneath, each with its own column. Tasks that belong to no design, and designs of a single Task, are listed as before.
- `trama task list` stays a flat list grouped by column, so every Task can still be found; each Task shows the ID of the Proposal it comes from when it has one.
- A Task taken by the agent is marked "(agent working)" in `trama board` and `trama task list`.
- A blocked Task is marked "(blocked by Drift <id>)", or "(waiting for Task <id>)" when it waits for the Task that fixes its Drift, in `trama board`, `trama task list` and `trama task show`. When several Drifts block it, all are listed.
- A Drift's own view (`trama drift show`) does not list the Tasks it blocks.
