# Handoffs and issues

## issue
- A handoff is a Proposal with `kind: handoff` (`data#proposal`). Beside `proposal.md` it has a folder `issues/` with one file `<identity>-<slug>.md` per issue, and no `tasks/`. The identity has 8 characters like the other cards and is unique among `.trama/issues/`, the `issues/` of every Proposal, `.trama/tasks/` and the `tasks/` of every Proposal.
- Front matter of an issue in a handoff: `refs` (element references and Requirement sections, as in Tasks; may be empty), `estimate` (days, a number), `assignee` and `reviewer` (GitHub handles without `@`, each optional), `sprint` (the title of an iteration of the linked Project, optional), `fields` (an object from the name of a field of the Project to its value as text, optional), `dependsOn` (identities of the issues it depends on, optional) and `manager` (an object from a field key to the value the Manager chose, optional). A field key is `assignee`, `reviewer`, `estimate`, `sprint` or `fields.<name>`; where `manager` has a key, its value is the issue's value and the agent's value stays in its own field. Any other field is a validation error. H1: the title. Body: the body the agent wrote for GitHub, without the lines Trama adds when composing it (`rules#issue`).
- Approving the handoff creates, for each issue, `.trama/issues/<identity>-<slug>.md` with the same identity, title and body, and a front matter with: `handoff` (the identity of the Proposal), `label` (the handoff's label), `refs`, `estimate`, `assignee`, `reviewer`, `sprint`, `fields` and `dependsOn` with the Manager's values already applied (no `manager` field), `created` (the approval instant), `state` (`publishing`, `not-published` or `published`), and, as they come: `number` and `url` (GitHub), `published` (instant), `unset` (keys of the fields GitHub did not take), `reason` (why it is not published), and `texts` (an object from each reference in `refs` to the text fingerprint of that reference at publication, as in `tech#scans`).
- `.trama/issues/` follows the rest of `.trama/`: tracked with the project, or kept out of git with Solo mode on like the other files of Trama.
- The Manager's changes to the fields of a handoff's issue are written only in `manager` of the issue's file and never change the file's starting version recorded in `base`: they make the handoff neither stale nor a Draft.

## github-project
- The linked Project lives in `.trama/manager/project.json`, a JSON object `{ "owner": "<login>", "number": <n>, "title": "<title>" }`, in the local folder `.trama/manager/` of Manager mode (`data#manager-mode`), so it is never committed. Absent means not linked; a file that does not match counts as not linked and is replaced by the next link.
- What Trama last read from GitHub lives only in the editor's `ExtensionContext.workspaceState`, key `trama.team.github`: `{ readAt, project: { fields, iterations } | null, error: string | null }`, where a field is `{ id, name, type, options? }` and an iteration `{ id, title, startDate, duration }`. It is a cache: nothing else depends on it and losing it only costs a read.
