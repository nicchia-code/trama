# Trama for VS Code

Shows the Trama Model of your project (`.trama/model/`) as a read-only Diagram, its Requirements (`.trama/requirements/`) in a read-only Requirements tab, and a Board of Proposals, Drifts and Tasks. The Board is read-only for Tasks: it offers no arrows, dragging or Take back button, and the editor accepts no message to move a Task or take it back; moving a Task and taking it back stay in the command line (`trama task move`, `trama task take-back`). Descriptions, Requirements, Proposal bodies, Task bodies and Drift texts are shown as Markdown. You never edit the Diagram: you ask your coding agent, then approve or reject its Proposals. Requirement files you may also edit by hand; the extension regenerates the `trama-req-*` agent skills whenever they change.

- **Trama: Open** opens the Diagram/Board/Requirements tab (offers **Initialize Project** when the workspace has no `.trama/`).
- **Trama: Design with Agent…**, **Trama: Scan System** and the Design, Scan and Run buttons send a prompt to your agent.
- **Trama: Import from Code** asks your agent to describe the existing code as Proposals (a first one for the System and its Actors, then one per Feature, each requiring the first). They describe the code as it is and list their doubts; approving them starts no Scan.
- **Trama: Update Agent Skills** installs this version's skills into the project, adds the starting Requirement Areas to projects created before they existed, and regenerates the Requirement skills.

Where the prompt goes is set by `trama.agentLauncher`:

- `terminal` (default): runs `trama.agentCommand` in the "Trama agent" terminal, for example `omp {prompt}`, `claude {prompt}`, `codex {prompt}`, `copilot -i {prompt}`; `{prompt}` is replaced by the shell-quoted prompt. A busy terminal is never reused; reuse also requires the same project and question endpoint. The terminal has `TRAMA_AGENT=1`, so the agent cannot approve, reject or resolve, and `TRAMA_QUESTION_ENDPOINT` routes its question rounds back to the launching window.
- `chat`: starts a new agent conversation in the editor's chat (Copilot in VS Code) with the prompt. In Cursor, or when the chat is not available, the prompt is copied to the clipboard to paste into the agent panel. Agents in the editor's chat do not get `TRAMA_AGENT`.

Agents run the `trama` CLI, so it must be on their `PATH`. `trama.autoScan` scans the touched Features after a Proposal is approved. `trama.skillsDir` is where Initialize installs the agent skills (`.claude/skills` for Claude Code).

`trama.language` is the language the agent writes in, typed as free text (`Italian`, `Deutsch`…) and empty by default. When it is set, every instruction Trama sends to the agent, with either launcher, ends with `Write everything you generate in <language>, except code, which always stays in English.` That covers the text the agent writes for Trama (Proposals, Model and Requirement text, Task and Drift texts, questions and replies); code, its comments, commit messages, the project's own documentation, names and titles, IDs, Event names and the section titles Trama requires stay English. The setting is read at each launch, changes nothing already written, is not saved in the project (an agent you start without Trama does not receive it) and leaves the Trama interface in English.

`trama.ntfy` is the name (for example `my-trama-alerts`) or the full URL of an [ntfy](https://ntfy.sh) topic, empty by default, and it only applies in your user settings (a workspace value is ignored, so the topic never lands in a file kept with the project). When it is set, Trama sends a notification to that topic in two cases, so that you know the agent is waiting for you when you are away from the computer: a question round the agent asked that stays unanswered for 10 seconds, and the end of the agent command (finished, failed with its exit code, or ended) unless another instruction is written into a terminal within 10 seconds. It only covers agents that Trama starts in a terminal: not the chat, and not an agent you start yourself. The question notice shows the project folder, the question you have in front of you with its position in the round and the labels of its options; the end notice shows the project folder, how the command ended and the Board counts (to decide, To do, In progress). It never contains answers, paths, file contents, Proposals, Tasks or Drifts. A topic name is sent to `https://ntfy.sh`, where anyone who knows the name can read the notifications, so use a long, hard-to-guess name or your own server. If a notification cannot be sent, Trama tries once more after 10 seconds and then tells you in the editor, once, until a notification goes through again. A notification is kept only in memory: if the window closes or the computer sleeps before it is sent, it is lost. The messages are in English whatever `trama.language` says. This request is the only network call Trama makes by itself.

## Agent questions

Agents ask with `trama ask --root <project>`, which accepts the JSON request on stdin; see the [request and result contract](https://github.com/nicchia-code/trama/blob/main/docs/cli.md#question-rounds).

The active round opens immediately at the top of the window in native Quick Picks, one question at a time. Recommendations are active or checked on the first visit; Back restores preceding answers. Other opens an input box and can accompany ordinary multi-choice selections. Empty free text shows validation feedback. Escape offers **Skip this one**, **Skip all** or **Go back**, never a silent skip. Focus loss does not dismiss the controls.

Each window has one FIFO shared by every `trama ask` caller, with no response deadline. Caller cancellation removes only that round. Closing the window, losing its channel, or removing its project interrupts every admitted active and queued round with `editor-interrupted`, disposes the controls and returns no partial answers. The agent must stop its workflow without fallback or retry. Initial editor absence instead returns `unavailable`, allowing its own question interface.

Local discovery chooses the most recently focused live window for the project unless a launching endpoint was supplied. Its records contain no question content and stay outside the repository. Unix sockets and Windows named pipes are user-private; Windows requires its built-in Windows PowerShell 5.1/.NET Framework bridge, not an additional runtime library.

The extension never calls an LLM.
