# Requirements: Tecnologia e vincoli

Generated by Trama from `.trama/requirements/tech/`. Do not edit these files: change the Requirements through a Trama Proposal (or ask the developer).

These are the developer's Requirements for how the System is built. Follow them when you write code. The Model (`.trama/model/`) says what the System does; when a Requirement and the Model disagree, stop and tell the developer.
A section titled with a Model reference (such as `order/Paid`) applies to that element and to everything inside it.
This is the index of the Area's Requirements. The General Requirements are below in full; every other section is in the file of its fragment, next to this one: read the fragments whose sections name the elements you work on.

## General

- Language: TypeScript in strict mode (ES2022, ES modules, bundler module resolution) with `noUncheckedIndexedAccess` on, so every indexed read may be undefined.
- Runtime, package manager, test runner and compiler of the command line: Bun (`bun install`, `bun test`, `bun build --compile`). Type checking is `tsc --noEmit`.
- The runtime libraries are the ones the Specs list (`specs#frameworks`): `yaml`, `zod` 4, `cytoscape` and `elkjs` for every part, and, only in the panel webview, React 19, the shadcn/ui components with their Radix UI primitives, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react` and `cmdk`. A new runtime library enters only through the Specs.
- Layers: `src/core` holds the Model, Requirements, Proposals, Tasks, Drifts and Snapshot logic and must not depend on Bun, so the editor extension reuses it; `src/cli` is the command line; `extension/src` is the VS Code extension (a host running in Node, bundled as CommonJS, and a webview running in the browser, written in React with shadcn/ui components and Tailwind CSS 4).
- The command line is one standalone binary named `trama`, built with `bun build --compile`. The agent skills are embedded in the binary.
- Persistent project information is plain Markdown (with YAML front matter where needed) in a `.trama/` folder at the project root, versioned with the project's git. There is no database or network service; the extension's user-local question socket and transient discovery records are the exception to project-file storage.
- Trama non chiama mai un modello linguistico e non legge mai il codice del progetto: lo fa l'agente, attraverso la riga di comando. Non c'è più nessuna eccezione: il classificatore System 1 e `trama classify` sono rimossi.
- The extension is built on the VS Code extension API (engine `^1.106.0`) and is packaged as one `.vsix` per platform (`linux-x64`, `darwin-arm64`, `win32-x64`), each with the command-line binary inside. Tagged releases (`v*`) are built and published by a GitHub Actions workflow on Bun 1.4.0, which type-checks, runs the tests and smoke-tests the packaged binary.
- Ogni job del workflow della release ha un limite di 15 minuti (`timeout-minutes`): un blocco fa fallire il job invece di occupare il runner per ore. La suite di test non si blocca su nessuna piattaforma: un test che attende un processo, un file o una connessione finisce sempre, con successo o con un errore, anche con `bun test --isolate`.
- Windows: solo `win32-x64`, nessun pacchetto arm64. Il binario si chiama `trama.exe`. Il pacchetto Windows si costruisce e si prova su `windows-latest` con le stesse fasi degli altri: type-check, tutti i test e smoke test del binario estratto dal `.vsix` (`trama.exe --help`, `project new` e `model check`). I test sono portabili: non dipendono da `process.getuid`, `/tmp`, `sh`, link simbolici o `SIGTERM` su Windows; ciò che su Windows non esiste si salta solo lì, con il motivo scritto nel test.
- `trama.exe` non è firmato: la README dice che Windows SmartScreen o un antivirus possono avvisare al primo avvio. La riga di comando si distribuisce solo dentro il `.vsix`, come sulle altre piattaforme.
- Windows è in anteprima: la README lo dice accanto alle piattaforme finché la verifica manuale di `docs/uat.md` su Windows 11 x64 non passa con VS Code e omp, in Windows PowerShell 5.1, PowerShell 7 e Git Bash. Dopo quella verifica, le versioni provate di Windows, di VS Code, delle shell e di omp si scrivono qui, e l'anteprima finisce.
- Fine riga: ogni lettura di un file sotto `.trama/` e delle skill installate, ogni hash e ogni confronto di contenuto normalizzano CRLF in LF, in un solo punto di `src/core`; Trama scrive sempre LF. Un checkout con `core.autocrlf` non produce Proposal obsolete, conflitti di skill né riscritture a vuoto.
- Una scrittura atomica (file temporaneo rinominato sopra il file esistente, per esempio `.trama/short-numbers/assigned`, `.trama/last-scan/system` e i record del canale locale) che fallisce con `EPERM`, `EACCES` o `EBUSY`, come su Windows quando un altro processo tiene aperto il file, si ritenta per al più 1 secondo, poi dà l'errore. Il file temporaneo non resta su disco. Un solo aiuto in `src/core` serve tutte queste scritture.
- La scelta di supportare solo omp, in VS Code con l'estensione, è registrata in una nuova ADR in `docs/adr/` (la prossima numerazione libera), che dice cosa esce (Cursor come editor, la chat di Cursor con i suoi hook e l'Advisor della chat, `trama.agent`, il riconoscimento di `CURSOR_AGENT`) e perché, e sostituisce `0010-cursor-chat-agent-is-the-agent.md`, `0011-cursor-chat-and-omp-only.md` e le parti di `0012-acp-returns-for-omp-chat-only.md` che riguardano Cursor; quelle ADR restano, con una riga in testa che rimanda alla nuova. Le ADR già superate (0004, 0006) non si toccano. Il `CHANGELOG.md` registra la rimozione sotto `## Unreleased`, con `trama.agent`, `trama hook cursor`, `trama advisor review` e la vista di omp Chat nel pannello in basso tolti, e l'accensione predefinita di omp Chat con la sua approvazione.
- Agent skills live in `skills/` (trama-design, trama-scan, trama-compare, trama-implement, trama-import, trama-resolve-drifts) and are installed into the project's `.agents/skills` by default, or into the folder chosen with `trama.skillsDir`. `trama-compare` non avvia un lavoro: la usa chi confronta una Machine dentro `trama-scan` e `trama-implement`, ed è corta perché la legge ogni sotto-agente.
- Le skill distribuite che mostrano comandi con JSON su standard input o testo fra virgolette (`trama-design`, `trama-import`, `trama-resolve-drifts`, `trama-scan`, `trama-compare`, `trama-implement`) e `docs/cli.md` hanno una breve nota per PowerShell: passare il JSON con una pipe (per esempio `Get-Content -Raw round.json | trama question new --input -`) invece di `<` o di un heredoc; in Windows PowerShell 5.1 impostare prima `$OutputEncoding` e `[Console]::OutputEncoding` su UTF-8, perché altrimenti i caratteri non ASCII arrivano come `?`; non passare il JSON come testo di `--input`, perché Windows PowerShell 5.1 toglie le virgolette interne degli argomenti dei programmi esterni. Gli esempi restano in sintassi POSIX. Ogni comando che legge JSON da standard input accetta un BOM UTF-8 iniziale.
- Trama non avvia sotto-agenti e non ne conosce l'interfaccia: le skill dicono all'agente di usare i propri, quando li ha, senza nominare lo strumento di un agente preciso, e di fare lo stesso lavoro un passo alla volta quando non li ha. Il parallelismo resta nella stessa cartella e nella stessa corsa; non usa worktree e non apre altri terminali. `docs/` descrive `trama task list` con `runnable`, `max` e `scope`, e `## Scope` (lo scope dal vivo di `trama proposal show`), e non nomina più `trama.autoImplement`.
- `examples/shop` is a complete sample Trama project (Model and Requirements of an online shop) used by the demo scripts, the harness and the manual acceptance run; it is data, not part of the System.
- Trama non gestisce notifiche esterne e non integra servizi di notifica. Non effettua telemetria né chiamate di rete; resta il trasporto locale tra CLI ed editor.
- L'impostazione `trama.ntfy` e tutta la gestione dedicata alle notifiche esterne sono rimosse, senza un servizio sostitutivo né compatibilità per la vecchia impostazione. Le impostazioni utente esistenti non sono riscritte.
- La rimozione mantiene gli avvisi locali dell'editor e della Board, gli errori operativi, i round di domande, il rilascio dei Task e il ritiro degli annunci. Documentazione e verifiche non descrivono più le notifiche esterne come funzionalità supportata.
- Il multi-branch e il giro di worktree sono rimossi, senza un sostituto né compatibilità: Trama non ha più l'interruttore `Multi-branch`, non dichiara `trama.worktreeAgent` né `trama.multiBranch` e non crea, legge o elimina worktree, branch `trama/*`, Merge Drift o Task di riconciliazione. Accettare una Proposal la applica sempre nella cartella aperta.
- Ciò che resta da prima non è toccato: una cartella `.trama/multi-branch/` già presente non è letta né cancellata; un valore di `trama.worktreeAgent` già nelle impostazioni utente resta e non è letto; worktree e branch `trama/*` di un giro ancora aperto non sono guardati né eliminati, e le Proposal di quel giro sono semplicemente da decidere. Il developer li toglie a mano, con git.
- Documentazione, test e verifiche manuali non descrivono più il multi-branch e il giro di worktree come funzionalità supportata.
- L'assegnazione dei numeri brevi sta in `src/core`, così la riga di comando e l'estensione la condividono e dànno gli stessi numeri alla stessa copia di lavoro. `.trama/short-numbers/assigned` si scrive in un file temporaneo e poi lo si rinomina, così il pannello e un comando che girano insieme non leggono mai un file a metà.
- Con `--json` ogni comando che descrive una scheda porta, per ogni Proposal, Task e Drift, sia `id` (l'identità permanente) sia `number` (il numero breve come `T3`, o nessuno se la scheda è chiusa). Il testo normale mostra uno solo dei due, come in `ui`.
- Le skill `trama-design`, `trama-scan`, `trama-compare`, `trama-implement`, `trama-import` e `trama-resolve-drifts` dicono all'agente di nominare le schede al developer con il numero breve e il titolo («Task T3 – titolo») e di usare l'identità permanente, presa da `--json` o dal nome del file, in ogni comando e in ogni file che scrive. Non scrive mai un numero breve in un file.
- Le skill `trama-design`, `trama-setup`, `trama-scan`, `trama-compare`, `trama-implement`, `trama-import` e `trama-resolve-drifts` dicono all'agente di dare a ogni Proposal, Task e Drift che crea, e al suo annuncio, un titolo breve: un nome di al massimo cinque parole, circa 40 caratteri, non una frase che descrive il lavoro (per esempio «Testo fantasma» invece di «Descrivere Start from Scratch e guidare le richieste scritte con un testo fantasma»). Il dettaglio va nel corpo, anche se il titolo perde informazioni. Nessun comando controlla la lunghezza dei titoli. Restano come sono i titoli che le skill e Trama compongono da un altro titolo: il Task di correzione `Fix code to match the …`, `Import: <Feature>` e i titoli dei check. Le schede esistenti non si riscrivono.
- Le skill `trama-design`, `trama-setup`, `trama-scan`, `trama-compare`, `trama-implement`, `trama-import` e `trama-resolve-drifts` hanno nella sezione `## Language` (che `trama-setup` e `trama-compare` ricevono, se non l'hanno) la regola della prima persona di `rules#General`: nei testi che scrivono per Trama, Trama è «Trama» e mai «I» o «we». Le skill che scrivono Task (`trama-design`, `trama-setup`, `trama-scan`, `trama-compare`, `trama-implement`) dicono che il corpo di un Task si capisce senza la conversazione, come dice `rules#General`.
- Le skill distribuite `trama-design`, `trama-scan`, `trama-compare`, `trama-implement`, `trama-import`, `trama-resolve-drifts` e la definizione del sotto-agente `trama-analysis` sostituiscono il divieto assoluto delle decisioni del developer con la regola di `rules#General`: solo su richiesta esplicita nella conversazione. Non insegnano a togliere le variabili d'ambiente per aggirare un blocco. La documentazione dei comandi e delle decisioni non descrive più la guardia come protezione; gli ADR che la descrivono sono segnati come superati, mantenendo la loro storia.
- La forma di ogni comando di `trama`, il suo input e il suo `--help` seguono `cli#General`; `docs/cli.md` descrive `--help` e `--input`.
