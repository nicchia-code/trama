# Project

A folder that Trama is, or is not yet, set up in: whether it holds a Model, Requirements, Proposals, Tasks and Drifts, and the skills the agent needs.

## States

### Not a Trama project (initial)
The folder has no Trama files. Other actions point the developer to initialize it first. Dall'editor lo si fa aprendo Trama, che in una cartella così mostra Get Started con il wizard di setup (vedi il Setup wizard e il Panel).
- `developer.INITIALIZE_PROJECT` → Trama project: creates an empty Model whose description is a placeholder named after the folder, no Actors, the five starting Areas of Requirements (interface, technology, quality, data, business rules), places for Proposals, Tasks and Drifts, and installs the agent skills and the generated Requirement skills. Scrive anche, nella cartella degli agenti di omp del progetto, la definizione del sotto-agente di omp di Trama che confronta una Machine con il codice (analisi), e, nella cartella di omp del progetto, le istruzioni dell'advisor di omp per l'Advisor Scanner (vedi Agent launching), anche con l'Advisor Scanner spento. Ogni Area di partenza nasce senza frammenti: il primo lo scrive l'agente. Fails, creating nothing, if Trama files already exist in the folder. If an agent skill file already exists with different content, nothing is created until the developer confirms overwriting them; identical files are not a conflict. Lo stesso vale per una definizione del sotto-agente di omp o per istruzioni dell'advisor già presenti con un contenuto diverso da quello di Trama. Fra le skill installate c'è anche quella con cui l'agente risponde alla richiesta di setup. Dall'editor l'inizializzazione è la conferma del riepilogo del wizard di setup: inizializza la cartella scelta nel wizard, dopo averne salvato le impostazioni e quindi con la cartella delle skill scelta lì; a progetto creato, Import from Code chiede all'agente di descrivere il codice che esiste lasciando fuori le cartelle escluse nel wizard, e Start from Scratch apre la richiesta di setup del progetto, in cui il developer descrive l'applicativo da costruire (vedi la Design request). L'avviso per Start from Scratch su una cartella che contiene già file sta nel wizard e non è più un dialogo.
- `developer.INITIALIZE_PROJECT` → Not a Trama project: the developer declines to overwrite customised skill files, una definizione personalizzata del sotto-agente di omp o istruzioni dell'advisor personalizzate, or no folder is open: non si crea nulla e nessun agente parte. Dall'editor il wizard resta sul riepilogo (vedi il Setup wizard).

### Trama project
The folder is set up. Its skills may fall behind the version of Trama or the Requirements. Aprire Trama dall'editor le riporta in pari da solo; Update skills resta il modo esplicito.
- `developer.UPDATE_SKILLS` → Trama project: writes this version's agent skills, replacing older or edited copies, removes the skill of the Fix action that earlier versions installed (its folder, wherever it is found, whatever its content), creates the five starting Areas if the project has no Requirements folder at all, and regenerates the Requirement skills; reports what changed. Riscrive anche la definizione del sotto-agente di omp di Trama nella cartella degli agenti di omp del progetto, sostituendo copie vecchie o modificate senza chiedere, e rimuove la definizione del sotto-agente di smistamento che le versioni precedenti installavano. Allo stesso modo riscrive le istruzioni dell'advisor di omp per l'Advisor Scanner nella cartella di omp del progetto. Porta al formato a frammenti ogni Area scritta ancora come un file unico: il suo contenuto diventa un solo frammento di quell'Area, che l'agente dividerà la prima volta che una Proposal lo tocca; un'Area che ha già sia il file unico sia i frammenti non viene toccata e il resoconto lo dice. It never touches what earlier versions installed for the Copilot chat: whatever is left there stays as it is.
- `developer.OPEN_PANEL` → Trama project: every ordinary opening of Trama from the editor (the Open Trama command or the Reopen of the questions notice), also with the panel already open, and every side menu entry and every command Show Board, Show Diagram, Show Requirements, Show Specs, Show History, Show Team and Show Settings only when it opens the panel that was closed, checks in the background whether what Trama installs for the agent differs from this version: le skill dell'agente, la skill dell'azione Fix e il sotto-agente di smistamento che le versioni precedenti installavano, la definizione del sotto-agente di omp e le istruzioni dell'advisor di omp e le skill di Requisiti. Il pannello si apre subito, senza aspettare il controllo. Se qualcosa è diverso lo porta in pari come Update skills, sostituendo senza chiedere anche le copie modificate a mano, e un avviso breve dice che le skill sono state aggiornate; se è tutto in pari non dice nulla. Non porta al formato a frammenti le Aree scritte come file unico e non crea le Aree di partenza: restano a Update skills. Se il controllo o l'aggiornamento fallisce, un avviso di errore ne dice il motivo, a ogni apertura finché il problema resta. L'apertura automatica del pannello per un round di domande non controlla nulla. A side menu entry or a Show command that only brings the open panel forward, or moves it to another view, checks nothing: the view changes at once.
- `workspace.REQUIREMENTS_CHANGED` → Trama project: after a short pause regenerates the Requirement skills, whether or not the Trama panel is open. If that fails the developer is told. Se le skill dei frammenti superano o tornano sotto il budget dell'elenco, le Aree passano tutte insieme da skill per frammento a skill indice, o viceversa.
- `proposal.APPROVED` → Trama project: regenerates the Requirement skills, so the agent sees the Requirements the Proposal changed, passando a skill indice o tornando a skill per frammento allo stesso modo.
- `developer.REWRITE_IDENTITIES` → Trama project: il developer dà un'identità propria a ogni Proposal, Task e Drift ancora numerati. La stessa scheda riceve la stessa identità su ogni copia che parte dallo stesso numero, e un istante di creazione che conserva l'ordine di quei numeri, non l'ora del comando. I riferimenti fra queste schede seguono le identità nuove. Lo stato di ciascuna scheda non cambia e non nasce nessun commit. È rifiutato, senza cambiare nulla, quando due schede dello stesso tipo condividono già un numero, o quando due identità nuove coinciderebbero. Se non c'è nessuna scheda numerata, non cambia nulla.
