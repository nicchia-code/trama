# Regole di Task e annunci

## task
- A Task that is not technical must reference at least one Model element, and may add Requirements. A Technical Task must reference no Model element, only Requirements if any. Every reference must resolve to an existing Model element or Requirement section when the Task is created.
- Any move between the three columns is allowed, in either direction, from the command line (and always for the agent). The Board offers no move at all: it sends none and the editor accepts none, whether by drag, by buttons or by message.
- A Task may be linked to a Proposal when it is created; the Proposal must exist, in any status. Tasks that carry no link are never grouped.
- Design grouping: the Tasks linked to the same Proposal form one design, listed in the order they were created. A design with fewer than two Tasks is not shown as a group. The column of a design is derived: To do when every Task is in To do, Done when every Task is in Done, In progress in every other case (including a mix of To do and Done).
- A Task is runnable when it is in To do and not blocked. The next runnable Task is the oldest runnable Task in creation order, worked out again each time it is asked: a Task that waits for the Task that fixes its Drift becomes runnable once that Task is Done, so the fixing Task runs first and the waiting one right after it. No other order is imposed between Tasks.
- A run (Run all To do, or implementing a design) asks for the next runnable Task, implements it, and asks again, until there is none. Run all To do considers every Task; implementing a design considers only that design's Tasks, so a fix Task, which belongs to no design, is never run by it. A run skips the Tasks that are blocked and goes on past a Drift: the Drift the agent files during the run leaves its Task In progress, blocks only the Tasks it concerns, and does not end the run. A run ends when no Task is runnable. Its report says what the agent implemented, the Drifts it filed, and the Tasks in To do left unrun, each with the Drift or the fix Task it waits for.
- Asked to implement one named Task, the agent still stops at once if that Task is blocked (see below): the order and the skipping apply only to runs over several Tasks.
- The agent takes a Task when it moves it to In progress with the command line run in the terminal Trama started for the agent (the one marked with `TRAMA_AGENT`). A move by the developer never takes a Task, and neither does a move made by an agent outside that terminal, which cannot be told from the developer's. Moving a taken Task to To do or Done, by the agent, clears the mark; moving it to In progress again keeps it.
- A Task taken by the agent cannot be moved by the developer: not with the command line run without `TRAMA_AGENT`. The Board has no way to move a Task. The refusal says the agent is working on it and points to `task take-back`. Moves by the agent are always allowed.
- Taking a Task back is a decision of the developer: it clears the mark, leaves the Task In progress and is refused to an agent. It has a command, `task take-back <id>`, refused when `TRAMA_AGENT` is set. The Board has no button for it.
- When the command running in the agent terminal ends, every Task that carries the mark is released and goes back to To do, so it can be run again. A Task is not released if the terminal cannot report that a command ended; then only `task take-back` frees it.
- Run all To do is unavailable while any Task is taken by the agent, and when no Task in To do is runnable. Run this design is unavailable while any Task of that design is taken, and when none of the design's Tasks in To do is runnable.
- A Task is blocked when an open Drift blocks it or when it is the origin of a Drift fixed in the code and the Task created for that fix is not Done. A Done Task is never blocked. Blocking is derived from the Drifts, the Tasks and their references each time it is asked; it is never stored on the Task.
- An open Drift blocks its origin Task, if it has one, and every Task that is not Done and concerns the same thing as the Drift. A Drift filed by a Scan has no origin. A Task concerns the same thing as a Drift when one of their references is the same as one of the other's or inside it: an element contains its States and Transitions, and a Machine or Feature contains its Machines and States. A Requirement section of an element also counts as that element, and the element and everything inside it as that section. The General section of an Area is equal only to itself, so it concerns only the Tasks that name it. This holds for Technical Tasks, which have only Requirement references.
- Moving a blocked Task to In progress is refused to the agent, whatever its column, and so is keeping a blocked In progress Task with another move to In progress. The refusal names the Drift that blocks it (ID and title), or the fix Task it waits for. Moves of the developer, and moves of the agent to To do or Done, are not affected. A blocked Task already In progress is not moved.

## announcement
- An announcement has a kind (Proposal, Task or Drift) and a title. The kind decides the column of its ghost: To decide for a Proposal or a Drift, To do for a Task.
- The agent announces a card as soon as it knows it will create it, saying the kind and the title, and gets the announcement's ID back. It passes that ID when it creates the card: when it starts the Proposal, files the Task or files the Drift. Creating a card without announcing it is allowed; it simply has no ghost.
- Trama announces a Proposal for every design request sent from a terminal launcher (integrated or external), at the moment the instruction is actually sent; its title is the developer's request (for a written design request, its title as defined for the Design request), or "Rework of Proposal <p>" when the request is to rework the stale Proposal of a Drift, and it belongs to the terminal the instruction is typed into. The agent is not told this announcement's ID: the first Proposal the agent starts without naming an announcement takes over the oldest of these still Preparing, and the Draft's title replaces the request in the ghost.
- A Proposal the agent starts that names no announcement, with none of these waiting, makes an announcement of its own, titled like the Draft and already Writing. This is how a design sent with the chat launcher gets its ghost.
- The announcement is delivered when the card arrives: a Proposal when it is handed over (never when the hand-over is refused, which leaves the ghost), a Task or a Drift when it is filed with the announcement's ID of the same kind. An ID that is unknown, already delivered or withdrawn, or of another kind never prevents the card from being created; the output says that no such announcement was found.
- An announcement that belongs to an agent terminal is withdrawn, with the notice, when the command Trama typed into that terminal ends or that terminal is closed. The end of any other command, in that terminal or in another one, and the close of another terminal, withdraw nothing. When the terminal cannot tell that the command that ended is the one Trama typed, its end withdraws nothing; the close of the terminal and the quiet period still do.
- Every announcement still waiting, whatever terminal it belongs to, is also withdrawn, with the notice, when fifteen minutes pass without the agent announcing a card, changing a Draft it announced or filing a card. The fifteen minutes stop counting while a question round is open and start again when it closes. This is the only way, besides the editor starting up, that an announcement with no terminal is withdrawn.
- An announcement whose Draft the developer discarded is withdrawn at once, with no notice. A Draft that returns to Draft after being handed over does not bring its ghost back.
- Starting up, the extension withdraws every announcement it finds left on disk, with no notice, since the agent run that made it can no longer be told.
- A delivered or withdrawn announcement ceases to exist at once.
- Un annuncio fatto dall'agente della chat di Cursor (campo `chat`) è ritirato, con l'avviso, quando una conversazione di Trama dello stesso progetto è interrotta (`cursor-chat.AGENT_INTERRUPTED`), e senza avviso quando è chiusa (`cursor-chat.CONVERSATION_CLOSED`). Un turno concluso normalmente (`cursor-chat.AGENT_STOPPED`) non ritira nulla: ci pensano la consegna della carta o i quindici minuti di quiete.
