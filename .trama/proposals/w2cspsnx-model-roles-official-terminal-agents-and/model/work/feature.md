# Work

The work that comes out of comparing the Model with the code, shown on the Board. Un Task o un Drift nuovo non prende l'identità da un contatore condiviso: ne ha una propria, così due branch che lo creano non si assegnano la stessa. A Task is a unit of work for the agent that the developer can see and ask the agent to run, but not move on the Board. A Drift is a difference between code and Model, or between code and Requirements, that only the developer can decide on. While the agent is preparing a card, an announcement lets the Board show a ghost of it.

Ogni Task e ogni Drift vivo ha, accanto all'identità permanente, un numero breve temporaneo (`T3`, `D3`) per leggerlo e citarlo a colpo d'occhio: è locale a ogni copia di lavoro e si libera quando la scheda si chiude. Un Task che fa parte di un design lo tiene finché non è finito tutto il design.

Ogni scansione, anche quella alla fine di una corsa di implementazione, smista prima le Machine del suo ambito, una alla volta: per ciascuna si decide soltanto se il codice è in conflitto con il Modello e i Requisiti che la riguardano. Decide il classificatore System 1, quando il developer l'ha acceso e l'editor risponde, altrimenti un sotto-agente sul modello di esecuzione. Una Machine senza conflitto non produce né Task né Drift e non è analizzata oltre. Una Machine in conflitto passa a un sotto-agente sul modello di analisi, che la confronta a fondo e archivia Task e Drift come sempre. Nel dubbio vince il conflitto: una risposta incerta o un classificatore che non riesce a rispondere mandano la Machine all'analisi. Con un agente che non sa dare un modello ai suoi sotto-agenti, smistamento e analisi restano sul modello della corsa e il resoconto lo dice. Il resoconto della scansione dice anche, in una riga, quante Machine sono state saltate e quante analizzate, e chi ha smistato.
