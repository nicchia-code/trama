# Dati di Task e Drift

## task
- One file `tasks/<id>-<slug>.md`. Front matter: `column` (`todo`, `doing` or `done`; default `todo`), `technical` (true or false; default false), `refs` (list of element or Requirement references), `drift` (ID of the Drift it resolves, or none), `proposal` (ID of the Proposal, the design, the Task comes from, or none; absent in Tasks written before this field existed), `agent` (who has taken the Task while the agent has taken it: the ID of the agent terminal that took it, or `cursor` when the agent of Cursor's chat took it, or `true` when it was taken without a known terminal or chat; `false` otherwise; default false, so Tasks written before this field existed are free; a Task marked `true` is released by the end of any agent terminal or of the chat), `created` (istante di creazione in UTC, ISO 8601; assente nei Task numerati scritti prima di questo campo), `finished` (istante in UTC, ISO 8601, in cui il Task è arrivato in Done da un'altra colonna; uno spostamento da Done a Done non lo cambia, uno spostamento fuori da Done lo toglie; assente nei Task arrivati in Done prima di questo campo). The H1 is the title; the body says what must be true when done, in domain words.
- Il front matter del Task contiene anche `unchanged`: il testo della nota con cui il Task di correzione è stato chiuso senza modifiche, oppure nessuno. Si scrive solo arrivando in Done con la chiusura senza modifiche e si toglie appena il Task lascia Done; è assente nei Task scritti prima che esistesse e in quelli chiusi normalmente. Solo un Task con `drift` può averlo.
- To decide della Board mostra Proposal aperte (mai Draft) e Drift aperti. Le Proposal allegate a un Drift aperto, nominate nel suo campo `proposal`, non compaiono a sé. Per ogni Proposal aperta con `kind: resolution`, i Drift aperti nominati in `drifts` compaiono solo dentro la sua scheda, non come schede separate. Si calcola dai file già esistenti, senza nuovi campi né stato persistito: una risoluzione Draft, rifiutata o scartata non nasconde nessun Drift. Il conteggio della colonna e della tab Board è quello delle schede visibili: una risoluzione conta una volta; i Drift raccolti al suo interno non contano di nuovo. La lista completa dei Drift nella Snapshot resta invariata per Diagramma, blocchi dei Task e comandi della riga di comando.
- Il ricordo dell'ultimo scan globale è una cartella `.trama/last-scan/`, locale a questa copia di lavoro e non versionata, con un suo `.gitignore` che ignora tutto ciò che contiene (il testo `*`), scritto insieme al primo file. Il file `system` contiene l'istante dell'ultimo lancio dello scan di tutto il Sistema dal pulsante Scan la cui istruzione è stata consegnata, come data e ora, con al più un a capo finale. Cartella o file assenti: l'estensione scrive il file con l'istante corrente la prima volta che lo cerca, così il conteggio parte da zero. Un file che non si legge come data e ora vale come assente ed è riscritto allo stesso modo. Il numero mostrato sui pulsanti Scan è il numero di Task con `column: done` il cui istante di arrivo in Done è dopo l'istante del file; un Task Done senza istante non conta.

## drift
- One file `drifts/<id>-<slug>.md`. Front matter: `status` (`open` or `resolved`; default `open`), `resolution` (`fix-code`, `proposal` or `dismissed`; none while open), `refs` (list of element or Requirement references), `proposal` (ID of the attached Proposal, or none), `task` (ID of the Task created when resolved as fix-code, or none), `origin` (ID of the Task the agent was implementing when it filed the Drift, or none; absent in Drifts written before this field existed, which have no origin), `option` (number, counted from 1 in the order of the Fix options section, of the option the developer chose when resolving as fix-code; none otherwise and in Drifts without options), `note` (the developer's note given with that choice, or none), `resolvedBy` (identità della Proposal di risoluzione che ha risolto il Drift, o nessuna; assente nei Drift risolti in altro modo e in quelli scritti prima che esistesse) e `created` (istante di creazione in UTC, ISO 8601; assente nei Drift numerati scritti prima di questo campo). The H1 is the title. The body is Markdown with three required sections, in this order: `## What happens`, what the code does today, `## What should happen`, what the Model or the Requirement says, and `## Fix options`; then `## Where in the code`, with the places where the difference was seen, obbligatoria nei Drift nuovi. `dismissed` vuol dire che né il codice né il Modello sono cambiati: il developer ha tenuto il codice senza una Proposal allegata, lo ha deciso una risoluzione, oppure il Task di correzione è stato chiuso senza modifiche (vedi sotto). Un Drift risolto da una risoluzione ha `resolution`, `option`, `note` e `task` come se il developer l'avesse risolto dalla riga di comando con la stessa decisione.
- Il front matter del Drift contiene anche `critical`, booleano: `true` soltanto quando è urgente una posizione del developer, `false` negli altri casi. Un Drift nuovo scrive sempre il campo; nei file precedenti l'assenza vale `false`, senza riscriverli. Un valore presente non booleano è un errore di lettura, non una classificazione automatica.
- Che un Drift aperto stia in una Proposal di risoluzione da decidere non è scritto nel Drift: si calcola dalle Proposal ancora in scrittura o aperte.
- `## Fix options` holds from two to five options, each a `###` heading with the option's title followed by its text, a Markdown description of that way to fix the code and what the developer gets from it. The first option is the agent's recommendation. Titles are unique within the Drift. The options are not part of the Model or of what a Requirement says: they only describe ways to reach what should happen.
- A Drift is not part of the Model, so the `## Where in the code` section may name files and code elements. Ogni Drift nuovo ha questa sezione, con testo; i Drift scritti prima che fosse obbligatoria possono non averla e restano come sono. The required sections are written at the level of behaviour (see the rules of the Drift) and name no code locations. Drifts written before the sections existed may name code locations in What happens; they stay as they are.
- Drifts written before the Fix options section existed have none: if they are Open the developer fixes their code without choosing an option; `option` and `note` stay empty.
- Resolved Drifts written before the two sections existed keep their free body; they are shown as one block.
- Il front matter del Drift contiene anche `previous`: l'identità del Drift precedente di cui questo è il seguito, o nessuna. Un Drift con `previous` è ricorrente. Si scrive alla creazione e non cambia più; è assente nei Drift scritti prima che esistesse, che non sono ricorrenti, senza riscriverli.
- Un Drift nuovo senza correzione del codice possibile non ha la sezione `## Fix options` e ha sempre `proposal`; `option` resta vuoto.
- Un Drift dismesso dal suo Task di correzione chiuso senza modifiche ha `resolution: dismissed` e conserva `task`, `option`, `note` e `resolvedBy` com'erano dopo la scelta di correggere il codice. Non ha un campo nuovo: un Drift `dismissed` con `task` presente è per forza stato chiuso dal suo Task, e la nota della verifica si legge nel campo `unchanged` di quel Task, finché il Task resta Done.
