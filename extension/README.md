# Trama for VS Code

Shows the Trama Model of your project (`.trama/model/`) as a read-only Diagram, its Requirements (`.trama/requirements/`) in a read-only Requirements tab, and a Board of Proposals, Drifts and Tasks. The Board is read-only for Tasks: it offers no arrows, dragging or Take back button, and the editor accepts no message to move a Task or take it back; moving a Task and taking it back stay in the command line (`trama task move`, `trama task take-back`). Descriptions, Requirements, Proposal bodies, Task bodies and Drift texts are shown as Markdown. You never edit the Diagram: you ask your coding agent, then approve or reject its Proposals. Requirement files you may also edit by hand; the extension regenerates the `trama-req-*` agent skills whenever they change.

Il filtro Done usa giorni locali: `Today`, `Last 7 days` e `Last 30 days` includono oggi e rispettivamente zero, sei o ventinove giorni precedenti, fino alla mezzanotte successiva esclusa, anche al cambio dell'ora. Le schede finite nei giorni futuri non compaiono né entrano nel contatore; `All` le mostra e conserva in fondo il gruppo `No date`.

- **Trama: Open** opens the panel on the Diagram tab, whose tabs are Board, Diagram, Requirements and Settings. In a folder without `.trama/` it opens on Get Started instead, where you choose **Import from Code** or **Start from Scratch** to set the project up.
- **Trama: Scan System** and the Scan and Run buttons send a prompt to your agent. Design requests start only from the Board's **Add Work Item…** button, and, while the Model is empty, from the Diagram's **Import from Code** and **Start from Scratch** buttons under its empty-Model text, which links to the Board.
- The **Add Work Item…** button and the Board's **+ Work Item** create an empty file `.trama/requests/<id>.md`, named after the local date and time (for example `2026-10-04T19-05-12.md`, with `-2`, `-3`, … when taken), and open it in a tab where you write a design request at length. The folder has its own `.gitignore`, so requests are never versioned. Trama saves the file by itself shortly after every change, whatever `files.autoSave` says, so closing the tab never asks to save. **Send to agent** in the editor title (or closing the tab) sends the agent `Use the trama-design skill on the design request in .trama/requests/<id>.md. …` and closes the tab; with the terminal launcher the ghost on the Board takes the request's title. An empty text sends nothing: **Send to agent** warns, and closing the tab deletes the file silently. If the instruction does not leave (for example you cancel the agent command prompt), the request stays on disk unsent; reopen it from the Explorer to send it. A request is sent once: Trama remembers the sent ones across restarts, and a sent request reopened can be edited but has no **Send to agent**, and closing it sends nothing. Closing the editor window sends nothing either. The agent binds its first Proposal to the request, and handing that Proposal over deletes the file; its tab closes unless it has unsaved changes.
- An empty request tab shows a grey ghost text saying what to write and how to send it (Send to agent, or closing the tab). It is only on screen, never saved or sent, and it disappears at the first character; a request already sent shows none.
- **Trama: Import from Code** asks your agent to describe the existing code as Proposals (a first one for the System and its Actors, then one per Feature, each requiring the first). They describe the code as it is and list their doubts; approving them starts no Scan.
- **Trama: Update Agent Skills** installs this version's skills into the project, adds the starting Requirement Areas to projects created before they existed, converts Areas still written as one file `requirements/<area>.md` into a folder with `area.md` and `main.md`, and regenerates the Requirement skills; its notification says which Areas it converted or left, and the mode of the Requirement skills (one per fragment, or one index per Area).

Le modifiche, aggiunte e cancellazioni nei Requisiti rigenerano automaticamente le skill del progetto della cartella modificata, anche con il pannello chiuso. Nei workspace con più cartelle ogni progetto ha una pausa breve indipendente; un errore di rigenerazione viene mostrato al developer.

Cards are named on the Board, in the panel and in the buttons by their **short number**: `P3` for a Proposal, `T3` for a Task, `D3` for a Drift. The number is temporary and belongs to this working copy (it is kept in `.trama/short-numbers/`, which is never versioned), so another copy or worktree may give the same card another number; a card that is closed (a decided Proposal, a resolved Drift, a Task in Done) has no number and shows its permanent eight-character identity instead, never both. The two look alike, in the same place and font, and are told apart by the tooltip and accessible name, **Short number (temporary)** or **Permanent ID**. Everything Trama writes into files, branches and instructions to the agent uses the identity. The command line accepts the number too (`trama task move T3 doing`); see the [CLI conventions](https://github.com/nicchia-code/trama/blob/main/docs/cli.md#conventions).
Choose where prompts go with the application-scoped `trama.agent` setting, for every project and instruction:

- `chat` (the default): Copilot Chat in VS Code or Cursor's chat in Cursor.
- `omp`: starts `omp` in a new integrated terminal.
- `claude`: starts Claude Code in a new integrated terminal.

`trama.terminalLocation` applies to `omp` and `claude`: `panel` (the default) creates the terminal in the terminal area without showing it; `editor` opens it as a tab in the active editor group without taking focus. Only the user value `editor` selects a tab; an absent or unrecognised value uses the terminal area. Existing values for removed settings are ignored and never rewritten.

Every instruction uses the current setting, including import and project initialization. No first-launch prompt, custom commands or other terminal agents are supported. Terminals are never reused.

Agents run the `trama` CLI, so it must be on their `PATH`. `trama.skillsDir` is where Get Started installs the agent skills (`.claude/skills` for Claude Code).

The delegation is one menu, `trama.driftAutoPilot`, with three values: `disabled` (the default: you decide on every Drift), `enabled` (the agent recommends, approves and fixes non-critical Drifts on its own) and `yolo` (also critical Drifts). It is an application-scoped user setting, read only from your user settings. It never skips the host's normal approval checks. The resolution agent submits a restricted Proposal; only the host approves it, then may start a separate Run limited to that resolution's fix Tasks and incomplete origins. The host coordinates Trama scans and Runs across project windows. `trama drift autopilot` reports the mode, the phase, the reason of any wait and whether work is active in another window; the Board has no autopilot status line. A failed or excluded Drift or Task card carries an `autopilot failed` badge whose tooltip gives the reason. Scans started outside Trama are not included. Failed cases stay excluded until a successful developer-started scan, a Drift edit, or an explicit Resolve Drifts request. Automatic cycles have no additional time, cost, or cycle limit, so set the delegation to `disabled` or interrupt work to stop further steps. Manual exceptions remain for developer intervention.

`trama.submitWhileRunning` is a checkbox, `false` by default. With `false`, Run all and each Task's Run are unavailable while a run started by Trama is not finished: its end-of-run scan included, and the runs of other windows of the same project when the autopilot coordinator is active. With `true`, a run can start while another one is in progress. Any value that is not a boolean (for example the former text `disabled` or `enabled`) counts as `false` and is never rewritten. It applies in your user and workspace settings.

`trama.language` is the language the agent writes in, typed as free text (`Italian`, `Deutsch`…) and empty by default. When it is set, every instruction Trama sends to the agent ends with `Write everything you generate in <language>, except code, which always stays in English.` That covers the text the agent writes for Trama; code, comments, commit messages, project documentation, names and titles, IDs, Event names and required section titles stay English. The setting is read at each launch, changes nothing already written and is not saved in the project.

On the first start of the extension in an editor, when you have no `trama.language` in your user settings, Trama detects it: the language of your operating system (`LC_ALL`, `LC_MESSAGES`, `LANG`), else the editor's language, else `English`, and saves its English name (`Italian`) in your user settings. It happens once per editor; a value you already have, or one you clear later, is never changed again.

`trama.maxParallelAgents` is an application-scoped number, default 20 and minimum 1. It tells the agent how many sub-agents to run at once in a scan, design exploration and Task run; agents without sub-agents ignore it. Empty, non-integer or less than 1 values use 20. The same value appears in each instruction and in `trama task next --batch --max <N>` for implementation runs. Workspace settings do not override it.

The Settings tab of the Trama panel lists every `trama.*` setting in groups (Agent, Models, Drift autopilot, Runs, Project, Experimental), with its title and explanation. Choose a value there and it is saved at once in your user settings, never in the workspace's; a text field saves when it loses focus or on Enter, and an empty text or the default value removes the value from your user settings. The Drift autopilot group has one menu, Delegation (`disabled`, `enabled`, `yolo`), which writes `trama.driftAutoPilot`. Raising the delegation asks first in a modal question, and cancelling saves nothing. A workspace value that overrides a setting is shown under its control.

The Experimental group holds `trama.experimentalDriftBlocker`, a checkbox, off by default and application-scoped. Experimental: on, the agent that files a Drift checks which Tasks it would block are really affected, blocks only those and explains why it leaves the others free; a Drift that blocks no Task is filed inside a resolution Proposal for you to approve. Off, a Drift blocks every Task that concerns the same thing. Only agents started by Trama follow it.

## Terminal agents and model roles

There are two terminal agents: omp (`omp`) and Claude Code (`claude`). Each instruction uses the model role that matches its work; empty roles leave the agent's default model:

- `trama.analysis`: design requests (written), Resolve Drifts and import.
- `trama.scan`: scans of the System and Features.
- `trama.execution`: implement and implement all, including the final selective scan of the run.

For instructions that can scan, both terminal agents receive the `trama-analysis` sub-agent sentence. omp gets `--slow <scan>` when `trama.scan` is set; Claude Code gets `--agents` with the scan model when set.

The chat (`chat`) takes the same roles. In Cursor, the role's model starts the new conversation only, with Max mode off; the other chats keep their model. In Copilot, Trama picks the first model named like the role (`<name> (<vendor>)`, or `<name>` for Copilot's own models), selects it for the new conversation and keeps it in the chat's picker. If no model has that name, the instruction is sent with the chat's model and a warning says so. Chat instructions that can scan carry the sub-agent sentence too. Get Started and Update Agent Skills write the chat's user definition of `trama-analysis` (`~/.cursor/agents/` in Cursor, `~/.copilot/agents/` in Copilot) with the current `trama.scan`, so a change of `trama.scan` reaches the chat's sub-agent only after Update Agent Skills.

## Cursor

Cursor is supported like VS Code (tested on 3.22.12 and 3.23.12), in the editor window; Cursor's Agents Window is not supported.

- **Delivery.** The chat launcher tries, in order, and moves on silently when a step is missing or fails: a new chat that sends the prompt by itself (Cursor's internal `composer.createNew`); the prompt deeplink, which opens a chat that waits for your confirmation and Enter (skipped when Cursor would refuse the text: empty, over 10,000 characters encoded, or naming `.env`); the clipboard, with a notice to paste it. No step is tried twice for the same prompt. The new chat counts as sent whenever Cursor raises no error (the command never returns anything), and Trama does not check afterwards that the chat really sent the prompt.
- **PATH.** Cursor runs its agent's commands without the PATH the extension gives the editor's terminals, so every instruction to Cursor's chat has a second line telling the agent to `export PATH="<folder of the bundled trama>:$PATH"` (absent when the package has no binary for the platform).
- **The agent.** Cursor sets `CURSOR_AGENT=1` in its chat agent's shell, and the CLI treats it as `TRAMA_AGENT` (ADR 0010): the developer's decisions are refused, a move to In progress takes the Task, and announcements made there carry `chat: cursor`.
- **Hooks.** In Cursor, **Get Started** and **Update Agent Skills** write Trama's entries for `beforeSubmitPrompt`, `stop`, `sessionEnd` and `afterShellExecution` into your own `~/.cursor/hooks.json` (never the project's), each running `"<bundled trama>" cursor-hook`; the shell-command entry carries `"matcher": "trama"`, so Cursor runs it only for command lines containing `trama`. Update rewrites them for the new version's path, and activation leaves the file alone when its entries are already these. Other entries are kept; a file that is not valid JSON is left alone and you are told. The hook passes each editor window of the project only the event, the conversation and the project folder, never the prompt or a command line, never blocks Cursor, and gives up after one second for a prompt or five seconds for the other hooks.
- **Fine di un turno.** Una conversazione è di Trama dal primo prompt che inizia con `Use the trama-` o `/trama-`, chiunque lo scriva. Quando un turno viene interrotto o fallisce, i ghost annunciati dalla chat di Cursor vengono ritirati con il consueto avviso locale; chiudere la conversazione li ritira senza avviso, mentre una fine normale li lascia alla consegna della scheda o al periodo di inattività. Ogni fine di turno, normale, interrotta o fallita, e la chiusura della conversazione riportano a To do tutti i Task presi dall'agente nel progetto (si presume un agente alla volta); l'agente riprende un Task quando riparte.
- **Domande.** `trama ask` dalla chat agente di Cursor raggiunge la finestra del progetto attiva più di recente e apre il normale overlay locale. Nella sandbox di Cursor le skill riprovano una sola volta un `trama ask` inizialmente `unavailable` al di fuori della sandbox e continuano ad attenderlo anche quando Cursor lo sposta in background.

## Agent questions

Agents ask with `trama ask --root <project>`, which accepts the JSON request on stdin; see the [request and result contract](https://github.com/nicchia-code/trama/blob/main/docs/cli.md#question-rounds).

The active round opens immediately as an overlay inside the Trama panel, which comes to the front (or opens) over whatever tab it shows. The header names the agent and the step (`Question <n> of <total>`); an index on the left lists every question with its state (**Answered**, **Skipped**, **Missing**) and ends with **Summary**, and below 600 px it becomes a row of numbered dots. The question, its context, the option descriptions and their **Show details** are Markdown. The recommended option is chosen on the first visit; keys 1–9 pick an option; **Your answer (optional)** takes free text, alone or beside the chosen options. **Next** confirms and moves on (**Review** on the last question), **Back** and the index move without confirming, **Skip** skips one question.

The **Summary** shows every answer, with **Edit** to reopen a question, and **Send to agent** delivers the round once nothing is missing. **Skip all**, and the **Close** button, ask first (`Skip all unanswered questions?`) and then deliver at once, the agent using its recommendation for each skipped question. **Minimize** shrinks the round to a bar at the top of the panel with **Open questions**; closing the panel with a round open shows `Trama has questions from the agent waiting.` with **Reopen**. Esc and focus loss do nothing.

Each window has one FIFO shared by every `trama ask` caller, with no response deadline. Caller cancellation removes only that round. Closing the window, losing its channel, or removing its project interrupts every admitted active and queued round with `editor-interrupted`, disposes the controls and returns no partial answers. The agent must stop its workflow without fallback or retry. Initial editor absence instead returns `unavailable`, allowing its own question interface.

Local discovery chooses the most recently focused live window for the project unless a launching endpoint was supplied. Its records contain no question content and stay outside the repository. Unix sockets and Windows named pipes are user-private; Windows requires its built-in Windows PowerShell 5.1/.NET Framework bridge, not an additional runtime library.

The extension never calls a language model. The agent performs scans directly, comparing each Machine with the Model and Requirements.
