# Requirements: Tecnologia e vincoli, PR Check

Use when building the PR Check: its core module, the git and gh calls, the host that runs it, the launch in a worktree, the messages and the Pull Requests tab.

## pr-check

- Hidden for now (`rules#pr-check`): `src/core/pr-check.ts`, `readPullRequests` of `src/core/github.ts`, `extension/src/host/team/pr-check.ts`, `extension/src/host/team/pull-requests.ts`, `pull-requests-tab.tsx`, `pull-request-report.tsx`, the `prCheck` launch and their tests stay in the code, unchanged as far as possible. What hides it: `teamTabs`/`TEAM_TABS` of `extension/src/webview/team/logic.ts` have no `pull-requests` tab; the host's read of GitHub (`readGitHub`) calls neither `readPullRequests` nor `deleteReportsExcept` and sends no `pullRequests` message; the dispatch of `checkPullRequest` and `stopPullRequestCheck` in the controller ignores them; `removeLeftoverWorktrees` at activation stays. The tests that pin the `Pull Requests` tab or the Team view without Manager mode are rewritten for the hidden PR Check; the unit tests of the PR Check's modules stay.
- Core: `src/core/pr-check.ts`, with `bun:test` tests on real temporary git repositories, holds the pure logic and the git work: the choice of Solo or Collaborative, the fetch and the commits read from `FETCH_HEAD`, the merge-base, creating and removing the worktree, copying Trama's own files (`rules#pr-check`), Trama's own checks of the report and the building, reading, writing and deleting of reports (`data#pull-request-report`). Every git call goes through `src/core/git.ts` with fixed arguments and no shell; `git fetch` has a time limit of 120 s, the others the helper's limit. A pull request number is a positive integer and a branch name that starts with `-` is refused.
- Trama's checks reuse the code that already exists: the changes element by element of `trama proposal show` for the `Model` rows, the validation of `trama model check` for the errors, the reading of Proposals, Tasks and Drifts of `src/core` for the approved Proposals and the open cards. The Model at the merge-base and at the commit of the branch it goes into is read from git objects (`git show <commit>:<path>`, `git ls-tree`), never by checking them out.
- GitHub: the list of pull requests is a read-only call of `src/core/github.ts`, with the same runner, time limit and errors as the reads of Team (`tech#issue`); the test that `src/core/github.ts` holds no command that writes covers it.
- Host: `extension/src/host/team/pr-check.ts` runs the PR Check for the window: it holds the running PR Check (`data#pull-request-check`), refuses a second one, prepares the worktree, launches the job, follows its end and its Stop, writes the report and removes the worktree, and removes the leftover worktrees at activation. Every failure is shown with the messages of `ui#pull-request-check`.
- Launch: `AgentAction` (`extension/src/protocol.ts`) gains `{ kind: "prCheck", number: number }`, which the panel cannot send. It goes through the same `send` as the scan of `Scan System`, without `confirmScanSystem` and without `rememberDeliveredScan`, with the working folder of the terminal or of the conversation set to the worktree, the scan role, the name `PR #<n>` and the announcement of a work titled `Checking PR #<n>` in the open folder. Its end is followed like the end of a work (`tech#announcement`).
- The `trama` commands of the agent of a PR Check work on the worktree, the folder they run in; the editor answers its question rounds as for any job of the window.
- Messages, webview → host, validated by `parseToHost`: `checkPullRequest { number }` and `stopPullRequestCheck { number }`. `Open on GitHub` uses the existing message that opens a link.
- Messages, host → webview: `pullRequests { readAt, error, items: PullRequestView[], running: number | null, blocked: "running" | "run" | null }` at the `ready`, whenever the Team view becomes visible, after every read and at every start and end of a PR Check. `PullRequestView` is the item read from GitHub plus `report: { checkedAt, variant, head, mergeBase, outdated, rows } | null`.
- Webview: the `Pull Requests` tab lives in `extension/src/webview/team/pull-requests-tab.tsx`, its report window in `extension/src/webview/team/pull-request-report.tsx`; the ordering, the outdated mark, the grouping of rows by section and the reasons of a disabled `Check` are pure functions of `extension/src/webview/team/logic.ts`, tested without DOM. The table uses the shadcn/ui `Table` and `Dialog`, copied in `extension/src/webview/ui/` when missing.
- While the PR Check is hidden, `README.md`, `extension/README.md`, the website (landing page and guide) and `docs/` do not describe it (`gh` is needed only for Team); `docs/uat.md` keeps its section AU with a line saying to skip it while the PR Check is hidden; `CHANGELOG.md` has a new entry saying the PR Check and the Team view without Manager mode are hidden for now, and its section 0.1.5 does not change. When the PR Check is offered: `docs/` and `CHANGELOG.md` describe the PR Check, its two ways, the worktree in the editor's storage, the report and that it stays local; `docs/uat.md` has the manual steps: Solo, Collaborative, a pull request without `.trama/` with Solo mode off, Stop, an agent that ends without delivering, an outdated report, a pull request closed after its report, a leftover worktree after the window was closed while checking, `Check` disabled during a Run, the Team view without Manager mode.
