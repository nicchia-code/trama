# omp Chat

## omp-chat
- Impostazione `trama.ompChat`: booleana, default `true`, `scope: "application"`, prima chiave del sottogruppo `omp Chat` del gruppo `Advanced` di `SETTING_GROUPS` (`extension/src/host/settings-schema.ts`, `tech#setup-wizard`), con il titolo esplicito `omp Chat` in `EXPLICIT_TITLES`. omp Chat è in uso salvo quando `inspect("trama.ompChat").globalValue === false`, letto a ogni istruzione: un valore assente vale il default, acceso, e un valore del workspace non conta, così un repository clonato non la cambia. Con `trama.ompChatIntentTracing` è una delle due funzioni facoltative accese per default.
- Impostazione `trama.ompChatApproval`: stringa, `enum: ["ask", "yolo"]`, default `ask`, `scope: "application"`, nel sottogruppo `omp Chat` subito dopo `trama.ompChat`, con il titolo esplicito `omp Chat Approval` in `EXPLICIT_TITLES`. Si legge solo da `inspect("trama.ompChatApproval").globalValue`: `yolo` vale yolo, ogni altro valore, assenza compresa, vale `ask`.
- Impostazione `trama.ompChatIntentTracing`: booleana, default `true`, `scope: "application"`, nel sottogruppo `omp Chat` subito dopo `trama.ompChatApproval`, con il titolo esplicito `omp Chat Intent Tracing` in `EXPLICIT_TITLES`. È spenta solo quando `inspect("trama.ompChatIntentTracing").globalValue === false`; un valore assente o non booleano vale acceso, e un valore del workspace non conta. Si legge all'apertura di ogni conversazione, mai per una ripresa.
- La scheda Settings non riceve più `trama.agent`; `SettingField` (`extension/src/webview/settings/field.tsx`) perde le proprietà `disabled` e `note`, che servivano solo a `trama.ompChat` con un altro agente, e `planSettingChange` non rifiuta più nessuna scrittura di `trama.ompChat`.
- Vista: un contenitore con titolo `omp Chat` e l'icona del logo, con una sola vista `webview` (`WebviewViewProvider` con `retainContextWhenHidden: true`):
  - `viewsContainers.secondarySidebar` con id `trama-omp-chat-sidebar` e la vista `trama.ompChatSidebar`, `when: trama.ompChatVisible`. Richiede l'engine `^1.106.0` (`specs#frameworks`), la prima versione di VS Code che accetta il contenitore, senza API proposte. Il contenitore `viewsContainers.panel` (`trama-omp-chat`, vista `trama.ompChat`), che esisteva solo per Cursor, sparisce dal manifest.
- La chiave di contesto `trama.ompChatVisible` la imposta l'host con `setContext`: `true` quando omp Chat è in uso o quando la finestra ha General o almeno una conversazione aperta (`rules#omp-chat`), altrimenti `false`. È l'unica chiave di contesto di Trama; la vista `trama.home` della barra di attività non ne usa nessuna (`tech#menu-laterale`).
- Il README, il CHANGELOG e `docs/uat.md` dicono che la vista sta nella barra laterale secondaria di VS Code e che omp Chat è accesa per default, con l'approvazione permissiva.
- Per mostrare la vista l'host esegue `trama.ompChatSidebar.focus` con `preserveFocus: true` per i lavori e senza per Ask more (`ui#omp-chat`). General non la esegue mai. Non esegue altri comandi che aprono, chiudono o spostano barre laterali, pannelli o viste.
- La webview è un secondo punto d'ingresso dello stesso build React del pannello (`dist/omp-chat.js` accanto a `dist/webview.js`, `scripts/build-extension.ts`), con lo stesso HTML e la stessa CSP di `webviewHtml` (`extension/src/host/html.ts`), lo stesso tema (`startTheme`) e lo stesso renderer Markdown.
- Messaggi host → webview: `conversations { items: { id, name, state: "running" | "idle" | "waiting-form" | "waiting-permission", model?: string, general?: true, placeholder?: string }[], selected?: string }`, con General, quando c'è, sempre per prima e con `general: true` (`tech#omp-chat-general`), e `placeholder` solo per una conversazione di Ask more ancora vuota (`tech#developer.ASK_MORE`); `sendMode { mode: "steer" | "queue" }` all'avvio della vista e a ogni cambio; e, per conversazione, `conversationUpdate { id, update }`, dove `update` è la `SessionNotification` di ACP così com'è, `messageStatus { id, messageId, status: "queued" | "delivered" | "failed", reason?: string }` per i messaggi mandati mentre l'agente lavora, più `formRequest { id, requestId, schema }` per i moduli e `permissionRequest { id, requestId, toolCall, options }` per le richieste di permesso. Webview → host: `selectConversation`, `sendMessage { id, text, messageId }`, `setSendMode { mode }`, `stopAgent { id }`, `closeConversation { id }`, `setModel { id, model }`, `formAnswer { id, requestId, answer }`, `permissionAnswer { id, requestId, optionId }`, più quelli di General (`tech#omp-chat-general`). `messageId` è un'identità che il webview genera per ogni messaggio, per legargli il suo stato. I dialoghi modali li apre l'host. Ogni messaggio in arrivo dal webview è validato con zod e ignorato se non valido.
- La scelta `Steer | Queue` (`ui#omp-chat-conversation`) è dell'host: la tiene in `ExtensionContext.globalState` sotto `trama.ompChatSendMode` (`data#omp-chat`), con `steer` quando manca o non è valida, la manda alla vista con `sendMode` e la cambia a ogni `setSendMode`, rimandando `sendMode` alla vista. Non è un'impostazione di `contributes.configuration` e non compare nella scheda Settings.
- Loghi delle chiamate (`ui#omp-chat-conversation`): la scelta del logo è una funzione pura del webview (`extension/src/webview/omp-chat/`), provata con `bun:test`, che dal titolo della chiamata e dal primo percorso di `locations` di ACP dà il logo e il titolo da mostrare: il prefisso `[py] `/`[js] ` all'inizio del titolo, il prefisso `$ ` dei comandi, l'estensione del percorso (senza distinguere maiuscole) secondo la mappa di `ui#omp-chat-conversation`. I loghi vengono da `simple-icons` (`specs#frameworks`), importati uno per uno (`siPython`, `siTypescript`, …) così che il bundle porti solo quelli usati, e disegnati come `<svg viewBox="0 0 24 24">` con il loro `path` e `fill="currentColor"`, con le stesse classi di misura delle icone per tipo di `TOOL_ICONS` (oggi `size-3.5`), con `role="img"` e `aria-label` il nome di `ui#omp-chat-conversation`. Un tipo che `simple-icons` non ha (per esempio per un marchio ritirato) resta senza logo nella mappa e tiene l'icona per tipo. `extension/THIRD-PARTY-NOTICES.md` riporta la licenza CC0 di `simple-icons` e che i loghi sono marchi dei loro proprietari.
