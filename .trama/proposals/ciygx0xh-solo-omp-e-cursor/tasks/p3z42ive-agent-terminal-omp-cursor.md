# Solo chat Cursor e omp

Quando il Task è fatto, `trama.agent` ammette solo `cursor`, il predefinito (la chat di Cursor, solo in Cursor), e `omp` (omp nel terminale integrato, in ogni editor, VS Code compreso). Ogni altro valore, assente, i vecchi `chat` e `claude` o qualunque testo, vale `cursor` senza avvisi e senza riscrivere l'impostazione.

- `extension/src/host/agent.ts`: `configuredAgent` restituisce `"cursor" | "omp"` (`omp` solo se il valore utente è esattamente `omp`, altrimenti `cursor`); tutti i confronti con `"chat"` in `launchAgent`, `agentName` e altrove diventano `"cursor"`. `agentName` per l'agente del terminale dà sempre `omp`.
- Consegna in chat: `openChat` consegna solo alla chat di Cursor (`openCursorChat`) quando `isCursor()`. Va tolto il ramo Copilot (`workbench.action.chat.newChat`, `workbench.action.chat.open` con `mode: "agent"` e `modelSelector`) e va eliminata `copilotModelSelector`, insieme all'avviso del modello Copilot non trovato. In `launchAgent` sparisce la scelta `isCursor() ? "cursor" : "copilot"`: con `cursor` la chat è sempre quella di Cursor. Gli annunci dei lavori avviati da Trama in chat restano quelli di Cursor.
- Fuori da Cursor con `cursor`: `launchAgent` non prova nessuna chat e nessun comando di chat, non annuncia nulla, non crea un job e non avvia il lavoro (nessun `announceSend`, nessuna voce in corso, niente `inSendTurn` con lavoro partito). Mette subito il prompt negli appunti (lo stesso testo che il terminale riceverebbe, senza le righe solo di Cursor) e mostra il messaggio informativo `Trama: Cursor's chat is only available in Cursor. The prompt is on the clipboard; choose omp in Trama's Settings to run the agent in a terminal.` con il pulsante `Open Settings`; scelto il pulsante, si chiama l'apertura del pannello di Trama sulla scheda Settings fornita dal pannello (la parte del pannello non è di questo Task). Questo avviso compare al posto di quello degli appunti di `toClipboard` in `extension/src/host/cursor.ts`, mai insieme: o si scrive gli appunti senza passare da `toClipboard`, o `toClipboard` riceve il messaggio da mostrare. L'esito per il chiamante è quello di una consegna non inviata (come `not-sent`/appunti oggi), così l'autopilota non vede un esito anomalo.
- Terminale: `extension/src/host/terminal-agent.ts`: `TerminalAgent` sparisce o diventa solo `"omp"`; `agentTemplate` costruisce solo `omp --hook <modulo> [opzioni modello/sotto-agenti/advisor] {prompt}`. Vanno rimossi il ramo `case "claude"` (opzioni `--settings` con gli hook `hook idle` e `hook claude-question-tool`, `--model`, `--agents`), `claudeAgents` e il parametro `tramaPath`. In `agent.ts` `terminalRun` non usa più `bundledTrama()` per Claude (`tramaPath`) e passa solo l'hook di omp. In `extension/src/host/quote.ts` va eliminata `hookProgram`, usata solo da Claude Code, con il suo commento.
- `extension/package.json`: `trama.agent` ha `enum` `["cursor", "omp"]`, `default` `cursor` e descrizioni in inglese: `cursor` = Cursor's chat, only in Cursor; the default; `omp` = omp in the editor's integrated terminal, in any editor. La descrizione di `trama.terminalLocation` dice che vale solo per `omp`. Le descrizioni dei ruoli dei modelli non nominano più Claude Code né Copilot se toccate qui insieme alla descrizione dell'agente.
- Su Windows la citazione delle tre shell resta com'è (commenti che citano `--settings` e `--agents` diventano generici: «un argomento JSON»).
- Affidabilità: l'hook di omp non blocca mai l'agente tranne quando rifiuta il suo tool di domande; ogni chiamata a `trama hook` ha timeout 3 secondi, gli errori sono ignorati, il rifiuto non contatta l'editor. Nessun testo, commento o test parla più dell'hook di Claude Code.

Test:
- `test/host-terminal-agent.test.ts`: tolti i casi Claude Code (righe `claude ...`, `--settings` con `claude-question-tool`, `--agents` con il modello di scansione); il test delle impostazioni si aspetta `enum` `["cursor", "omp"]` e default `cursor`; i casi omp restano.
- `test/host-agent-terminals.test.ts`: tolto il blocco `Claude Code run hooks`; aggiunti casi per `configuredAgent` (assente, `chat`, `claude`, testo qualsiasi valgono `cursor`; `omp` vale `omp`) e per il lancio con `cursor` fuori da Cursor: nessun comando di chat eseguito, prompt negli appunti, messaggio informativo con `Open Settings` che apre il pannello su Settings, nessun annuncio e nessun lavoro in corso. Rimossi i test della consegna alla chat di Copilot e di `copilotModelSelector`.
- `test/host-quote.test.ts`: tolto il test di `hookProgram` (hook di Claude Code su Git Bash) e gli esempi `claude ...` di `agentCommandLine` diventano esempi con `omp`; i test reali delle tre shell mantengono un JSON compatto con spazi solo nelle stringhe, senza nominarlo come quello di `--settings`.
