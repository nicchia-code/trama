# Requirements: Tecnologia e vincoli, Tecnologia della chat dell'editor

Generated by Trama from `.trama/requirements/tech/editor-chat.md`. Do not edit this file: change the Requirements through a Trama Proposal (or ask the developer).

These are the developer's Requirements for how the System is built. Follow them when you write code. The Model (`.trama/model/`) says what the System does; when a Requirement and the Model disagree, stop and tell the developer.
A section titled with a Model reference (such as `order/Paid`) applies to that element and to everything inside it.

## editor-chat

- Cursor. Le voci di Trama stanno in `~/.cursor/hooks.json` (`version: 1`), per gli hook `beforeSubmitPrompt`, `stop` e `sessionEnd`. Ognuna è il comando `"<percorso assoluto del programma trama incluso nell'estensione>" cursor-hook`, e questo comando le identifica come voci di Trama. Le altre voci del file non si toccano; un file mancante si crea; un file che non è JSON valido non si riscrive e il developer lo viene a sapere. Gli hook di Cursor non ereditano il `PATH` dell'estensione, per questo il percorso è assoluto: è riscritto da Update skills perché cambia a ogni aggiornamento. Gli hook sono a livello utente e non del progetto, così non entrano nel repository e non toccano i colleghi.
- `trama cursor-hook` legge da standard input il JSON che Cursor passa all'hook (`hook_event_name`, `conversation_id`, `workspace_roots`, e `prompt` per `beforeSubmitPrompt`, `status` per `stop` con `completed`, `aborted` o `error`, `reason` per `sessionEnd`). Trova l'editor del progetto con le stesse registrazioni locali di `trama ask`, usando la prima cartella di `workspace_roots` che contiene `.trama/model/system.md`, gli manda l'evento e finisce subito. Non blocca mai Cursor: per `beforeSubmitPrompt` risponde `{"continue": true}` e per gli altri `{}`, esce con 0 anche senza editor, senza progetto Trama o con un errore, e non scrive altro su standard output.
- Copilot (VS Code). L'estensione, all'attivazione in un editor che non è Cursor e a Update skills, scrive il file `copilot-hooks.json` nella cartella `ExtensionContext.globalStorageUri` e lo registra nelle impostazioni utente in `chat.hookFilesLocations` (`{ "<percorso assoluto del file>": true }`, aggiunto con `ConfigurationTarget.Global` senza toccare le altre voci; se la scrittura dell'impostazione fallisce il developer lo viene a sapere). Il file è `{"hooks": {"UserPromptSubmit": [{"type": "command", "command": "\"<percorso assoluto del programma trama>\" copilot-hook"}], "Stop": [{"type": "command", "command": "\"<percorso assoluto del programma trama>\" copilot-hook"}]}}`, riscritto a ogni aggiornamento perché il percorso cambia. È un file utente, mai nel progetto.
- Su Windows la forma del comando degli hook è quella che la shell degli hook di ciascun editor accetta. Copilot: accanto a `command` il file ha anche la variante `windows` del comando, nella forma provata (per PowerShell `& "<percorso assoluto di trama.exe>" copilot-hook`). Cursor non documenta la shell dei suoi hook su Windows: `hooks.json` contiene, al posto di `command`, la stessa forma PowerShell `& "<percorso assoluto di trama.exe>" cursor-hook`, scelta dal developer e non ancora provata su Cursor; se Cursor non la accetta, gli hook non arrivano e il Run non registra gli eventi della chat, e la forma si corregge qui. Il riconoscimento delle voci di Trama accetta sia la forma di oggi sia quella di Windows, così Update skills sostituisce le voci vecchie invece di aggiungerne altre.
- `trama copilot-hook` legge da standard input il JSON che la chat di VS Code passa all'hook (`hook_event_name`, `session_id`, `cwd`, e `prompt` per `UserPromptSubmit`). Trova l'editor del progetto con le stesse registrazioni locali di `trama ask`, usando `cwd` se contiene `.trama/model/system.md`, gli manda l'evento e finisce subito. Non blocca mai la chat: risponde `{}`, esce con 0 anche senza editor, senza progetto Trama o con un errore, e non scrive altro su standard output.
- L'host dell'estensione traduce gli eventi così. Un prompt (`beforeSubmitPrompt` di Cursor, `UserPromptSubmit` di Copilot) che comincia con «Use the trama-» o «/trama-» segna la conversazione (`conversation_id` o `session_id`) come di Trama; per una conversazione di Trama ogni prompt è `PROMPT_SUBMITTED`. In Cursor `stop` con `completed` è `AGENT_STOPPED`, con `aborted` o `error` è `AGENT_INTERRUPTED`; `sessionEnd` con `window_close` o `user_close` è `CONVERSATION_CLOSED` e la conversazione non è più di Trama; con gli altri motivi non produce nulla, perché lo `stop` ha già riferito. In Copilot `Stop` è sempre `AGENT_STOPPED`: la chat di VS Code non distingue un turno interrotto e non riferisce la chiusura della conversazione. Gli eventi di conversazioni che non sono di Trama si ignorano. L'elenco delle conversazioni di Trama sta solo nella memoria dell'host: si perde al riavvio dell'editor, e le conversazioni già aperte non sono più seguite finché non ricevono un nuovo prompt di Trama.
- I comandi che registrano un'azione dell'agente (spostare un Task in In progress, annunciare, `trama ask`) trattano `CURSOR_AGENT=1` come `TRAMA_AGENT=1`: Cursor imposta la variabile nella shell del suo agente (verificato in `cursor-agent-exec`, 3.22.12 e 3.23.12) e non nei terminali del developer. Nessuna delle due variabili impedisce più i comandi che eseguono una decisione del developer. La chat di Copilot non imposta nessuna variabile: i comandi del suo agente non si distinguono da quelli del developer, quindi un Task spostato in In progress dalla chat di Copilot non è preso, mentre un annuncio fatto senza `TRAMA_TERMINAL` né `CURSOR_AGENT=1` porta `chat: editor` (vedi `announcement` in `data`).
- `AGENT_STOPPED`, `AGENT_INTERRUPTED` e `CONVERSATION_CLOSED` agiscono sui Task presi e sugli annunci con `chat` del progetto della conversazione.
