# Requirements: Interfaccia, Handoffs and issues

Use when building or changing the Decisions and Issues tabs of the Team view, the issue preview, the GitHub Project picker and the GitHub states of the Team view.

## proposal/Open

- Decisions tab, header row: on the left the heading `Waiting for your decision`; on the right, in secondary text, `Approving publishes the issues on GitHub`, then the button `Replan` (`outline`, lucide `CalendarSync`, tooltip `Plan sprints and people again for all open handoffs`, or the reason of `rules#developer.REPLAN_HANDOFFS` when disabled), then the primary button `New handoff` (lucide `Plus`), which opens a handoff request (`ui#design-request`). The tab's label in the tab bar carries a round primary `Badge` with the number of handoffs waiting, only when it is not zero.
- `Replan` opens a confirmation `Dialog` titled `Replan open handoffs?` with the text `The agent plans sprint, assignee, reviewer and estimate again for the issues of <n> open handoffs, keeping your changes. Each handoff it changes goes back to Draft until the agent hands it over again.` (`1 open handoff`), followed, when some open handoffs are stale, by `<m> stale handoffs only count as load and do not change.` (`1 stale handoff only counts…`), and the buttons `Cancel` (`outline`) and `Replan` (primary, lucide `CalendarSync`). Esc and `Cancel` close it without launching anything. While the Replan runs the button shows lucide `LoaderCircle` turning (still with `motion-reduce`) and is disabled with `Replan is already running`. The empty Decisions does not show `Replan`.
- One card per open handoff, in creation order, never a Draft: on the first line the short number (`P4`) in secondary text, the title in medium weight and the label as a chip with a coloured dot (`epic: <label>`, colour from the tag colour function of `tech#panel`); on the second line, in secondary text, `Creates <n> issues · changes <m> Machines · proposed <time ago>` (`1 issue`, `1 Machine`; `changes nothing in the Model` when it changes no file; `proposed 12 min ago`, `proposed 1 h ago`, `proposed yesterday`, then the date). On the right `Approve` (primary, `Check`) and `Reject` (`outline`, `X`) as a split button whose arrow (`ChevronDown`) opens `Rework with feedback…` (lucide `MessageSquare`, with the description `The agent revises this handoff from your notes`) and `Reject` (`X`). A blocked handoff shows its reasons under the second line and `Approve` disabled with the first reason as tooltip, as on the Board; while the agent that handed it over is still finishing, `Approve` and `Reject` are disabled with `The agent is still finishing`. Without a linked GitHub Project, `Approve` is disabled with `Link a GitHub Project first`.
- Clicking a card, or Enter on its focused title, opens the issue preview of its first issue. A card with warnings (`rules#proposal/Draft`) shows, under the second line, lucide `TriangleAlert` and `<n> warnings` in the warning colour.
- Empty Decisions: centred, a round muted icon box with lucide `Inbox`, the heading `No handoff waits for a decision`, the text `When the agent turns a request into issues for your team, its proposal appears here for you to approve.` in secondary text, and the buttons `New handoff` (primary, `Plus`) and `View published issues` (`outline`), which opens the Issues tab.
- Issue preview, a page of the Decisions tab: a top bar with `Decisions` (`ghost`, lucide `ArrowLeft`), the short number and title of the handoff, then at the right `<i> of <n>` between two icon-only buttons `ChevronLeft` (`Previous issue · Alt+↑`) and `ChevronRight` (`Next issue · Alt+↓`), and the same `Approve` and `Reject` split button as the card. Alt+↑ and Alt+↓ move between the issues of the handoff anywhere in the preview; Esc goes back to the cards.
- Under the bar: a line with a dashed status pill `Not published` and `New issue in <owner>/<repo>` in secondary text; the issue title as the page heading; the labels as chips (the epic first); then, when the issue has warnings, one warning box per warning (`rules#proposal/Draft`), with lucide `TriangleAlert` and the warning in bold followed by the hint: `Estimated <n> d: more than 3 days per issue.` `Split it so each part fits in a sprint.` with the button `Split` (`outline`, lucide `Split`), or `Not covered: <ref>.` `No issue of this handoff is about it.`
- Body and fields side by side (body about two thirds, fields one third), one above the other narrower than 720 px. The body sits in a bordered box whose header says, with lucide `Bot`, `Trama agent` in bold and `drafted from handoff <P4> · preview of the GitHub issue body`; inside, the body exactly as it will be published (`rules#issue`), rendered with the panel's Markdown (`ui#panel`), `mermaid` diagrams included. The folded `Trama references` block is a disclosure with lucide `ChevronRight` and, at its right, `<n> items`; opened, it lists the references as the panel's chips, which open the focus.
- Fields column, one field after the other, each with its label above and a line in secondary text below: `Assignee` and `Reviewer` (a `Select` of the members of the team, each with initials avatar and `@handle` in monospace, plus `Nobody`), `Estimate (days)` (number input, step 0.5, followed by `d`), `Sprint` (a `Select` of the iterations of the linked Project, each `<title> · <dates>` with lucide `Calendar`, plus `No sprint`), then every other field of the Project in the Project's order, as a `Select` for a single-select field, a text or number input otherwise (iteration fields other than the sprint, and fields Trama cannot set, are not shown). The line below says `Proposed by the agent` (lucide `Bot`) or `Changed by you · Undo` (lucide `Pencil`, `Undo` as a link-style button that restores the agent's value). A value is saved when chosen or when the input loses focus; an invalid one keeps the input with the destructive border and `rules#developer.CHANGE_ISSUE_FIELD`'s message under it.
- An estimate field over 3 shows the warning border of the theme.

## issue

- Issues tab, header: in secondary text `<n> issues in <m> epics · ordered by dependencies`.
- A bordered table with the columns `Issue`, `Title`, an unnamed column with the assignee's initials avatar (a dashed circle with `–` for nobody), `Sprint`, `Status` and `Actions`. Rows are grouped by epic: each group starts with a row on the muted background with a chevron (lucide `ChevronDown`, `ChevronRight` when folded, accessible name `Fold <epic>`), the epic chip and `<n> issues · <days> d` in secondary text; groups follow the order of their oldest handoff.
- `Issue` is `#<number>` in monospace, or `–` before publishing. `Title` is the title in medium weight; under it the problems of the row: in the destructive colour, lucide `CircleAlert` and `Publish failed: <reason>`, or, in secondary text, `Fields not set on GitHub: <field>, <field>`. `Sprint` is the sprint title or `No sprint`.
- `Status` is a pill with an icon: `Publishing` (lucide `LoaderCircle`, turning, removed with `motion-reduce`), `Not published` (dashed border, lucide `CircleDashed`) and, once published, the states of `ui#issue/Published`.
- `Actions`, aligned right: `Publish again` (`outline`, lucide `Upload`) for an issue not published, disabled with the reason as tooltip while a publication of the same handoff is running, without a linked Project or with Team not available; `Open on GitHub` (`ghost`, lucide `ExternalLink`) for a published issue, which opens its address in the system browser.
- Narrower than 640 px each row becomes a block: number and status on the first line, title and its problems below, sprint and assignee on the last line, actions at the right of the first line.
- No issues: `No issues yet. Approve a handoff to publish its issues.` in secondary text.

## github-project

- Top of the Team view, on the title's line: the GitHub Project as an `outline` button with lucide `SquareKanban`, `<owner>/<repo>` in monospace, ` · `, the Project's title and lucide `ChevronsUpDown`; it opens a `Popover` titled `Change GitHub Project` with a search field (placeholder `Search Projects of <owner>…`), the Projects of the owner (checked one with lucide `Check`), each `<owner> · <title>` or `<owner>/<repo> · <title>` for a Project linked to the repository, and at the bottom `Link another Project…` (lucide `Plus`), which opens the full picker below, and `Unlink` (destructive text). At the right of the line: `Updated <time ago>` (`Updated just now`, `Updated 2 min ago`) in secondary text and `Refresh` (`outline`, lucide `RefreshCw`, turning while reading), disabled while a read runs.
- No Project linked: instead of the tab's content, the heading `Link a GitHub Project`, the line `Team publishes issues to a Project and reads its sprints from the Iteration field.` and a bordered list of the Projects of the owner as radio rows, each with the title and, under it, the fields Trama will use (`Iteration · Estimate · Priority fields`); a Project without an iteration field is disabled with `No Iteration field — add one on GitHub to use it`. Under the list `Link Project` (primary) and `Create a Project on GitHub` (`ghost`, lucide `ExternalLink`), which opens the owner's Projects page in the browser. People and the tab bar stay usable.
- GitHub states, as a box at the top of the content, in the warning colour unless said otherwise:
  - `GitHub CLI is not installed` (lucide `Terminal`): `Team uses gh to read the Project and publish issues. Install it, then select Refresh.`, with `Install gh` (`outline`, lucide `ExternalLink`, opens `https://cli.github.com`) and `Refresh`.
  - `You're not logged in to GitHub` (lucide `TriangleAlert`): `Log in so Team can read <owner>/<repo> · <Project> and publish approved issues. This runs gh auth login in a terminal.`, with `Log in to GitHub` (primary, lucide `LogIn`).
  - `GitHub CLI can't read Projects`: `Give gh access to Projects. This runs gh auth refresh in a terminal.`, with `Give access` (primary, lucide `KeyRound`).
  - `Couldn't read the GitHub Project`, in the destructive colour (lucide `CircleAlert`): the reason in monospace and `Showing data from <time ago>.` when there is data from before, with `Retry` (`outline`, lucide `RotateCw`) and `Show details`, which opens the output channel of Trama on the full error.
- While the first read of the view runs, the content shows skeleton rows (muted blocks, no animation with `motion-reduce`) and the line `Loading from GitHub…` in secondary text.
- These texts are in English and do not follow `trama.language`; the issue preview's body is the agent's text, in the language it was written in.
